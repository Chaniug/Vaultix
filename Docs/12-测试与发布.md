## 2. 单元测试（重点）

### 2.1 `core:crypto` —— 必测

| 用例 | 断言 |
|---|---|
| PBKDF2 派生 | 与 Bitwarden 官方测试向量一致（邮箱作盐、600 000 次） |
| Argon2id 派生 | 与 RFC 9106 / Argon2 参考实现向量一致（m=64MiB, t=3, p=4） |
| HKDF-Expand | 与 RFC 5869 向量一致 |
| EncString 编解码 | 官方示例字符串可解；MAC 错误必须抛错；**篡改密文/IV/MAC 任一字节必须失败** |
| EncString 类型 | type 2 读+写；type 7 只读不崩；type 0 / 4 / 6 必须拒绝并报"过旧版本" |
| RSA-OAEP | 组织密钥解包（仅 SHA-256 变体）成功/失败路径 |
| KDBX 密钥链 | 与 KeePass 官方样例库一致（4.0 / 4.1 × Argon2id × AES-256-CBC / ChaCha20） |
| KDBX 版本闸门 | 3.1 文件、AES-KDF、Argon2d、Salsa20/RC4 保护流、Twofish 均被拒绝，且不得输出部分明文 |
| KDBX 完整性 | header SHA-256 / header HMAC / 块 HMAC 逐字节损坏均被检出，且错误阶段正确 |
| 保护流 | ChaCha20 加解往返；字段可随机访问 |
| SecureBytes | `zero()` 后全 0；不可序列化 |

### 2.2 `data:kdbx`

- 官方样例库（含历史、附件、自定义图标、回收站）正确打开。
- 往返：随机生成 → 保存 → 重开 → 全字段一致（含 Protected 字段密文不同但明文相同）。
- 交叉：KeePassXC / KeePass2Android 能打开 Vaultix 写出的文件（人工验证 + 自动化脚本可选）。
- 大库性能：10 000 条目打开 < 5 s（基准测试，CI 可选）。

### 2.3 `domain` / ViewModel

- 每个 UseCase：正常 + 边界 + 错误路径。
- ViewModel：用 `Turbine` 断言状态序列与一次性事件；`reduce` 纯函数直接测试。
- 冲突合并策略：本地/远端各种组合的字段级合并结果。

## 3. 集成测试

| 场景 | 方案 |
|---|---|
| Bitwarden 协议 | 使用 `MockWebServer` 回放真实 `prelogin`/`token`/`sync` 响应；或对接本地 Vaultwarden（Docker）跑 nightly |
| 2FA 流程 | Mock 返回 `TwoFactorProviders` → 断言进入 2FA 状态 → 补 token 成功 |
| Token 续期 | 401 → refresh → 重试成功；refresh 失败 → 回落锁屏 |
| Room 迁移 | `MigrationTestHelper` 覆盖每个版本迁移 |
| Keystore | Robolectric 无法真实覆盖 → 用 instrumentation 测试（真机/模拟器）验证生物识别凭据存取与失效 |

## 6. 发布流程

```
1. 冻结功能 → 创建 release/x.y.z 分支
2. 全量回归（自动 + 手动清单）
3. 更新 CHANGELOG、版本号（versionCode +1 / versionName）
4. 打 tag → CI 产出签名 APK/AAB + SHA-256
5. GitHub Release（附变更说明与 checksum）
6. Google Play 分阶段发布（20% → 50% → 100%）
7. F-Droid 由元数据仓库自动拉取构建
8. 观察崩溃与反馈 48 h，必要时回滚
```

## 7. 版本号策略

语义化版本 `MAJOR.MINOR.PATCH`：

- MAJOR：不兼容的数据格式/重大架构变更
- MINOR：新功能（如 Passkey 支持、新库类型）
- PATCH：修复与小幅优化

数据库 schema 版本与导出文件格式版本独立编号，写入导出文件头部，保证向后兼容读取。
