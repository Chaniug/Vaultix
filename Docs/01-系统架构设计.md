# 01 · 系统架构设计

## 1. 架构总览

采用**清晰分层 + 单向依赖**的结构：UI → ViewModel → Domain → Data，Data 内部再通过"源适配器"抹平 Bitwarden 与 KDBX 的差异。

```
┌───────────────────────────────────────────────────────────────┐
│                        UI Layer (Compose)                      │
│  主题/组件(core:ui)  页面(feature:*)  导航(app)                │
│  只依赖 ViewModel 暴露的 UiState 与 Intent，不直接碰数据源      │
└───────────────────────────┬───────────────────────────────────┘
                            │ UiState / Intent (单向)
┌───────────────────────────▼───────────────────────────────────┐
│                    ViewModel Layer (MVI)                       │
│  每个页面一个 ViewModel：状态归约、一次性事件、生命周期感知      │
└───────────────────────────┬───────────────────────────────────┘
                            │ suspend / Flow
┌───────────────────────────▼───────────────────────────────────┐
│                      Domain Layer (纯 Kotlin)                  │
│  VaultRepository  ItemRepository  AuthInteractor  SyncInteractor│
│  GeneratorUseCase  TotpUseCase  ImportExportUseCase            │
│  ✅ 无 Android 依赖（便于 JVM 单测）  ✅ 只认识统一领域模型      │
└───────────────────────────┬───────────────────────────────────┘
                            │ VaultSource 接口（策略模式）
┌───────────────────────────▼───────────────────────────────────┐
│                       Data Layer                               │
│  ┌──────────────────────┐   ┌───────────────────────────────┐ │
│  │ BitwardenVaultSource │   │ KdbxVaultSource               │ │
│  │  Retrofit + OkHttp   │   │  KDBX 解析器 + 文件快照       │ │
│  │  EncString 加解密    │   │  XML/保护流/附件              │ │
│  └──────────┬───────────┘   └──────────────┬────────────────┘ │
│             └───────────┬──────────────────┘                  │
│                 Room（本地密文缓存 / 索引 / 元数据）            │
│                 DataStore（设置）  Keystore（密钥材料）         │
└────────────────────────────────────────────────────────────────┘
```

### 关键抽象：`VaultSource`

```kotlin
interface VaultSource {
    val descriptor: VaultDescriptor          // 库标识：id / 类型 / 显示名 / 图标
    suspend fun unlock(credential: UnlockCredential): Result<Unit>
    suspend fun lock()
    fun observeItems(): Flow<List<VaultItem>>         // 已解密的领域对象流
    suspend fun save(item: VaultItem): Result<VaultItem>
    suspend fun delete(ids: Set<String>): Result<Unit>
    suspend fun sync(force: Boolean): Result<SyncReport>   // KDBX 实现为落盘/重读
}
```

Domain 层只面向 `VaultSource`，因此"新增一种库格式"（如 KeePass 1.x `.kdb`）只需实现该接口。

> **状态图例**：✅ 已建 · 🚧 骨架 / 占位 · 📋 规划（M数字为 `Docs/13` 的里程碑编号）
>
> **关于 `feature/*`（2026-09 决策）**：文档原规划 11 个 feature 模块，但当前代码量尚小，
> **决定暂不拆分**——先在 `app` 内按包名组织（如 `ui/vault/`、`ui/settings/`），
> 待某个 feature 真正膨胀到需要独立编译时再抽成模块。
> 理由：模块越多 `settings.gradle.kts` 越臃肿、编译配置负担越重，而代码量小时收益为负。
> 本条与"保持分层（core / data / domain / app）"不冲突——**分层照做，feature 粒度从缓**。

### 模块依赖规则（由 Gradle + 一致性测试强制）

| 规则 | 说明 |
|---|---|
| R1 | `feature:*` **不得**互相依赖；跨页面导航通过 `app` 模块的路由契约 |
| R2 | `domain` **不得**依赖 `data`、`core:database`、`core:platform` 或任何 Android SDK（除 `javax.crypto` 等 JVM 标准库） |
| R3 | `core:crypto` 只依赖 `core:common` 与加密库，**不得**依赖 Room / 网络 |
| R4 | `data:*` 可依赖 `core:*` 与 `domain` 接口，**不得**依赖 `feature:*` |
| R5 | `core:ui` 只依赖 Compose + Material3，**不得**依赖 `domain` / `data` |

> 建议引入模块依赖 lint（如 `dependency-analysis` 插件或自写 Gradle 检查任务）在 CI 中校验 R1–R5。

## 3. 主要技术选型

| 领域 | 选型 | 理由 |
|---|---|---|
| UI | Jetpack Compose + Material 3（含 Expressive 组件） | 声明式、M3 官方实现、大屏适配成本低 |
| 导航 | Navigation Compose + 类型安全路由（Kotlin 序列化） | 深链接支持自动填充跳转 |
| 异步 | Coroutines + Flow | 与 Room / 生命周期天然契合 |
| DI | Hilt | Android 官方，减少样板 |
| 本地库 | Room（SQLite） | 存密文快照 + 搜索索引（FTS5） |
| 网络 | **Retrofit + OkHttp** | 均支持证书固定；Bitwarden 的 `connect/token` 是表单编码，Retrofit 用 `@FormUrlEncoded` + `@FieldMap` 直接承接，无需手写请求体 |
| 序列化 | Kotlinx Serialization | 与 Ktor/类型安全路由统一 |
| 加密 | Android Keystore（AES-GCM）、Bouncy Castle 或 libsodium 绑定（Argon2） | Argon2 在 JVM 上无标准实现，需引入成熟绑定 |
| KDBX | 自研或引入 Apache-2.0 兼容库（如 `kotpass`，需自行核对最新版本与 License） | KeePassDX 为 GPL-3.0，若本项目选 Apache-2.0 则**不可**直接复用其代码 |
| 图片 | Coil | 网站图标缓存，可完全关闭 |
| 后台 | WorkManager | 定期同步、KDBX 自动保存 |
| 测试 | JUnit5 + Turbine + Truth + Compose UI Test + Hilt Testing | 见 [12](./12-测试与发布.md) |

## 4. 关键时序

### 4.1 解锁 Bitwarden 库（首次）

```
用户 → 输入邮箱/主密码 + 服务端地址
  → /identity/accounts/prelogin          获取 KdfType / KdfIterations（或 Argon2 参数）
  → 派生 MasterKey（PBKDF2/Argon2id，邮箱作盐）
  → HKDF-Expand 得到 StretchedMasterKey（enc / mac）
  → /connect/token (grant_type=password, scope=api offline_access)
  → 返回 access_token / refresh_token / Key（受保护的对称密钥 EncString）
  → 用 StretchedMasterKey 解密 Key → 得到 64 字节对称密钥（enc 32B + mac 32B）
  → /api/sync 拉取全量密文 → 本地解密 → 写入 Room
  → 用 Keystore 密钥加密"生物识别解锁凭据"并落盘（可选）
```

### 4.2 打开 KDBX 文件

```
用户 → SAF 选择 .kdbx（+ 可选 KeyFile）
  → 读外层 header（签名、版本、CipherID、MasterSeed、IV、KDF 参数）
  → 组装 CompositeKey（SHA256(密码) ‖ KeyFile 摘要 ‖ 挑战响应）
  → KDF 变换（仅 Argon2id）
  → 校验 header SHA-256 与 header HMAC-SHA256 → 口令错误在此暴露
  → 分块读取并逐块校验 HMAC → 解密 → 解压（GZip）
  → 解析内层 header（InnerRandomStreamID/Key、二进制附件）
  → 解析 XML → 建立 Group 树与 Entry 列表
  → Protected 字段保持密文，仅在 UI 请求时按需解密
```

### 4.3 自动填充（Autofill）

```
第三方 App 请求填充
  → AutofillService.onFillRequest
  → 提取包名 / 域名（需 Digital Asset Links 校验，见 06）
  → 库中是否解锁？否 → 展示"解锁并填充"演示视图（远程 Presentations）
  → 是 → URI 精确/包含匹配 → 返回 Dataset（用户名/密码/TOTP）
  → 用户点选 → 解密该条目 → 填充 → 记录使用时间与匹配 URI
```

## 5. 状态机：库生命周期

```
         ┌──────────┐  lock()   ┌──────────┐
         │ UNLOCKED │──────────▶│  LOCKED  │
         └────┬─────┘           └────┬─────┘
              │ timeout/切后台        │ unlock(主密码 / 生物识别)
              └──────────────────────┘
   ┌──────────┐  首次添加   ┌──────────┐  网络错误   ┌──────────┐
   │ NOT_ADDED│───────────▶│  LOCKED  │◀──────────▶│ SYNC_ERR │
   └──────────┘            └──────────┘            └──────────┘
        Bitwarden 额外：TOKEN_EXPIRED（静默 refresh_token 续期，失败回落 LOCKED）
        KDBX 额外：DIRTY（有未落盘修改）→ SAVING → UNLOCKED
```

- 锁定时：**必须**从内存清除对称密钥、解密后的条目缓存与 Protected 流密钥（`core:crypto` 的 `SecureBytes.zero()`）。
- 进程级锁定开关由 `VaultSessionManager` 统一持有，任一库锁定只影响该库。

## 6. 性能预算

| 指标 | 目标 |
|---|---|
| 冷启动到主列表（已锁定） | < 800 ms（中端机） |
| 解锁（PBKDF2 600k / Argon2id 64MB） | 首次 1–3 s，需展示进度与取消 |
| 1 万条目列表滚动 | 稳定 60 fps（分页 + `LazyColumn` + 稳定 key） |
| 搜索响应 | < 100 ms（Room FTS5 索引，密文不入库） |
| KDBX 保存（1 万条目） | < 4 s，后台线程 + 原子写（临时文件 + rename） |
| 自动填充响应 | < 300 ms（匹配走内存索引，密钥已在内存） |

## 7. 可观测性

- **日志**：`Timber`，release 构建中**必须**无日志；`core:crypto` 内禁止打印任何密钥、密文、口令（lint 规则：方法名含 `key/password/secret` 的参数不得出现在日志拼接里）。
- **崩溃**：可选接入，上传前需用户明示同意，且剥离 `VaultItem` 内容。
- **指标**：仅本地计数（同步耗时、KDF 耗时、填充成功率），默认不上传。
