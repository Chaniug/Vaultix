## 🔄 Bitwarden 同步修复：改动终于能真正推上服务器

这一版集中修复了自建 Vaultwarden 上「改了条目、本地看着正常、服务器却始终不变」的问题。
从真机日志到服务端协议逐层取证，修掉了串在同一条路径上的五个独立缺陷（#294–#298）。

- **请求体补上 `encryptedFor`**（关键）：Vaultwarden 1.37+ 把它设为必填，缺就会在服务端
  拒收更新（HTTP 422），导致你改的网址 / 密码 / 备注永远上不了云。现在按官方客户端口径，
  用当前账号的 user id 填充；旧版服务端会忽略该字段，向后兼容。
- **HTTP 422 不再被当成"确定性失败"丢弃**：以前 422 会让改动静默丢单、界面还显示"同步成功"；
  现在保留在队列里重试，并把脱敏后的响应体写进日志，便于定位。
- **推送成功后推进本地 revision 基线**：以前服务端接受了改动，本地时间却停在编辑前，
  导致第二次编辑必被服务端以"副本过期"拒绝。现在推送成功后立即对齐服务端时间。
- **编辑已有条目时用条目自己的密钥加密**：带独立密钥的条目，以前字段被账号密钥加密，
  官方客户端 / 网页端解不开、只显示旧值；现在按 Bitwarden 官方口径写回。
- **同步日志可自证**：队列为空、待推送几条、推送成功 / 失败各几条，现在都有明确日志，
  不再出现"点同步显示成功但什么都没发生"却无从排查的情况。

## ⚠️ 升级须知

- 如果你此前有**卡在队列里反复失败的旧改动**，升级后首次同步会尝试推送它们。其中基于过期
  基线（例如几个月前的改动）会被服务端以"副本过期"拒绝并清理——这是正确行为：服务端的
  当前版本才是有效数据，本地旧改动不会覆盖它。真正需要保留的改动请重新编辑一次再同步。
- 本次不改动 KDBX 库、不改动数据格式、不需要重新登录或重新注册通行密钥。KDBX 与 Bitwarden
  在代码上是两套独立的存储与同步链路，本次修复完全位于 Bitwarden 一侧。
