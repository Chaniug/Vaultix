## 🌐 WebDAV 连接与坚果云

- **#288 坚果云「登录不上去」**：此前服务端返回 403 时界面仍只说「账号或密码不正确」，把人锁死在反复重输一个本来正确的密码上。现在 **401 / 403 分开处理**：403 明确提示认证其实已通过、是服务端拒绝，并列出四条可排除原因（应用密码、微信二次验证、访问频率、目录权限）。
- 密码框下新增提示：坚果云、群晖等需在网页端生成**应用密码**，登录密码无效；坚果云还需先在安全选项里关闭微信二次验证。
- 连接自检改为 `PROPFIND Depth: 0`，与后续列目录用**同一个协议方法**（此前用 `HEAD` 探目录，探通了也不代表能列目录，404 会假报成功）；服务端不支持时才降级 `HEAD`。
- WebDAV 改用**独立的 OkHttp client**，不再复用带 Bitwarden 鉴权拦截器的全局实例，避免 `Basic` 凭据被覆盖、token 被发到 NAS。

## 🛡 网盘账号不再闪退

- **#290 点「注销」网盘账号闪退**：真机日志显示 `Resources$NotFoundException: String resource ID #0x0`。根因是提示文案的 11 个资源 id 被写成 `const val ... = R.string.*`，而 Android 编译期 R 类里这些 id 是 `0x0` 占位、运行时才是真值 —— `const val` 把 0 内联进了每个调用点，界面弹提示时在 Compose 重组期直接崩。现改为运行时读取真值，并给所有变量式文案解析加了无效 id 守卫。
- **订正 #289**：连接 WebDAV 成功后闪退、重进却发现账号已添加，与 #290 同源（成功提示同样下发了那个 0）。此前的协程异常边界修复仍然必要，但不是那次闪退的根因，已在接力文档中如实订正。
- 两个网盘页面的动作统一收口到异常边界：未捕获异常转为可见错误态并留日志，凭据写入 / 自检 / 清单读取下沉到 IO 线程，不再压在主线程。
