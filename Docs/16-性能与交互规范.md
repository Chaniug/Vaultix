# 16 · 性能与交互规范

> 目标：在 Android 17（API 37）设备上**流畅、省电、易维护**，并为后续升级留出空间。
> 本章是 `Docs/11`（工程规范）的补充，属于**强制性工程约束**。

## 1. 为什么单独立这一章

参考项目（Bastion）暴露了两类已发生的问题：

| 问题 | 实例 |
|---|---|
| **超大文件** | `KeePassKdbxService.kt` 6708 行、`BitwardenSyncService.kt` 2594 行、`EnhancedAutofillStructureParserV2.kt` 2136 行 |
| **由此引发的性能后果** | 方法体过大时 ART JIT **不予编译**，退化为解释执行——表现为"点一下卡一下"、列表滚动掉帧 |

Vaultix 当前代码量很小（core:crypto 约 1500 行），**此刻立规矩成本最低**；等长成大文件再拆，代价高一个数量级。

## 2. 代码规模上限（硬性）

| 维度 | 建议值 | 硬上限 | 检测 |
|---|---|---|---|
| 单文件行数 | ≤ 600 | **1200** | Detekt / 脚本统计 |
| 单函数行数 | ≤ 60 | **150** | Detekt `LongMethod` |
| 单类函数数 | ≤ 20 | **40** | Detekt `TooManyFunctions` |
| 函数参数个数 | ≤ 5 | **8** | Detekt `LongParameterList` |

**为什么必须限制函数体大小**（两条独立原因）：

1. **DEX 硬限制**：单个方法的字节码上限为 65536 个 16-bit code units，超出**直接编译失败**。
2. **JIT 软限制**：ART 的 JIT 对过大方法**不做编译优化**，即使它是热点也会走解释执行。
   这是"函数超大导致卡顿"的真正原因——代码逻辑没错，只是没被编译。

> 因此：**拆函数不是风格问题，是性能问题。**

## 3. 性能与省电

### 3.1 列表与滚动

- 列表一律使用 `LazyColumn` / `LazyRow`，**禁止**用 `Column` 包裹全量数据。
- `LazyColumn` 的 item 必须设稳定 `key`（条目 id），否则重排时重组范围放大。
- 列表项 Composable 参数保持稳定：数据类用 `@Immutable` / `@Stable` 标注，避免不必要的重组。

### 3.2 解密与 IO

- **列表页只持有密文句柄**（`LoginSecret.Encrypted`），**绝不**批量解密（见 `Docs/02` 2.1）。
- 解密结果绑定生命周期：离开页面即 `zero()`。
- KDF（PBKDF2 / Argon2）为 CPU 密集型，**必须**在注入的 `CoroutineDispatcher` 上执行，禁止在主线程调用。

### 3.3 后台与省电

- 周期同步用 `WorkManager` + 约束（充电/非计量网络可选），**禁止**常驻轮询。
- 自动锁定与剪贴板清除用系统回调，不用 `Handler` 循环。
- 日志：release 构建零日志；OkHttp 日志拦截器仅 debug（见 `Docs/09`）。

## 4. 交互与视觉

以下源自 Bastion 已验证的体验，为 Vaultix 的**目标基线**：

| 特性 | 说明 |
|---|---|
| **顶部大标题随滚动缩放** | 列表顶部为大号标题，随下滑平滑缩小为普通标题栏（CollapsingToolbar 语义），带阻尼回弹 |
| **功能折叠进标题** | 搜索、筛选、排序等入口常驻标题区域，随滚动折叠/展开，不占额外固定高度 |
| **沉浸式 + 半透明** | 状态栏/导航栏透明，内容延伸至系统栏之下；配合动态取色，避免"一条黑边"的割裂感 |
| **切换顺滑** | 页面切换与共享元素过渡统一，避免突然的尺寸跳变 |

实现要求：以上效果**必须由滚动位置驱动**（`NestedScrollConnection` / `ScrollState`），
不能靠定时器或一次性动画，否则与手势脱节。

## 5. 可维护性与升级

- **分层不可破**：`core` 不反向依赖 `data` / `domain`（`Docs/01` R1–R5）。
- **公开 API 收敛**：模块间只暴露接口与领域模型，内部实现标 `internal`。
- **依赖版本集中**：全部走 `libs.versions.toml`，**禁止**在 `build.gradle.kts` 里硬编码版本号。
- **升级记录**：每次大版本升级在 `docs/adr/` 写决策记录，并说明"为什么锁这个版本 / 升了会炸在哪"
  （Bastion 的 `libs.versions.toml` 注释是很好的范本）。

## 6. 门禁

- Detekt（或 ktlint）纳入 CI，启用 `LongMethod` / `TooManyFunctions` / `LongParameterList` / `LargeClass`。
- 覆盖率：`core:crypto` 已有 Kover 门禁（≥80%）；其余模块随落地逐步启用（见 `Docs/11`）。
- 新增大文件（>600 行）需在 PR 中说明拆分计划。
