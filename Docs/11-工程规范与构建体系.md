# 11 · 工程规范与构建体系

## 1. Gradle 结构

```
settings.gradle.kts          模块声明 + 版本目录（libs.versions.toml）
build.gradle.kts             根：插件声明、公共配置
gradle/libs.versions.toml    集中版本管理（Compose BOM、Kotlin、AGP、Hilt、Room…）
```

采用 **Version Catalog + Convention Plugins**（`build-logic/` 下的 `compose-library`、`android-library`、`android-app`、`hilt` 等约定插件），避免每个模块重复配置。

| 构建配置 | 值 |
|---|---|
| `minSdk` | 26 |
| `targetSdk` | 36 |
| `compileSdk` | 36 |
| Kotlin | 2.x（K2 编译器） |
| Java | 17 |
| Compose | 启用 `composeCompiler` 插件，开启强跳过模式（Strong Skipping）与报告 |
| 构建特性 | `buildConfig = true`、`compose = true`；KSP（Room/Hilt） |

### 变体

```kotlin
flavorDimensions += "distribution"
productFlavors {
    create("full")    { dimension = "distribution" }                 // 含网络（Bitwarden）
    create("offline") { dimension = "distribution"                   // 仅 KDBX，manifest 通过 placeholder 移除 INTERNET
        manifestPlaceholders["internetPermission"] = "" }
}
buildTypes {
    release { isMinifyEnabled = true; isShrinkResources = true
              proguardFiles("proguard-rules.pro") }   // 注意：保留序列化模型与 JNI 符号
}
```

## 3. 开源协议选择

| 选项 | 影响 |
|---|---|
| **GPL-3.0-or-later**（推荐，与 Bitwarden 客户端、KeePassDX 一致） | 强 copyleft：任何分发版本必须同样开源；可复用 GPL 生态代码 |
| Apache-2.0 | 更宽松，但**不可**复用 GPL 的 KeePass/KDBX 实现，需自研或只用 Apache/MIT 库 |

**必须做的合规动作**：
1. 根目录 `LICENSE`、`NOTICE`；
2. 设置页提供"开源许可"页（`com.google.android.gms:oss-licenses` 或自建 `aboutlibraries`）；
3. 如使用 EFF 词表、Argon2 实现等第三方资源，注明来源与许可；
4. 商标：不声称与 Bitwarden Inc. 或 KeePass 官方有关联；图标与品牌需原创（不复用 Bitwarden 官方 logo）。

## 4. 代码规范

| 项 | 规范 |
|---|---|
| 语言 | 全 Kotlin；禁止 Java 新文件（JNI/C 仅限性能关键且说明原因） |
| 命名 | 屏幕：`XxxScreen`（UI）、`XxxViewModel`、`XxxState/Intent/Effect`；数据：`XxxRepository`（接口在 domain，实现 `XxxRepositoryImpl` 在 data） |
| 包结构 | `io.vaultix.<module>.<layer>`，layer ∈ {ui, domain, data, di} |
| 状态 | 见 [10](./10-状态管理与数据流.md) |
| 协程 | 禁止 `GlobalScope`；所有作用域来自 DI（`ApplicationScope`/`viewModelScope`/`CoroutineScope(Dispatchers.IO)`） |
| 异常 | 加密/网络层抛具体异常 → Repository 统一映射为 `Result<T>` 或 sealed error；禁止吞异常 |
| 注释 | 关键密码学步骤必须写清"为什么"（引用规范/格式定义），而非"做了什么" |
| 资源 | 字符串全放 `strings.xml`（便于翻译）；禁止硬编码文案 |
| 可组合项 | 公共组件必须提供 `@Preview`（含深/浅两种）；使用 `PreviewParameterProvider` |
| 无障碍 | 每个可点击元素提供语义；`contentDescription` 不为 `null` 除非纯装饰 |

## 5. Git 与协作

- 分支：`main`（受保护，需 CI 通过）+ `develop` + `feature/*`；发布打 `vX.Y.Z` tag。
- 提交信息：Conventional Commits（`feat(kdbx): 支持 Argon2id 写入`）。
- PR 要求：描述 + 影响面 + 测试方式 + 截图（UI 变更）；至少 1 名维护者审核；涉及 `core:crypto` 必须 2 人审核。
- 变更日志：`CHANGELOG.md` 自动生成。

## 6. CI

| 任务 | 内容 |
|---|---|
| `build` | `assembleFullDebug assembleOfflineDebug assembleRelease` |
| `lint` | Android Lint + detekt + 自定义敏感日志规则 |
| `test` | 单元 + JVM 测试；Compose UI 测试（托管设备/Gradle Managed Devices） |
| `coverage` | `core:crypto`、`data:kdbx`、`domain` 要求行覆盖 ≥ 80%（**随模块落地逐步生效**：当前仅 `core:crypto` 已达标 91.4%；`data:kdbx` 属 M2、`domain` 仍为占位，尚无代码可覆盖） |
| `dependency` | 依赖校验和、License 检查、体积增量报告（APK 大小对比） |
| `release` | 签名构建 + 生成 checksum + 发布到 GitHub Releases |

## 7. 发布渠道

| 渠道 | 说明 |
|---|---|
| GitHub Releases | APK + AAB + SHA-256 + 构建说明（可复现构建） |
| F-Droid | 提供 `offline` flavor；无任何非自由依赖；元数据在独立仓库 |
| Google Play | `full` flavor；需填写数据安全表单（声明"不收集/不共享"） |
| Obtainium / IzzyOnDroid | 自动识别 GitHub Release |

## 8. 目录约定（模块内）

```
feature/vault/src/main/java/io/vaultix/vault/
├── VaultHomeScreen.kt        UI（stateless composable + 路由入口）
├── VaultHomeViewModel.kt
├── VaultHomeContract.kt      State/Intent/Effect
├── components/               该模块私有组件
└── di/                       Hilt 模块（如需）
```

`core:ui` 放置跨模块复用组件（`VaultixItemRow`、`PasswordStrengthBar`、`TotpChip`、`SecureTextField`），并配套 `Preview` 与"组件目录"调试页（`debug` 构建可见）。
