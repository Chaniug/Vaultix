# 02 · 统一领域模型

## 1. 设计思路

Bitwarden 的 `Cipher` 与 KDBX 的 `Entry` 差异很大：前者是扁平的单层文件夹 + 字段数组，后者是嵌套群组树 + K/V 字符串字段 + 附件。领域层用一套**超集模型**承载，差异通过"能力声明"表达，避免 UI 层写 `if (isBitwarden)`。

> **规范模型（canonical）· 2026-09 决策**
> Vaultix 定位为 **Bitwarden 优先的客户端**（对标 Keyguard 路线，见 `Docs/13` M1）。故本超集模型**以 Bitwarden `Cipher` 为规范模型**：`ItemType`（LOGIN/SECURE_NOTE/CARD/IDENTITY 对应 `cipher.type` 1/2/3/4）、`uris[].match`、`card` / `identity` 结构、`reprompt` 等一律采用 Bitwarden 语义。
> **KDBX 侧为降级映射端**：其无法原生承载的字段通过约定前缀（如 `Vaultix.*`）落库。两侧转换的保真度**并不对称**，分级与强制要求见 [3.4 往返保真度](#34-往返保真度-round-trip-fidelity)。

```
领域模型 = 公共超集 + 能力集合（Capabilities）
UI 根据能力决定：能否显示"群组树"、能否编辑附件、能否改 KDF
```

## 2. 核心数据类

```kotlin
// core:model —— 纯 Kotlin，无 Android 依赖
data class VaultDescriptor(
    val id: String,                  // 本地稳定 UUID
    val kind: VaultKind,             // BITWARDEN | KDBX
    val displayName: String,
    val origin: String,              // 服务端 URL 或 文件 URI
    val iconTint: Int? = null,
    val createdAt: Instant,
)

enum class VaultKind { BITWARDEN, KDBX }

data class VaultCapabilities(
    val nestedGroups: Boolean,       // KDBX: true  Bitwarden: false
    val attachments: Boolean,        // KDBX: 读写  Bitwarden: V1 只读（需 Premium）
    val configurableKdf: Boolean,    // KDBX: true  Bitwarden: 服务端决定
    val passwordHistory: Boolean,
    val offlineOnly: Boolean,
    val maxFolderDepth: Int,         // Bitwarden = 1，KDBX = Int.MAX_VALUE
)

data class VaultItem(
    val id: String,                  // Bitwarden: GUID；KDBX: UUID 字符串
    val vaultId: String,
    val type: ItemType,              // LOGIN | SECURE_NOTE | CARD | IDENTITY
    val name: String,                // 明文（Bitwarden 需解密；KDBX 默认明文）
    val subtitle: String?,           // 用户名 / 卡号后四位
    val icon: ItemIcon,              // 内置图标 key 或网站 favicon URL
    val favorite: Boolean,
    val groupPath: List<String>,     // KDBX 层级路径；Bitwarden = [folderName] 或空
    val folderId: String?,           // Bitwarden 专用
    val uris: List<ItemUri>,         // 含匹配规则（精确/主机/以…开头/正则/永不）
    val secret: LoginSecret?,        // 见下：按需解密
    val notes: String?,
    val fields: List<CustomField>,
    val totp: TotpSecret?,
    val card: CardInfo?,
    val identity: IdentityInfo?,
    val attachments: List<AttachmentRef>,
    val passwordHistory: List<PasswordHistoryEntry>,
    val reprompt: Boolean,           // 查看/填充前需再次验证主密码
    val deletedAt: Instant?,         // 回收站
    val revision: ItemRevision,      // 版本号/修订时间，用于冲突检测
)
```

### 2.1 敏感值的惰性解密

```kotlin
sealed interface LoginSecret {
    data class Plain(val value: SecureString) : LoginSecret      // 已解密，需及时清零
    data class Encrypted(val handle: CipherHandle) : LoginSecret // 仍为密文句柄
}
```

- 列表页只持有 `Encrypted`，**绝不**批量解密。
- 详情页、复制、填充时才解密为 `Plain`，并绑定"离开页面即清零"。
- KDBX 的 Protected 字段与 Bitwarden 的 EncString 都映射为 `CipherHandle`（内部记录源、密文、解密所需密钥引用）。

## 3. 字段映射表

### 3.1 登录类条目

| 领域字段 | Bitwarden `Cipher` | KDBX `Entry` |
|---|---|---|
| `id` | `id` (GUID) | `UUID` (Base64) |
| `name` | `name`（EncString type 2） | `Name`（默认明文，可受保护） |
| `secret` | `login.password`（EncString） | `Password`（Protected） |
| `subtitle`/用户名 | `login.username`（EncString） | `UserName`（Protected 可选） |
| `uris` | `login.uris[].uri` + `match` | `URL` + `OverrideURL` |
| `totp` | `login.totp`（EncString，otpauth 或裸 secret） | `otp` 字符串字段（`otpauth://...`） |
| `notes` | `notes`（EncString） | `Notes`（Protected 可选） |
| `fields` | `fields[]`（Text/Hidden/Boolean/Linked） | `StringFields[]`（K/V，`Protected=True` 时为隐藏） |
| `favorite` | `favorite` | 约定：存于 `Tags` 或自定义字段 `Vaultix.Favorite` |
| `groupPath` | `folderId` → 单一文件夹名 | Group 树路径 |
| `attachments` | `attachments[]`（需 Premium） | `Binary` 内嵌 / 内层 header 二进制 |
| `passwordHistory` | `passwordHistory[]` | `History[]` 中同名条目历史 |
| `reprompt` | `reprompt`（0/1） | 约定：自定义字段 `Vaultix.Reprompt` |
| `revision` | `revisionDate`（服务端时间） | `LastModificationTime` + 内存脏标记 |

### 3.2 其他类型

| 领域类型 | Bitwarden | KDBX |
|---|---|---|
| `SECURE_NOTE` | `type = 2`（`notes`） | `Notes` 为主体的普通 Entry |
| `CARD` | `type = 3`（`card.*`） | 约定：字段前缀 `Card.`（卡号/持卡人/有效期/CVV） |
| `IDENTITY` | `type = 4`（`identity.*`） | 约定：字段前缀 `Identity.` |

> **互操作约定**：KDBX 无原生类型概念，Vaultix 使用 `Vaultix.Type` 自定义字段标记；未标记的 Entry 默认按 `LOGIN` 呈现。导出到 KDBX 时若用户选择"兼容模式"，则不写入 `Vaultix.*` 字段（会丢失收藏/重验证等信息，需在 UI 提示）。

### 3.3 TOTP 统一

```kotlin
data class TotpSecret(
    val algorithm: TotpAlgorithm,   // SHA1 / SHA256 / SHA512
    val digits: Int,                // 6 / 8
    val periodSeconds: Int,         // 30
    val secret: CipherHandle,       // Base32 密钥，密文保存
    val issuer: String?,
    val accountName: String?,
) {
    companion object { fun parse(otpauthUri: String): TotpSecret }
}
```

- 解析 `otpauth://totp/{label}?secret=...&issuer=...&algorithm=...&digits=...&period=...`
- 兼容 KeePass 生态的 `keyUri` 与 Steam 特殊格式（可选）。
- HOTP 增加 `counter` 字段，使用后递增并持久化。

### 3.4 往返保真度（Round-trip Fidelity）

**定义**：同一条目经 `Bitwarden Cipher ⇄ VaultItem ⇄ KDBX Entry` 转换后，信息能否完整还原。

由于规范模型取 Bitwarden，两个方向的保真度**并不对称**，必须分级声明：

| 等级 | 含义 | 典型字段 |
|---|---|---|
| **无损** | 双向往返完全一致 | `id`、`name`、`secret`、`subtitle`、`notes`、`totp`（otpauth URI） |
| **约定承载** | 落入 `Vaultix.*` 自定义字段；**Vaultix 可读回**，其他 KeePass 客户端不识别 | `favorite`、`reprompt`、`Card.*`、`Identity.*`、`Vaultix.Type` |
| **有损** | 结构差异导致语义降级，无法还原 | `uris[].match`（KDBX 仅有 URL 字符串）、`passwordHistory` 精度、条目独立密钥 `cipher.key`；反向为 KDBX 的 Group 树 / 图标 / 颜色 |

**强制要求（MUST）**

1. **往返测试**：每次映射变更必须附测试
   `Bitwarden Cipher → VaultItem → KDBX Entry → VaultItem → Bitwarden Cipher`，
   断言"无损级"字段逐一相等。这是模型对齐之外，真正保证不出错的手段。
2. **有损字段显式声明**：所有"有损"字段必须在 `VaultCapabilities` 中登记；UI 在**跨库移动 / 导出 / 切换兼容模式**前提示会丢失哪些信息，**禁止静默丢弃**。
3. **兼容模式降级**：若用户选择兼容模式（不写 `Vaultix.*`），"约定承载"字段一并降级为"有损"，须同样提示。
4. **反向必然有损**：KDBX → Bitwarden 方向上，KDBX 的群组树、图标、颜色、附件内嵌方式在 Bitwarden 中无对应结构，须按第 2 条列明。

> **对齐基准**：与 Bitwarden **官方客户端的实际行为**一致（含其非标准实现），而非仅依据公开文档。
> 已知非标点（源自 bw2keepass 实战）：KDF salt 为 UTF-8 编码字符串、`encKeyValidation` 明文为 UUID 而非 `"Bitwarden"` 字符串。
> 另注意 Vaultwarden 与官方存在差异（如忽略 `sinceRevisionDate`，增量同步会空转）。

## 4. 文件夹 / 群组模型

```kotlin
data class VaultGroup(
    val id: String,
    val vaultId: String,
    val name: String,
    val parentId: String?,     // Bitwarden 恒为 null
    val isRoot: Boolean,
)
```

| 操作 | Bitwarden | KDBX |
|---|---|---|
| 新建群组 | `POST /api/folders` | 新建 `Group` 节点 |
| 移动条目 | 改 `folderId` | 改 Entry 所属 Group + 更新 `Times` |
| 嵌套显示 | 忽略（降级为单层） | 完整树形，支持折叠 |
| 回收站 | 服务端 `deletedDate` | 读取 `Meta/RecycleBinUuid` 指向的 Group |

## 5. 同步与冲突的领域表达

```kotlin
data class ItemRevision(
    val sourceRev: String?,        // Bitwarden: revisionDate；KDBX: 文件 mtime + 内存序号
    val localRev: Long,            // 本地单调递增序号
    val dirty: Boolean,            // 有未推送修改
)

sealed interface ConflictResolution {
    data object UseRemote : ConflictResolution
    data object UseLocal : ConflictResolution
    data class Merge(val winner: Map<String, FieldWinner>) : ConflictResolution
}
```

- Bitwarden：以 `revisionDate` 为准，本地 `dirty` 条目优先推送，服务端返回 4xx 时进入冲突流程。
- KDBX：**不做自动合并**（文件级写冲突风险高）。检测到外部修改（mtime/哈希变化）时，提供三条路径：① 覆盖外部 ② 重新加载并丢弃本地（提示会丢失）③ 另存为新文件。

## 6. 搜索索引模型

```kotlin
// Room FTS5 表：只存"安全可索引"的字段

data class ItemIndex(
    val itemId: String, val vaultId: String,
```

- **MUST NOT** 把密码、TOTP 密钥、笔记全文写入 FTS 索引（索引文件是明文 SQLite）。
- 笔记/自定义字段的搜索采用"内存内全量匹配"，可在设置中开启（说明性能与内存权衡）。
