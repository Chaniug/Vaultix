# 「不需要修」清单与判定方案（2026-11-11）

> **用户诉求**：「还有哪些是不需要修的，仔细看看，做出完善的方案」。
> **本文回答的不是「列哪些不用修」，而是「凭什么判定不修」** —— 清单本身会过期，
> 判据和复核机制才能让下一轮排查不再把同样的误报、同样的刻意冻结重新列成待办。
> **口径**：静态复核，基于 [整体排查主报告](project-audit-2026-11-11.md)、
> 三份证据附录、`.ai/decisions/*`、`Docs/progress/decisions.md`、版本目录注释与源码全文。
> **唯一真源**：[附录 D · 登记表](evidence/no-fix-entries-2026-11-11.md) 的 `NO_FIX_REGISTER` 表格；
> 本文只做摘要与指针，不复制条目。

## 1. 为什么必须建这份登记

上一轮排查把「159 条注释缺空格」「52 条硬编码密钥」「131 个超长方法」这类数字写进了报告，
并在正文里逐条解释「是误报」。但**解释写在报告里，下一轮扫描器还会原样再输出一遍** ——
于是同一批误报会被第三次、第四次当成待办。项目里已经有过两次同类教训：

- `.ai/decisions/快速解锁房子化-两级钥匙层级-定稿-part3.md` 设了
  「§11 被否 / 刻意不学（连同理由，**避免新会话重复提议**）」；
- `.ai/decisions/条目页-M3-视觉方案.md` 设了「附：不做的事（**明确排除**）」。

⇒ **项目早就有「不做登记」的惯例，只是散落在各篇决策里，排查时不会被自动读到。**
本方案把它收敛成：一份登记表 + 一套判定法 + 一条门禁，让「不修」变成可查询、可校验、可过期的状态。

## 2. 判定法：三问 + 一个前置问题

### 2.0 前置问题：这是「要修」还是「要建」？

Baseline Profile 缺失、Kover 未接 CI、Gradle 配置缓存未启用，是**能力缺失**，
不是被写坏的代码。混进「违规整改」清单会让优先级失真。
答「要建」⇒ 走主报告 §4/§5 施工单，登记为 C11 / C12，**建成后转 D 类「不要回退」**。

### 2.1 三问

| # | 问题 | 答「否」 | 答「是」 |
|---|---|---|---|
| **Q1** | 有没有**真实损害**：用户可见错误 / 崩溃 / 数据风险 / release 与 debug 的行为差异 / 安全边界被绕过？ | 进 **B / C**（误报或推迟） | 继续 Q2 |
| **Q2** | 仓库里有没有**明确的知情记录**：决策文档、代码注释、版本目录注释、`@Suppress`、`constraints`、`@file:Suppress`？ | **真违规**，进主报告整改清单 | 进 **A / D / E**，并写下 Q3 |
| **Q3** | 将来出现**什么情况**必须重新评估？写不出 ⇒ 判断不扎实，退回 Q1 | 不允许登记 | 写进「触发转修条件」列 |

> **Q2 的强制子步骤（本轮复核踩到）**：必须沿时间线确认该决策**没有被后续条目推翻**。
> 差点把「从 Bastion 只搬三类资产，不做文件级搬迁」登记为现行不修项，
> 但 `Docs/progress/decisions.md:47` 明确写着「**策略变更：分批整体搬入（推翻「不做文件级搬迁」）**」。
> 被推翻的旧决策只留在 `decisions.md` 当历史，**不进登记表**。

### 2.2 三条反纪律

1. **「不修」不是「永不修」**：每条都必须有触发条件；条件命中就转修，并从登记表移入主报告。
2. **「不修」不等于「不用看」**：D 类要防回退，A 类要防被 Dependabot 顺手升掉 —— 两者都要门禁。
3. **不要为了对齐数字去动代码**：为把 131 个方法压到 80 行而批量拆分，
   会重演 `.ai/conventions/8.6` 记过的「抽类对函数数减益比预期小 / 抽 composable 凭记忆写类型名炸 CI」。

## 5. 复核机制与自动化门禁

### 5.1 门禁：`check_no_fix_register.py`

把「登记」变成机器可检查的，而不只是一篇文章。脚本以**附录 D 表格为唯一真源**，做三件事：

| 检查 | 判据 | 红了说明 |
|---|---|---|
| ① 登记完整性 | ID 唯一、格式 `[A-E]\d{2}`、分型合法、7 列齐全、条数不低于基线 | 表格被误删或格式写坏 |
| ② **锚点有效性** | 逐条确认 `文件 → 片段` 仍存在 | **代码/配置被改了，登记可能失效** ⇒ 要么恢复锚点，要么把条目改成「已转修」并移出表 |
| ③ **防重复列入待办** | 扫 `Docs/progress/next-steps.md` 的 `- [ ]` 行，命中「禁止重新表述」列即失败 | 下一轮又把已判定不修的事列成待办 |

> ② 是**触发转修条件的自动化**：D 类锚点消失通常意味着配置被回退，A 类锚点消失通常意味着
> 有人动了冻结的版本键 —— 两种都必须有人看一眼，而不是静默放过。
> 各配一条自测（`selftest_no_fix_register.py`），沿用 `ci-docs.yml` 现有「每关配自测」的规矩。

### 5.2 CI 覆盖边界（诚实说明）

门禁挂在 `ci-docs.yml`（文档门禁，不挡 APK 出包）。`paths` 增补登记表锚点涉及的**高频配置文件**：
`gradle/**`、`gradle.properties`、`app/build.gradle.kts`、`app/src/main/AndroidManifest.xml`、
`app/proguard-rules.pro`、`config/detekt/**`。

少数锚点落在 `.kt` 上（D04/D05/D06/D07、E01–E03、B09），这类改动**不会触发文档 CI**，
由本地全量门禁与下一轮排查兜底 —— 这是刻意权衡：为覆盖它们而把 `app/src/main/**` 塞进
`ci-docs.yml` 的 paths，会让当初「改代码不触发文档门禁」的拆分设计失效。

### 5.3 复核节奏与纪律

| 时机 | 动作 |
|---|---|
| **任何整体排查 / 审计开工前** | 先读附录 D；产出的每条「待修项」先与 52 个 ID 比对，命中即引用登记而非重写理由 |
| 依赖升级专项（含 Dependabot PR） | 逐条过 A 类；A01 三项被单独改动必须拦下 |
| detekt / 阈值 / 扫描器调整后 | 重跑 B 类计数，只处理非误报残留 |
| 新增决策文档「不做 / 被否」段 | 同步在登记表加行并分配新 ID；编号不复用、不重排 |
| 季度复核 | 检查触发条件是否已命中；命中则移出登记表、写进主报告 |

> **一条纪律**：登记表与主报告的「待修清单」互斥。同一件事同时出现在两处 = 状态错了，
> 由门禁 ③ 与人工复核共同守住。

## 6. 本轮对主报告的订正

用户指出「**release 主要是 dev 合并进去的，所以只要 dev 没问题，release 自然没问题**」。
核对后确认**分支流程的描述是对的**，但由此推出的「release 自然没问题」不成立：

| 核对项 | 结论 |
|---|---|
| `main` → `assembleFullDebug`（`ci-debug.yml`） | ✅ 源码来自同一条主线 |
| `rele` 分支 / `v*` tag → `assembleFullRelease`（`release.yml`） | ✅ release 由主线合并，**源码一致** |
| `BuildConfig.DEBUG` 由什么决定 | **buildType**（编译期常量），**不是 Git 分支** |
| R8 裁掉什么 | 只裁 `if (BuildConfig.DEBUG) { ... }` 整块；**没有门面保护的裸 `Log.d/w` 运行时调用裁不掉** |
| `VaultixLog.install(enabled = BuildConfig.DEBUG)` | release 下门面在拼串前就返回；6 处直接 `Log` 绕过总开关 / 限频 / 异常兜底 / 日志红线 |

⇒ **订正**：

1. 日志门面收敛 **P0 → P1**：不崩溃、不丢数据，属日志红线与信息泄露风险；
   且 debug 包本来就打日志，会掩盖这个问题（更难发现，但更不紧急）。
2. **S2 仍是真违规，不进「不修」登记**：绕过统一门面就是绕过，与分支无关。
3. **施工顺序改为 S1 → S3（生产 `!!`，会 NPE 崩溃）→ S2 → S4**，主报告 §6 阶段 0 同步调整。
4. 增加判据：**「源码一致 ⇒ 产物行为一致」是错的**，debug / release 差异看 buildType 而非分支。
5. 顺手订正 `.ai/MEMORY.md` §4 技术栈口径：实际是
   `Gradle 9.8.2 / AGP 9.5.0 / Kotlin 2.4.21 / KSP 2.3.13`，
   旧写法 `9.5.1 / 9.3.2 / 2.4.10 / 2.3.11` 是主报告 §1.4 版本漂移的**第 5 处**（在 AI 必读文档里，危害更大）。

- 本轮**未改任何生产代码**；订正只涉及报告、登记表、AI 记忆、待办与文档门禁。
