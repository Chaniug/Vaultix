三个时刻：M3 只管第一拍

时刻时间M3 规范项目现状

思路主线：不是「把 ripple 加回来」，而是把 T1 与 T2 补上。 方案 2 是 M3 合规化的底线；方案 3 / 4 / 5 是放开形变与动效后可以探索的方向。 方案 4（相邻联动）最出彩，也最接近历史上「点一个、旁边跟着闪」的高危区 —— 差别在于那次是跨 tab 双色渐变并行 200ms，这次是几何位移、被按项主导。
加号为什么不该旋转（用户 19:32 指出后修正）： ① 「+」有四次对称，旋转 90° 的终态和初始态一模一样 —— 松手后看不到任何结果， 反倒是过渡过程中它变成了「×」，而 × 在界面语义里是「关闭 / 取消」，与「新建」正好相反； ② 两侧的 tab 是导航项（有选中态），中央「+」是动作按钮（没有选中态）， 两者的形状变化说的是不同的事，不该套同一套形变语言； ③ 因此加号的反馈只表达「我按下了」：压缩回弹 / 笔画伸缩 / 底色下压 / 外扩光晕， 四种都保持符号恒为「+」。判据：动作按钮的形状变化不能让用户以为它变成了另一个功能。

技术上行得通，且第一版零新增依赖： 官方三条路径是 AVD（animation-graphics）、ImageVector + Compose 动画 API、Lottie。 本项目目前只有静态 Icons.Default.*，没有 animation-graphics 也没有 Lottie。 ⇒ 「弹跳 / 旋转 / 描边转实心」直接用 Animatable + LaunchedEffect(点击) 即可， 零新依赖零新资源；「部件动」才需要为四个图标自绘分层矢量（或引入 AVD）。 三条硬提醒：动画状态必须放在 key(item) 稳定的组合槽里（否则重现「点一个、旁边跟着闪」）； 只做 one-shot 不循环（循环会持续重组，滚动时掉帧）；选中 pill 的颜色仍须瞬切。
