## 0. 结论先行

你这两句其实是同一个抱怨：**「库」是 Vaultix 里最重的对象，但切换它时界面几乎没有任何反馈，
列表页又把它画成了两张灰白卡片。**

M3 Expressive（Google I/O 2026 仍在推的方向）恰好给了两条对得上的答案：

| 线 | 官方给了什么 | 对本项目怎么用 |
|---|---|---|
| **Motion physics** | 弹簧取代 duration+easing；`container transform` / `shared axis` 仍是官方转场模式；短 200ms、中 400ms 的 token 体系 | 切库用 **container transform**（卡片张开成新库）或 **shared axis Z**（纵深换层），**200–250ms**，不加长动画 |
| **Shape library + vibrant color** | 新增约 35 种形状（squircle / scallop / burst…）与形状 morph；强调色按 tonal 角色分配；emphasized 排印 | 库卡给**形状徽章 + 类型色**，大标题用 emphasized 字阶；装饰形状作背景水印 |

⚠️ 一条诚实的边界：项目 `.ai/conventions/8.8` 定过「只借 M3E 理性的一半」——
形状变形、夸张动效、强调排印**当年全部不采纳**。这轮用户明确放开约束，
所以下面的候选里也放了大胆项，但**推荐仍落在克制那一档**。
8.4 #87「不要花哨页面转场」降级为历史证据，不再是红线。

## 1. 切库动效：五个候选

预览页 A 区可以逐个点播（都是 200–300ms，慢放按钮用于逐帧看）。

| # | 做法 | 观感 | 规范 | 判断 |
|---|---|---|---|---|
| **A 容器展开** | 被点的库卡圆角与尺寸连续扩成整屏，像「打开这个库」 | 最贴「确实切了库」 | ✅ M3 官方 container transform（卡 → 详情） | ★ **推荐** |
| **B 圆形幕布** | 从触点圆形揭开新库页面 | 最像你说的「电影幕布」 | ⚠️ Compose 无官方组件，需 `clip` 圆路径自绘 | ★★ 备选，实现成本中 |
| **C 纵深换层** | 旧库缩小淡出、新库从稍大处淡入，Z 轴感 | 克制、有「换了一层」的语义 | ✅ M3 shared axis Z | ★★ 最稳、最不容易翻车 |
| D 百叶幕布 | 数条纵带依次滑开 | 最戏剧化 | ❌ 无官方对应，且最容易显得花哨 | 探索 |
| E 齿轮 / 形状 morph | 徽章形状旋转变形再定格 | 最「有设计感」 | ✅ M3E 35 shapes 支持 morph | 探索；alpha API 风险高 |

**我的推荐：A 容器展开**，理由不是好看，是**它把「切库」这件事的因果画出来了**：
用户点的是那张卡，展开的也是那张卡 —— 而不是一个与点击无关的整屏淡入。
C 作为保守备选：它只改透明度与缩放，不动布局尺寸，最不容易撞历史那几次转场事故。

### ⚠️ 施工前必须带上的三条历史证据

1. `MainShellScreen` 的 Tab `AnimatedContent` 用 `SizeTransform(clip = false) { _, _ -> tween(0) }`
   把**尺寸补间关成瞬时**——因为返回时重进组合会重放转场，把详情页裁小 1–2 帧。
   ⇒ 切库动效**不要碰** `SizeTransform`，也不要复用那套 `AnimatedContent`。
2. `skipFirstTransition` 旗标挡的是「重新进入组合时重放 Tab 过渡」；
   切库是**另一个事件**，要独立状态，否则会与 NavHost 的返回转场叠成双影。
3. 8.4 part3 §2：容器底色按「要不要从栏下穿过」选，不按「两页一致」选。
   新库页若让内容从顶栏下滑过，底色必须 `surfaceContainerHighest`（实测亮度比 1.232），
   用 `Low` 会与栏同色、标题区糊成一片。

⇒ 结论：**动效做在「库列表 → 主界面」这条导航的 enter/exit 上，不碰主界面内部的 Tab 转场**。

## 1.1 联动型候选（22:55 用户追加需求）

用户要「有个性但不特别夸张，类似数据流、齿轮滚动」，并且明确
**「考虑到库列表的效果，最好有一些联动」** —— 这正戳中 A–D 的短板：
那四种都是**整屏换页**，库列表只是被动消失，没有任何一个列表元素参与。

### M3E 2026 给的编排依据（不是自创）

| 模式 | 官方口径 | 本项目约束 |
|---|---|---|
| **Sequential Reveal / Stagger** | 列表子项 20–50ms 间隔依次入场，**总 stagger ≤300ms** | 4 行条目占位用 40ms，总计 120ms |
| **Hero-First** | 焦点元素先动，支撑元素 100–150ms 后跟 | 选中库的徽章先亮，条目行后到 |
| **Coordinated Exit** | 退场**统一**，不 stagger（否则显得拖沓） | 其余两张库卡一起淡出 |
| **Shared motion / container transform** | 卡面、标题、图像在同一条时间线联动 | 徽章 / 卡片圆角 / 条目宽度共用一条曲线 |
| **Shape morph** | 35 种形状 token 之间插值，用于状态切换 | 圆角方 → 圆，只做一次、不循环 |
| 时长与数量 | 与点击相连的动作上限约 **300ms**；同屏同时动画 **≤3 个** | 全部 240–300ms，单舞台最多 3 组动画 |

⇒ 「有个性但不夸张」有客观判据：**不转满圈、不循环、不超过 300ms、不同时跑 4 组动画**。

### 四个新候选（预览页 A2 区可点播）

| # | 联动了哪些列表元素 | 观感 | 判断 |
|---|---|---|---|
| **E 数据流** ★ | 选中徽章、4 行条目占位、其余库卡、条目计数 | 徽章先亮 → 条目像一串数据流入列表 → 计数落定 | ★ **推荐**：最贴你说的「数据流」，且是标准的 Hero-First + stagger |
| **F 齿轮滚动** | 三张库卡的位置、徽章转角（只 45°）、条目行 | 列表像滚轮转一下，选中卡升到顶部定格 | ★★ 机械感最贴「齿轮」，但只转 45° 才不夸张 |
| **G 级联流入** | 库卡高亮、4 行条目、计数 | 官方 staggered entrance 的直译 | 最规范、最稳，也最不「有个性」 |
| **H 形状联动** | 徽章形状、卡片圆角、条目行宽度 | 三者同一条时间线连续变形 | 最有设计感；依赖 M3E shape API，落地成本最高 |

### 与库列表外观的配套（这才是「联动」的完整含义）

联动不该只发生在切换的 300ms 里，切换前后也要接得上：

- **切之前**：库列表用 ②「库身份卡」——每张卡已有徽章 + 条目数，动效才有东西可联动；
  用 ① 灰卡基线的话，E/F/G/H 全部落空。
- **切之中**：被点卡片的徽章/计数就是 Hero-First 的 hero，不需要额外造一个图形。
- **切之后**：新库页顶部保留同色的活跃库标识 1–2 秒再淡出，让「刚才那张卡」和
  「现在这个库」在视觉上连成一条线（对应 M3 的 shared element 语义）。

⇒ 我推荐 **E 数据流 + ② 库身份卡**，F 作为机械感备选。
H 的 shape morph 要引 M3E 的 shape API（8.8 §6① 只允许 alpha API 用在叶子组件），
留到 P4-c 单独评估。

⚠️ 实现提醒：这些是**编排**（choreography），不是新组件。Compose 侧用
`AnimatedVisibility` + `animation-delay`/`LaunchedEffect` 的 stagger 即可，
不要引入 Lottie 或 alpha 的 `SharedTransitionLayout`。

## 2. 库列表页：四个方向

截图里的问题是三重的：**大片空白、两张同色灰卡、只有一个孤零零的 + FAB**。
没有视觉锚点，也没有「这是哪个库」的身份感。

| # | 方向 | 做法 | 判断 |
|---|---|---|---|
| ① | 现状基线 | 标题 + 灰卡 + FAB | 基线 |
| **② 库身份卡** | 每卡左侧一个 48dp **形状徽章**：按库类型取 `primaryContainer` / `tertiaryContainer` / `secondaryContainer`，里面一枚类型图标（云端盾 / 本地文件 / 云盘）；右侧标题、账号、同步状态，卡片上沿一条极细的 tonal 色条 | ★ **推荐** |
| ③ 统计型 | ② 之上加「条目数」小环与「最近同步」时间轴，把空白区变成有用的信息 | 信息密度高，但要与库摘要加载时序同步 |
| ④ 全 M3E vibrant | emphasized 大标题 + 背景装饰形状（squircle / burst 水印）+ 不同形状卡角 + Extended FAB | 最「高级」，也最容易一屏两套规格 |

**我的推荐是 ② + 一点点 ③**：
- **颜色只来自 `colorScheme` 角色**，不硬编码品牌色（动态取色 + 8.8 §6② 都不破）；
- 徽章**形状**按库类型区分（M3E shape library 的克制用法）：
  Bitwarden → squircle，KDBX 本地 → 圆角方，云盘 → 圆形；
  用户扫一眼就能分清「哪个是云端、哪个是本地文件」；
- 空白区不塞插画，改为一张**「当前活跃库」摘要卡**（条目数 / 上次同步 / 锁定状态），
  既填了空白又是真信息 —— 比装饰图案更耐看；
- FAB 保留（8.4 反对长按隐藏手势），只在滚动时按 M3 惯例收缩，不做 FAB Menu（alpha API）。

⚠️ 8.4 的「一屏两套规格」纪律：徽章与卡片必须共用 `VaultixCorner` 三档，
不要为每个库类型各写一套圆角。装饰形状**不承载语义**，只作底纹，不能抢标题。
