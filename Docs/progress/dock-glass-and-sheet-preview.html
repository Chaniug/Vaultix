项目里有完整的液态玻璃实现：ui/glass/ 四个文件，源→消费分离、AGSL 边缘折射、 上沿高光 / rim 暗线 / 内描边、三档降级，2026-10-27 起经过四轮真机返工。 开关在 设置 → 主题模式 → 液态玻璃底栏，默认关闭（当时用户明确指定）。 所以第一件事不是新建，是先打开它看现状。

内容侧的前置条件也已经具备：AdaptiveMainScaffold 在窄屏用叠层 Box，内容一路铺到屏幕底，底栏浮在其上；各页只给列表末尾留 bottomInset。滚动过程中条目本来就会从胶囊后面穿过——只是滚到底时 胶囊后面是空白。这正是「淡淡看到下方条目」能成立的地方。

一条被拍过的定案，这次要重新拍： 8.4-UI·观感-part3.md §四处静默失效明确写着——API 30 及以下没有 RenderEffect，降级必须画全不透明实色，理由是「半透明底栏浮在滚动列表上， 条目会从图标之间透出来 ⇒ 读不清，那是不可用不是不好看」。 现在用户要的恰好是「透出来」，且明确说「淡淡的」。 ⇒ 要么在 API 31+ 单独调淡（推荐），要么连降级档一起重开（需真机验对比度）。 这不是审美分歧，是有实测记录支撑的可用性取舍，别顺手改。

「+」面板：M3 给了什么，没给什么

路径官方说法本项目的判断
ModalBottomSheet只规定容器与行为，不规定内容布局； Google 自家 Drive / Photos 的创建面板用磁贴网格✅ 网格、主卡、工具条都在规范内，零 alpha API
M3E FAB Menu2–6 个相关动作，弹簧展开， 触发按钮 morph 成关闭⚠️ 项目锁 alpha16，8.8 §6① 要求 alpha 只用于叶子组件； 且「+ 变 ×」正撞你上一轮否决的判据（动作按钮不能让人以为变成了别的功能）。 只借「从原位展开」的运动语义，不借组件
M3E ButtonGroup表达单选 / 分段，connected 组会做相邻形变❌ 动作集合不是选择态，语义不符
M3E FloatingToolbar横向悬浮动作条❌ 与底栏胶囊抢同一块空间
M3 state layer / 一个 Filled一屏只该有一个 Filled 主按钮✅ 网格里全部用 tonal / outlined，主卡独享主色

我自己的三条大胆建议

1 · 类型卡画「字段剪影」，不画抽象图标。登录画两行 + 锁、银行卡画磁条 + 四位点、 笔记画三行文本、身份画头像 + 两行、SSH 画等宽字符。用户扫一眼就知道要建的是哪种， 比读文字快；而且这是密码管理器独有的表达，别家抄不走。也是刚做的折纸 V 那套 「一个不单调的单一符号」思路的延续。

2 · 面板与底栏同一块材质。面板从「+」原位展开（container transform： 圆角 16dp → 28dp、位置从胶囊中央 → 全宽），顶部沿用同一道玻璃高光。 这样两个问题合成一个答案：底栏不是「一块贴上去的玻璃」，面板是它长出来的一块。

3 · 生成器不排第 7 项。它是动作不是条目类型，放进 2×3 网格会污染分类。 单独做成底部工具条或 chip，和「新建什么」拉开层级。
