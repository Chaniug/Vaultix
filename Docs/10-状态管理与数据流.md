# 10 · 状态管理与数据流

## 1. 总体模式：MVI（单向数据流）

```
       用户操作（Intent）
            │
            ▼
      ViewModel
    ┌───────────────┐
    │ reduce(state, │  ← 纯函数，可单测
    │       intent) │
    └───────┬───────┘
            │ 新 UiState（不可变 data class）
            ▼
      Compose UI（collectAsStateWithLifecycle）
            │
            │ 一次性事件（导航、Snackbar、复制）
            ▼
      Effect Channel（Channel<UiEffect>，缓冲 1，收集即消费）
```

| 规则 | 说明 |
|---|---|
| 单一可信源 | 每个页面一个 `UiState`，不含派生状态（派生用 `derivedStateOf` 或 `remember`） |
| 不可变 | `UiState` 全部 `val` + `ImmutableList`（`kotlinx.collections.immutable`）以优化重组 |
| 线程 | 状态更新只发生在 `viewModelScope`；IO 切 `Dispatchers.IO`，KDF/加解密切 `Dispatchers.Default` |
| 事件不重放 | 一次性事件用 `Channel`，**禁止**用 `StateFlow` 承载导航 |
| 生命周期感知 | UI 用 `repeatOnLifecycle(STARTED)` 收集 |

## 2. 典型 UiState

```kotlin
data class VaultHomeState(
```

## 3. 数据流分层

```
UI (Compose)
  │  intent
  ▼
ViewModel
  │  suspend 调用
  ▼
UseCase（domain）
  │  组合多个 Repository、做业务规则（如"保存前写入密码历史"）
  ▼
Repository（domain 接口 → data 实现）
  │  VaultSource 策略
  ▼
BitwardenVaultSource / KdbxVaultSource
  │
  ▼
Room（密文快照）/ Retrofit + OkHttp（网络）/ KDBX 引擎 / Keystore
```

- `Flow` 从 Room 一路向上：本地数据库是 UI 的**唯一数据源**（Single Source of Truth），网络结果只写库，不直接推 UI。
- KDBX 没有 Room 落库：由 `KdbxVaultSource` 维护内存 `StateFlow`（`MutableStateFlow<List<VaultItem>>`），保存后重放；对外仍表现为 Flow，UI 无感知。

## 4. 会话与密钥管理

```kotlin
@Singleton
class VaultSessionManager @Inject constructor(...) {
    private val sessions = MutableStateFlow<Map<String, VaultSession>>(emptyMap())

    suspend fun unlock(vaultId: String, credential: UnlockCredential): Result<Unit>
    fun lock(vaultId: String)
    fun lockAll()
    fun isUnlocked(vaultId: String): Flow<Boolean>
    fun requireKey(vaultId: String): VaultKey   // 抛异常若未解锁
}
```

- 自动锁定由 `AppLifecycleObserver`（`ProcessLifecycleOwner`）+ `InactivityTimer` + `ScreenOffReceiver` 驱动。
- 锁定即调用各 `VaultSource.lock()` → 清零密钥与解密缓存。

## 5. 错误与用户消息

```kotlin
@Immutable
data class UserMessage(
    val id: Long,             // 用于 Snackbar 去重
    val text: UiText,
    val action: MessageAction? = null,   // 重试 / 重新登录 / 前往设置
    val severity: Severity = Severity.Info,
)
```

| 错误 | 文案示例 | 动作 |
|---|---|---|
| `WrongPassword` | 主密码不正确 | 重试 |
| `TwoFactorRequired` | 需要两步验证 | 前往输入 |
| `Network` | 无法连接服务器，已切换到离线模式 | 重试 |
| `TokenExpired` | 登录已失效，请重新登录 | 重新登录 |
| `KdbxCorrupted(header)` | 文件头部损坏，可能无法恢复 | 选择其他文件 |
| `UnsupportedFormat` | 该数据库为 KDBX 3.1 或使用了不受支持的算法（AES-KDF / Argon2d / Salsa20 / Twofish），请转换为 KDBX 4.x 后再打开 | 查看转换指引 |
| `UnsupportedFormat`（服务端） | 服务端版本过低，请升级 Bitwarden / Vaultwarden | 前往设置 |
| `BiometricInvalidated` | 生物识别已变更，请用主密码解锁一次 | 输入主密码 |

## 6. 并发与取消

| 场景 | 策略 |
|---|---|
| 重复点击解锁 | 用 `Mutex` 或 `state.compareAndSet` 防重入；按钮置 `loading` 态 |
| KDF 计算 | 使用可取消的 `withContext(Default) { ... ensureActive() }`；用户取消即 `zero()` 中间值 |
| 同步 | 单库串行（`Mutex` per vault）；多库并行但限制并发 ≤ 3 |
| 保存 | 编辑页 debounce 300 ms；保存中禁用二次提交 |
| 搜索 | `debounce(250)` + `distinctUntilChanged()`；`flatMapLatest` 取消上一查询 |

## 7. 测试友好性

- ViewModel 只依赖 UseCase 接口 → 单测中注入 fake。
- `reduce` 为纯函数 → 用 `Turbine` 断言状态序列。
- `UiState` 默认参数化 → 每个测试只需设置关心的字段。
- 提供 `PreviewParameterProvider` 为每种状态生成预览（加载/空/错误/正常/多选/离线）。
