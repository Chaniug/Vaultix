### 教训（已写入 `ISSUES.md` #76~#80）

- **同一根因会在别的页面残留**：#67 修的是让位写在外层 padding，本轮验证码页又是同一个病
  ⇒ 修「一类 bug」时要**全仓搜一遍该模式**，别只修报出来的那一处（#76）；
- **一个手势事件只承担一种语义**：长按 = 进选择、滑动 = 危险操作，红底 / 位移
  **只能由位移一个驱动源**推；条件式增删 Compose 节点会让第一个像素的位移触发重组 ⇒ 起手抖（#77）；
- **RemoteViews 的 Material 只能对齐「尺寸 + 静态配色」**（阴影 / ripple / 动态色全属硬边界）（#78）；
- **队列表当判据前先问「哪些行对应用户正在看的东西」**：判定集合 ≠ 展示集合 ⇒
  用户看不懂的标记（删除类操作的条目在列表本就不可见）（#79）；
- **给滚动容器加让位后，要同步检查下拉指示器 / 加载态 / 吸顶头这些「不在滚动内容里」的元素**（#80）。

### ★ #88 根因（**不是密钥问题**）

用户原话是决定性的：「**像这种情况又必须清掉后台打开，才能看到指纹解锁**」——
`keyAvailable` 只在 KEK `MISSING`/`INVALIDATED` 时才 false，而那两种**重启进程也救不回来**
⇒ 「重开就有」只能是 **UI 状态被固化成错值**。

**三条前提实测钉死**（debug 包 `run-as` 可读私有状态）：
| 实测 | 结果 | 排除了什么 |
|---|---|---|
| DataStore `.pb` 值字节 `12 02 08 01` | `local_unlock_enabled…` = **true** | 不是"开关被关" |
| `shared_prefs` 含 `local_unlock_key::<vaultId>` | **payload 在** | **`disableLocalUnlock` / `clearBrokenLocalUnlock` 从未执行**（都会删它） |
| `bw_access::` / `bw_refresh::` 均在 | — | 与"凭据库密钥"无关，不用重登 |

**机制**：`UnlockViewModel` 里「选库」（协程 A）与「订阅 `localUnlockAvailable`」（协程 C）
**并发**收集同一个 `observeVaults()`；C 若先处理同一次发射，其 `.map` 读到的 `var vaultId`
仍是空串 ⇒ `return@collectLatest` 跳过，而唯一写入点正在其后 ⇒ **状态永久停在初值 false**
⇒ 指纹入口不渲染、生物识别也不自动弹。重建 ViewModel（手动返回 / 清后台重开）才有一次重掷机会。

**修法**：新增私有 `resolveTargetVaultId(vaults)`，订阅侧改为
`.map { resolveTargetVaultId(it) }.filter { isNotBlank() }.distinctUntilChanged()`，
**不再读跨协程 `var`**（语义不变：路由带参只认该库、不在列表则"无可解锁目标"；无参才自动选库，
且**先看查看层锁**再看"第一个未锁定"）。

**门禁**：新增 `UnlockViewModelTest`（3 例），
`fingerprintEntryAppearsEvenIfFirstCollectorGetsTheVaultListLate` **修前精确红 → 修后绿**；
另两例是反向门禁（正常顺序 / 未启用时必须保持隐藏）。
全模块 detekt / `:app:compileFullDebugKotlin` / `:app:assembleFullDebug` / app 全量单测 全绿。

**真机验收（四条独立证据闭环）**：① 单测红→绿；② 真机 dump 到
`window-name="biometrics_dialog"`（`解锁 Vaultix` / `请按压屏内指纹感应区验证指纹`）
⇒ **自动弹窗真的发起** ⇒ `localUnlockAvailable == true`；③ `keystore2` 日志
`add_auth_token(authType=0x2)` → `createOperation/update/`**`finish`**（带 `HardwareAuthToken`），
`acceptCrypto` **118→135** ⇒ **KEK 健康、`unwrap` 成功**（顺带排除"次要可能 keyAvailable=false"）；
④ 用户确认解锁页有指纹入口且实际可解锁。
⚠️ 这四条合起来才叫闭环 —— 只有"用户说好了"不足以定论。

### 教训（本轮新增，均已写进用户级记忆）

- ★★ **`adb shell cat` 拉二进制会被换行转换损坏**：拉一个 389,120 字节的 SQLite 库，
  本地变 **389,437**（+317 = 被替换的 LF 数），SQLite 直接报 `database disk image is malformed`。
  ⇒ **拉二进制一律 `adb exec-out`**，且**拉完比对字节数**。同一坑也影响 DataStore 的 `.preferences_pb`。
- ★★ **设备锁屏时 `adb install` 会被拒**（`INSTALL_FAILED_ABORTED: User rejected permissions`），
  且**重跑时输出可能只剩空白行、看着像装上了** ⇒ 必须用 `SHA-256` 或 `lastUpdateTime` 核证。
- ⚠️ **别在设备端 `adb shell grep` 过滤 `uiautomator` 的 xml** —— **不生效**，
  `window-name` 与计数全空 ⇒ 会静默得到"全是 0"的样本，**极易误读成"页面上没有那个元素"**。
  ⇒ 一律 `adb pull` 到本地再 grep。
- ⚠️ **`uiautomator dump` 可能抓到叠加窗而非宿主页面**（如 `biometrics_dialog`），
  此时看不到底下 Activity 的文案 ⇒ **判空之前先看 `window-name`**。
- ⚠️ **`jit_compiled` 这类 ART 消息会挂在应用进程 tag 下**，debug 包里占该 tag 的 **99.9%**
  （39,897 行里 39,844 行）⇒ 不是应用在刷日志。统计"日志里有多少错误"**必须先按包过滤**。
- ⚠️ **PSS 与 RSS 是两个口径**：进程列表聚合值 242MB ≈ TOTAL RSS 247MB，而私有 PSS 仅 78.6MB
  ⇒ 用户看到的"占用很大"多半是**含共享页的 RSS 口径**，**下结论前必须说明用的哪个口径**。

### 两次被否各修掉一个真问题

1. **"盾 + 钥匙孔"被否**：用户「第一眼给人的感觉是**很邪恶的笑容**一样，盾牌的装饰元素不够」。

2. **人字带被否 → 改 V 带**：用户「人字带改成 **V** 字带更好吧…我这个项目也叫 vaultix，
   可以呼应，盾牌也是 U 型的」+「两种颜色会不会太单调」⇒ 背景升级三档渐变 + 引入金色第二色相。

### ★ 方法论：**"视觉居中"要算，不能靠眼**

| 对象 | 包围盒中心 y | **面积质心 y** |
|---|---|---|
| 内场 | 57.39 | **54.73** |
| 首版 V | 54.00 | **50.89** ⇒ 视觉重心比内场**高 3.84dp** |

**根因**：V 带的重量集中在上面两条臂（顶部最厚）⇒ **面积质心天然高于包围盒中心**，
**只对齐包围盒是不够的**。解：**下移 3.84 + 半宽 13→11** ⇒ 质心偏差 **0.000**、
边采样（步长 0.5）越界数 **0**。
最终 V：`M43,45 L49,45 L54,63 L59,45 L65,45 L54,71 Z`（48dp 下 V 高 11.5dp、臂宽 2.7dp）。
⚠️ 本次为此写了三个一次性脚本（安全圈校验 / 点在多边形内 / 面积质心+越界采样）——
后续若再动图标几何，**务必重跑同款校验，别凭目测挪**。

### 教训

- ⚠️ **写 Android XML 资源时，注释里不能出现连续两个短横线** ——
  markdown 表格分隔行 `|---|---|` 会直接让 aapt2 报 `Failed to parse XML file '(...).xml'`，
  **错误描述完全不提注释**，极难猜。⇒ 资源注释里别放 markdown 表格；改完先跑一次 XML 解析校验。
- ⚠️ **monochrome 层必须保持单一颜色剪影**：系统只取 alpha 重新着色 ⇒
  彩色版里"填色的 V"在单色版**必须改成挖空**，否则与盾同色而整块消失。
  两层结构可以不同，但**形状语义必须一致**。
- 装机核证方式（同第五十三轮）：与本地包比 **SHA-256**，而不是只看 `adb install` 的输出。
