## 根因与机制备忘（防重复调查）

1. **老 autofill 双轨制**：Via 等传统 WebView 走 Autofill Framework（Vaultix 此轨正常）；
   Chrome/Edge 走 Credential Manager（只问系统已启用的 Provider）。两轨独立，勿混淆。
2. **dataset 认证（老路）**：服务无「点选回调」→ 复制 TOTP 须挂 `setAuthentication`；
   认证 Activity 必须**完整启动（onResume）后**再 `setResult`+`finish`，onCreate 同步
   会丢认证结果（表现「验证码复制成功但密码没填」）；宿主 launchMode 须 standard、
   intent 不带 NEW_TASK（引导型才补）。
3. **「能填就不复制」**：页面有验证码框 → 直接填；无码框 → 才复制兜底（对齐 Bitwarden）。

### 找到的缺陷（均修复）
1. **`androidx.credentials` 1.3.0 太旧（总根因）**：1.5.0 才引入「凭据选择二级 UI 体验」
   （聚焦输入框时下发请求 + 下拉/键盘建议聚合），Chromium 呈现凭据条目依赖它；
   1.5.0 另引入 `setBiometricPromptData`。→ 升 **1.6.0**（对齐 Bitwarden）。
   原锁 1.3.0 的理由（origin 被收紧）已由官方 `isOriginPopulated()`+`getOrigin()` 消解。
2. **来源读取**：新增 `CallingAppOrigin`，替换 2 处 `callingAppInfo.origin` 直读。
3. **entry 能力**：补 `setAutoSelectAllowed` + 按需 `setBiometricPromptData`；
   新增 `RomCompat`（**HyperOS/MagicOS 不挂**——Bitwarden 原文标注 HyperOS 不兼容）。
4. **取消监听**：两个 process 方法补 `cancellationSignal.setOnCancelListener`。
5. **密码条目按来源过滤**：复用 `BitwardenLikeAutofillMatcher`（与 autofill 通道同规则）；
   浏览器场景只用 origin 不用包名；来源不可得时不过滤。
6. **多库部分锁定**：凭据通道与认证动作通道并存（可就地解锁其余库）。
7. **⑥ settingsActivity**：新建 `CredentialProviderSettingsActivity`，替代 `MainActivity`。

### 教训沉淀
- **系统集成依赖的 androidx 版本不能凭「能编译」锁死**；要对照官方 release notes 确认
  功能引入版本（本次是 1.5.0 的二级 UI 体验）。
- 为绕单个 API 变更（origin 收紧）退到有功能缺陷的版本，是本末倒置。
- 魔改 ROM（HyperOS/MagicOS）对新系统 API 的兼容性要主动设防（Bitwarden 有先例）。

  **需用户提供具体站点**再修分类器。
