# AI 协作记忆

> 供 **AI 接力**使用。开工前必读，收工后必更新。

## 文件说明

| 文件 | 用途 |
|---|---|
| `MEMORY.md` | 项目长期约定：定位、架构、技术栈硬约束、代码来源与协议 |
| `ISSUES.md` | 踩过的坑（现象 → 根因 → 解法），**务必先读，避免重复踩** |
| `SESSION-YYYY-MM-DD.md` | 每次会话的工作日志 |

## 接力流程

1. 读 `MEMORY.md` —— 了解项目约定与硬约束
2. 读 `ISSUES.md` —— 避开已知坑（AGP 9 五连坑、Hilt 版本绑定必看）
3. 读 `Docs/progress/current-status.md` 与 `next-steps.md` —— 知道进度与下一步
4. 完成后**更新上述文件**；新坑写入 `ISSUES.md`

## ⚠️ 读记忆的正确姿势（2026-09-12 补充）

**被推翻的旧结论不会删除，而是就地标注 —— 看到 `~~删除线~~` / `🔴 已被推翻` /
`~~xx~~` 标记时，务必读完整标注再决定要不要照做。**

真实案例：`ISSUES.md` #35 曾判定「通行密钥浏览器流程应回传**空占位符**」，
该结论于 2026-09-12 被 **#43** 推翻（回传空占位符会让 GitHub 注册直接失败）。
**只读 #35 不读 #43，就会重新引入同一个 bug。**

因此新增两条纪律：

| 纪律 | 说明 |
|---|---|
| **旧结论就地加勘误指针，不删原文** | 保留错误推演过程有价值（能看出当时是怎么想歪的），但**必须在标题处**给出推翻标记与正确去向 |
| **推翻类记录必须写「错在哪」** | 否则接力者只会知道结论变了，不知道**为什么**变，容易又绕回去 |
