## 272. 本地 KDBX 怎么接入 OneDrive —— 补一条**引导**，不代搬文件（2026-11-10 晚，用户提问）

**用户原话**：

> 本地的 kdbx 如何接入到 onedrive 呢，好像目前项目没有考虑到这个部分，
> 相当于本地的 kdbx 库上传到 onedrive 上？

确认：**此前确实没有这条路**。现有的「从网盘添加」是单向的 ——
挑一个**已经在网盘上**的 `.kdbx`；反向的"把本地文件搬上去"不存在。

### 为什么不做"一键迁移"

技术上缺的只是一个"搬过去"的动作（`OneDriveGraphClient.upload` 已有原子上传 +
条件写 + 写后读回）。但搬完要付出的代价不在这个动作上：

1. **库的身份绑在位置上**：`vaults.origin`、库主键、加密信封（`markUserLocked` 那套）、
   已登记的指纹与 PIN、文件夹归属，全部以 origin 为准。搬完要让新库可用，
   就要迁移这一整套 —— 任何一步失败，用户丢的是**解锁凭据**，不只是两步操作。
2. **原文件删不删都是坏选择**：删了用户以为数据丢了；不删就是两份会分叉的库。
3. **用户自己搬的代价极小**：在 OneDrive 客户端上传，再回来「从网盘添加」，
   只多输一次主密码 —— 而这条路**不迁移任何东西**，失败也不会损坏已配好的解锁方式。

⇒ 结论：Vaultix 只给方法，不替用户动文件。

### 落地：`KdbxCloudGuideScreen`（「放到网盘」）

| 段 | 内容 |
|---|---|
| 开场 | 本地 `.kdbx` 只是一个文件，只有这台设备能打开；放到 OneDrive / WebDAV 上才能多设备共用 |
| 三步 | ① 上传文件（用网盘客户端）② 从网盘添加（密码库管理 → 添加密码库 → 从网盘打开）③ 输入同一个主密码（主密码 / keyfile 不变，条目不用重输） |
| 为什么不自动搬 | 库身份与指纹 / PIN 绑在文件位置上；自动搬会牵动解锁凭据，风险远大于省下的两步 |
| 出口 | 两张卡：网盘账号 / 从网盘添加（复用现成路由，不实现第三套流程） |
| 页脚 | **本机旧文件不会自动删除** —— 确认新库能打开、条目都在之后，用户自己处理 |

**入口**：本地 KDBX 那一行的 ⋮ 菜单 →「放到网盘…」。

```kotlin
internal fun VaultSummary.canMoveToCloud(): Boolean =
    kind == VaultKind.KDBX && kdbxSourceTargetOf(origin) == KdbxSourceTarget.LocalFile
```

⚠️ 先判 `kind`：Bitwarden 的 origin 是 `https://…`，只按来源判会落到 `LocalFile`。
⚠️ 判据用 `kdbxSourceTargetOf` 而不是 `origin.startsWith("content://")` ——
后者正是 #264（WebDAV 被显示成本地文件）的病根。

### 为什么是"页"而不是对话框

三步 + 一句"为什么不自动搬"，M3 对话框（标题 + 正文 + ≤3 动作）装不下；
而且它是**可回看**的说明页，不是"为一次决定服务"的瞬时容器
（同一条理由见「国内镜像」从对话框迁进关于页，`SettingsScreen` 的 `UpdateCheckDialog` KDoc）。

### 为什么不打扰

没有横幅、没有首启弹窗、没有角标。入口只在**本地 KDBX 那一行**的 ⋮ 里 ——
没有本地库的用户永远看不到它；有本地库的用户，正好在管理这个库的时候看到。

### 边界（不要做）

1. **不要**在这个页面加"开始上传"按钮。真要做迁移，是另一个功能，
   要先解决 origin / 库 id / 解锁信封的迁移与回滚，不是给引导页加个按钮。
2. **不要**在上传后自动删除原文件 —— 数据安全上这是最危险的一步。
3. **不要**假设 keyfile 也跟着搬：keyfile 是另一个 URI，目标设备上同样要能选到它
   （三步里那句"主密码与密钥文件都不变"说的就是这个）。

### 测试

`VaultCloudCapabilityTest`（5 例）：

| 库 | 期望 |
|---|---|
| 本地 SAF（`content://`） | ✅ 出 |
| OneDrive（`onedrive:acct:path`） | ❌ 不出 |
| WebDAV（`webdav:cred:https%3A…`） | ❌ 不出 |
| Bitwarden（`https://…`） | ❌ 不出（先判 kind 的那条） |
| 畸形 origin 的 KDBX | ✅ 出（当本地处理，最坏只是说明页对不上） |
