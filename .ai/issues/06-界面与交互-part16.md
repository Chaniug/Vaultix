## 275. 主题模式「关闭」按钮用错强调级别 + 关联应用露包名 + 「已绑定」文字占宽 + 卡包两类条目长成同一张列表行（2026-11-10 深夜，用户 4 点反馈）

**用户原话**（附 3 张真机截图）：

> 1. 在设置里面，外观与自定义中，主题模式中的关闭按钮好像不对，不符合标准。顺带查一下项目中其他位置的按钮是否存在错位或者是大小不对，弹窗大小不对，字体不对，文案啰嗦的地方，都是需要整改优化的。
> 2. 密码条目中，关联应用的部分，展示的时候显示的是完整的包名，不是中文的显示。
> 3. 验证码界面的条目，已绑定的文案能够换成图标显示吧，节约空间又提升美观度。
> 4. 卡包里面的展示，像卡片条目，比如一个银行卡条目，能不能做的大一点，像真的银行卡那样的造型的，而个人信息，能不能做的像名片那样好看一点。

第 1 点是**用户凭观感点名的一处**，后面「顺带查一下」把它扩成了全仓排查；
2 / 3 / 4 是三处独立的功能诉求。四件事看似无关，但收敛到同一条判据：
**控件的视觉权重必须匹配它的语义权重**。

### 一、点名的「关闭」按钮：不是位置也不是尺寸，是强调级别

`SettingsScreen.ThemeModeDialog` 的单动作退出按钮用了 `DialogOutlinedActionButton`。
M3 动作区的强调顺序是 **TextButton（低）< OutlinedButton（中）< Button（高）**；
「关闭 / 取消 / 完成」是**收起**动作而非决策动作，应当最低强调。带一圈边框的按钮
在只有一个动作时反而成了整个对话框视觉最重的一块 —— 用户说的「不对」就是这个。

顺着「顺带查一下」把全仓 `AlertDialog` 动作槽、弹窗尺寸、字体、副标题过了一遍，
结论分三档：

| 档 | 发现 | 处理 |
|---|---|---|
| **确认有问题** | 7 处单动作对话框用 `DialogOutlinedActionButton`：主题模式、剪贴板清除、自动锁定、长文说明、密码库操作结果页、KDBX 冲突、卡包挡创建提示 | 全部改 `DialogTextButton` |
| **确认有问题** | `PasskeysScreen` 的「删除」在 `dismissButton`、「关闭」在 `confirmButton` —— **槽位反了**，危险动作反而落在次要位置 | 删除移到 `confirmButton`（error 色 + 二次确认），关闭移到 `dismissButton` |
| **确认有问题** | `TotpCodesScreen.LoginPickerDialog` 写死 `height(240.dp)`，候选少时留一大片空白；还挂着 `dismissButton = { }` 空槽 | `heightIn(max = 240.dp)` + 可滚动列表；删空槽 |
| **查了，不用动** | 字体：硬编码 `fontSize` 只在 `VaultixTypography.kt`、顶栏动态适配、品牌标签、大号验证码等有理由处，未发现字号错用 | 不动 |
| **查了，不用动** | 弹窗尺寸：`DialogShell` 的 `0.92f` 宽 / `520.dp` 上限、多处 `heightIn(max)` + `verticalScroll` 都在位 | 只修上面那一处固定高度 |
| **确认有问题** | 文案啰嗦：5 条设置行副标题（`auto_copy_totp` / `copy_next_totp` / `autofill_save_prompt` / `manual_fill_tile` / `quick_unlock_legacy`）+ 关联应用「已安装 · 自动填充会匹配到此应用」 | 精简，解释性文字让位给主标识 |

⚠️ **一个 API 事实，别再踩**：M3 这个 `AlertDialog` 重载把 `confirmButton` 定为**必需参数**。
一度把「只有一个按钮」理解成「只给 `dismissButton`」，编译器把它解析到 `content` 重载，
报 `No value passed for parameter 'confirmButton'` 外加一串「@Composable invocations…」。
**低强调 ≠ 换槽位**：单动作乖乖放 `confirmButton`。真要整个对话框没有动作区，
得改用 `BasicAlertDialog` 自己排版，而不是留 `dismissButton = { }` —— 它不报错、不显示，
但暗示「这里本来该有按钮」，是纯噪音。

**文案按语义选词**：`取消` = 放弃这次操作；`关闭` = 收起看过的内容；
`完成` = 结果已发生后的确认收尾。故结果页按成功 / 失败分流 `action_done` / `action_close`，
纯说明页用 `action_close`，其余单选 / 设置页用 `action_cancel`。

### 二、关联应用显示完整包名

截图里「关联应用」一行赫然是 `com.tdx.AndroidNew`，而同一条目的自定义字段里
`appName=通达信` / `bastion_app_name=通达信` / `bastion_app_package=com.tdx.AndroidNew`
—— **名字本来就在库里，只是没人读**。

新增 `ui/common/AppLabel.kt`（纯逻辑，可单测）：

1. `fromCustomFields(fields, packageName)` 先按别名表找应用名：`appName` / `App Name` /
   `bastion_app_name` / `BastionAppName` / `applicationName` / `androidAppName`…
   （KeePassDX 与 Bastion 的写法都要认，键名大小写与分隔符归一后比较）；
2. **有包名字段时，必须字段值与当前包名一致才允许采用应用名** —— 一条密码可以绑多个应用，
   否则会把 A 的名字安到 B 头上；
3. 字段值本身就是包名时不认作显示名（有的库把 `appName` 直接写成包名）；
4. 没名字 → `installedLabel(context, pkg)` 走 `PackageManager` 读已安装应用 label，
   Android 11+ 包可见性下用 `runCatching` 兜底（`NameNotFoundException` 不该让详情页崩）；
5. 都没有 → 回退包名，总比空白强。

`AppsSection` 改成一次性 `remember(item.uris, item.customFields, context)` 构建
`List<AppDisplay>`，**不要在 `forEach` 里逐条 `remember`**：`remember` 按**调用位置**分组，
循环里同一个调用点只有一份缓存，后一条会覆盖前一条。

支持文案从「已安装 · 自动填充会匹配到此应用」精简为 `已安装 / 未安装`；
有中文名时副行补 `包名 · 已安装`（包名退到副行，需要核对时仍在，但不再当主标识）。

### 三、「已绑定」文字 chip → 圆形图标徽标

`TotpCodesScreen.Badge(bound)` 原是文字 chip，标题行右侧常驻 4 个字，窄屏下挤标题。
改成 `26.dp` 圆形 `Surface` + `14.dp` 图标：`Link`（已绑定，primary）/ `Timer`（独立，tertiary），
底色取对应色的 14% 透明。

两条不能省的约束：

- **图标替代文字必须留 `contentDescription`**（`totp_badge_bound` / `totp_badge_standalone`），
  否则 TalkBack 读到的状态信息整个消失 —— 省下的是像素，不能省掉语义；
- **不挂 `IconButton`**：这是纯状态徽标、没有动作，挂了点击语义会抢 ⋮ 菜单的触摸区。

### 四、卡包：银行卡做成实体卡、个人信息做成名片

旧 `CardWalletRow` 把两类条目都塞进同一张 `EntryCard` 列表行 —— 只换标题和一行摘要。
新增 `ui/cardwallet/WalletCardFaces.kt`（475 行；拆文件是为了不让 `CardWalletScreen.kt` 撞 detekt 上限）：

| 类型 | 造型 | 比例 | 关键取舍 |
|---|---|---|---|
| 银行卡 | 深色渐变 + 光斑 + Canvas 芯片 + 等宽凸印卡号 + 持卡人 / 有效期 | `aspectRatio(1.7f)` | 深色是**印刷品图案**，不跟随主题（真实银行卡在浅色主题里也仍是深色）；渐变按 `item.id.hashCode()` 稳定挑选，滑动重组不会换色；1.7 比实体卡略扁，兼顾一屏能看到下一张 |
| 个人信息 | 浅色 `surfaceContainerLow` / `secondaryContainer`、姓名作主标识、字段分列 | `aspectRatio(2.45f)` | 更扁，与卡形成视觉差异；底色跟随主题（名片是纸，卡是塑料） |

`CardWalletRow` 现在只做类型分发。**语义不同就不该共用一张卡** —— 这是 8.4 已有判据

选中态保留 `2.dp primary` 描边：`PressAndSwipeToDelete` 要求用户先看清哪张被选中才敢左滑删除，
描边是**功能性反馈**，不是装饰。点击 / 长按通过 `combinedClickable` 透传
（`@OptIn(ExperimentalFoundationApi)`）。`maskCardNumber` 从 `CardWalletScreen.kt` 提为
`internal` 放进新文件 —— **打码规则只留一份**。

## 276. 卡包第二轮：卡面颜色改由「银行」决定 + 名片按真实名片重排（2026-11-10 夜，用户反馈）

**用户原话**：

> 需要不同的银行有不同的颜色卡片。然后个人信息的名片也要好看一点。

#275 把银行卡做成了实体卡、把身份条目做成了名片，但两处都只做到「形状像」。
这轮用户要的是**颜色有语义**、**名片有层次**。

### 症状一：颜色跟银行没有关系

#275 的卡面渐变是 `paletteFor(item) = CARD_FACE_PALETTES[floorMod(item.id.hashCode(), 5)]`：
按**条目 id** 从 5 组色里挑。它保证了「同一张卡每次打开颜色一样」，
但和「这是哪家银行」毫无关系 —— 招行的两张卡可以一红一蓝，招行和建行反而撞成同一个蓝。
用户没法靠颜色认卡，而**认卡正是颜色在卡包里唯一该干的事**。

⚠️ 数据模型里**没有发卡行字段**：`VaultCard.brand` 存的是**卡组织**（Visa / 银联 / Mastercard），
不是「招商银行」。银行名只可能出现在条目标题（「招行工资卡」）或用户手填的 brand 文本里。
⇒ 这不是换个色板就能解决的事，得先有一套「从哪读银行名」的判据。

### 解法：四级配色判据，收敛到 `core/common/BankCardPalette.kt`

| 级 | 条件 | 上色依据 |
|---|---|---|
| ① | 标题 / brand 命中常见银行关键词表（14 家） | **显式分配**一组色相，各家互不重复 |
| ② | 表外但标题里能提出「XX银行」（如「宁波银行借记卡」） | 用**银行名**稳定 hash 到 18 组色板 |
| ③ | 连银行名都没有 | 按 `CardBrand` 卡组织显式配色（Visa 蓝 / 万事达橙 / 银联红 …） |
| ④ | 卡组织也 `UNKNOWN` | 才退回 `item.id` 稳定 hash（旧行为降级为兜底） |

18 组深色渐变**刻意把色相铺开**而不是照抄各家 logo 色 —— 工行、中行、招行都是红色，
照抄只会得到三张一样的卡，与用户诉求正好相反。全部保持足够暗，卡面白字才读得清。

**卡面副标题同步改成「银行名 · 卡组织」**（识别出银行时），让「为什么这张是红色」在卡上自解释；
没识别时维持旧的卡组织文本，`distinct()` 防止两处写同一个词。

⚠️ **关键词表必须按长度降序匹配**：`boc` 是「中国银行」、`bocom` 是「交通银行」，
`cmb` 是「招商」、`cmbc` 是「民生」。按书写顺序 `firstOrNull` 会让短词吃掉长词，
交通银行被染成中行的颜色 —— 这种错在界面上完全看不出原因，只能靠测试拦。

⚠️ **纯逻辑不放 `ui/`**：`BankCardPalette` 不 import Compose / Android，颜色用 ARGB `Long`
传递，UI 层再包成 `Color`。两个理由：① 银行名关键词是**数据**不是 UI 文案，放 `ui/` 会被
`check_ui_hardcoded_text.py` 当成硬编码中文（该门禁白名单「只减不增」，不该为数据开口子）；
② 「颜色由谁决定」这条判据要能在 JVM 单测里直接断言，埋在 Composable 里就没法测。
同理 `CardBrandDetector` 的中文关键词本来就在 `core/common`。

顺带去掉了农行的 `abc` 关键词（会误伤 "ABCD corp card" 这类普通英文），
改收 `abcbank` / `agriculturalbank` + 中文名。

### 症状二：名片只是「一行列表」，没有名片的层次

#275 的名片是 `2.45f` 的横条：左侧 4dp 竖条 + 44dp 圆形首字 + `titleMedium` 姓名 + 副标题 +
竖排联系方式，全挤在一行里，姓名压根大不起来。

改版：比例 **2.45 → 2.05**（328dp 宽下 134dp → 160dp），排版才有呼吸空间，
同时仍明显扁于银行卡 1.7 的 193dp。版式按真实名片分四层：

1. **机构抬头**：公司名 / 城市 / 兜底「个人信息」，`labelMedium` + 1.2sp 字距 + primary 色，
   右侧 34dp 渐变描边圆形 monogram；
2. **大姓名**：`headlineSmall` SemiBold，下方一行「省 · 国家」小字（有值才画）；
3. **细分隔线**：`outlineVariant` 65% 透明；
4. **横排联系方式**：两项各 `weight(1f)`，比旧版竖排省高度，更像名片脚注。

材质：底色 `surfaceContainerLow → surfaceContainer` 的**主题色渐变**（跟随深浅主题，
选中时换 `secondaryContainer → tertiaryContainer`），左侧 5dp `primary → tertiary` 渐变抬头竖条
贯穿整张卡，右下角一实一虚同心圆水印（纯 Canvas 绘制）。银行卡是「深色印刷品、不跟随主题」，
名片是「纸、跟随主题」—— 两者刻意保持材质差，这正是 #275 定的判据。

### 交互契约一个都没丢

整卡 `combinedClickable` 可点 / 长按选中；选中态 2dp primary 描边
（`PressAndSwipeToDelete` 的删除前置反馈，不是装饰）；卡号仍只显示打码末四位；
水印与光斑不拦手势、不进无障碍树；打码规则仍只有 `maskCardNumber` 一份。

### 踩坑

- **`matchParentSize` 是 `BoxScope` 扩展**：把水印抽成独立 Composable 后编译报
  `Unresolved reference 'matchParentSize'`。修法是给函数加接收者
  `private fun BoxScope.IdentityWatermark(...)`，而不是改回 `fillMaxSize()`（那样水印会相对
  padding 后的内容区偏移，与银行卡那两处光斑口径不一致）。
- **本地 `ANDROID_HOME` 本轮没带过来**，gradlew 报 `SDK location not found`；SDK 实际在
  `/opt/android-sdk`，显式设环境变量即可，别去写 `local.properties`（那是本机配置，不该入库）。
- **门禁台账要对口径**：`./gradlew testFullDebugUnitTest detekt` 只跑 app 的 fullDebug 变体，
  本地汇总会少算其它模块；CI 用的是**显式列出 9 个模块**的命令。按 CI 同款跑完才是
  **1741 例**（上轮 1730 + 本轮 11），别拿 1590 那个数去汇报。
