## 301. 条目页 ⋮ 菜单改版：单块 DropdownMenu → 三块 Expressive 分组的独立卡片（2026-11-17，用户截图反馈）

### 用户原话

> 这个部分的 UI 该如何设计才好看呢？信息直观，功能完善，目前感觉这个看起来很老套的样子

附一张真机截图：顶栏 ⋮ 展开后的下拉，内容为「切换密码库 / 回收站 / 文件夹管理」三项 +
一条底部状态灯-同步-锁定行。

两条硬指标写在话里：**信息直观**、**功能完善**。⇒ 这一轮的前提是
**一个功能都不许删**（`ItemsMoreMenuGroupingTest` 用一条用例把四个入口 + 两个动作钉死）。

### 改前是什么样（为什么"老套"）

| 项 | 改前 |
|---|---|
| 结构 | 单个 `DropdownMenu`，一整片同色底板 |
| 分组 | 两条 `HorizontalDivider`（1dp 灰线） |
| 圆角 | 4dp（`DropdownMenu` 默认 `CornerExtraSmall`） |
| 组标签 | `MenuGroupTitle("前往")` —— 11sp 灰字，占一整行 |
| 身份信息 | `MenuVaultCard`：280dp 固定宽 + 三行纯文本，**看不出是哪种库** |

问题不在"某个元素不好看"，而在**整套结构与项目的视觉语言不是一套**：本项目的卡片是
16dp 圆角 + 8dp 间隙 + 1dp `outlineVariant` 描边（`EntryCard` / 设置卡都这样），
而菜单还是"一整块板被两条线切割" —— 那是十年前 Android 菜单的形态。

> 判据：**「老套」几乎总是"结构与周边语言不一致"**，而不是配色。改配色救不了它。

### 改后：三张独立卡片

| 组 | 内容 | 回答的问题 |
|---|---|---|
| 1 | 库身份（40dp 类型徽标 / 库名 / 条目数 / 来源 / 同步状态） | **我在哪** |
| 2 | 切换密码库 · 验证码 · 回收站 · 文件夹管理 | **去别处** |
| 3 | `[●] [⟳] ←weight→ [🔒]` | **对这个库做什么** |

- 外层 `DropdownMenuPopup(expanded, onDismissRequest)`：只给 Popup + 布局，**不带整块底**。
- 每组 `DropdownMenuGroup(shapes = MenuDefaults.groupShapes(shape, inactiveShape), border = BorderStroke(1.dp, outlineVariant), modifier = Modifier.width(MENU_PANEL_WIDTH))`。
- 组间 `Spacer(Modifier.height(Spacing.sm))` = 8dp。
- 组 1 增一枚**库类型徽标**（40dp 圆牌 + 22dp 品牌图标，`primaryContainer` / `onPrimaryContainer`）。
- 组 2 删掉「前往」小标题；四项走 `buildList { … }` + `forEachIndexed`，圆角取
  `MenuDefaults.itemShape(index, items.size).shape`。
- 组 3 `MenuSyncLockRow` **内容一字未改**（2026-11-08~09 改了四轮才定稿）。
- `VaultCardInfo` 新增**必填** `kind: VaultKind`（无默认值 —— 有默认值就会有人不传，
  退化成"少一枚徽标"而不是编译错误）。

### 四处取证（都不是"感觉这样好"）

#### ① 为什么不用 `MenuDefaults.groupShape(index, count)`

读了 `material3-android-1.5.0-alpha16` 的 `MenuDefaults.kt`：`groupShape(index, count)` 给的是
**「一整块被切开」**的语义 —— 首组上 16 / 下 8，中组全 8，尾组上 8 / 下 16，
配 `GroupSpacing = 2.dp`（`SegmentedMenuTokens.SegmentedGap`）。组的边界靠**圆角半径变化**暗示，
2dp 缝在 density 3.47 的真机上几乎渲染成亚像素线 ⇒ 读起来仍是"一整片"。

⇒ 改 `MenuDefaults.groupShapes(shape = VaultixCorner.Panel, inactiveShape = VaultixCorner.Panel)`：
三组统一 16dp 四角全圆。**为什么用 `groupShapes` 而不是手写 `Surface`**：前者仍走
`DropdownMenuGroup` 的 hover / 涟漪 / 无障碍语义，只换形状；后者要把这套语义全部重写一遍。

#### ② 为什么间隙用 `Spacing.sm`（8dp）而不是 `MenuDefaults.GroupSpacing`（2dp）

2dp 是框架为"整块切开"配的值。本实现要的是"独立卡片堆叠"，缝必须一眼可见。
8dp 恰好是项目标尺里"相关元素之间的标准间隙"那一档 —— 是设计选择，不是随手数字。

#### ③ 为什么必须加 1dp 描边（这条是**截图逼出来的**）

第一版只有 8dp 间隙、没描边。渲染出来一看：浅色下三块**又糊成一片**。

取证：组容器色是 `surfaceContainer`（`#F1F0EF`），屏幕底是 `surface`（`#FDFCFB`）,
两者亮度只差约 **4%** —— 8dp 的缝在两块近似同色之间等于没缝。

⇒ 加 `border = BorderStroke(1.dp, MaterialTheme.colorScheme.outlineVariant)`（`#C6C6C5`），
与 `EntryCard` 同支色、同值宽度。**形状语言和列表里的卡片保持一致**，这才是"不老套"的实质：
不是加特效，是让同一屏里的东西用同一套形态语法。

> 判据：**分组视觉必须同时有「间隙」与「描边」**。只靠间隙，在浅色低对比主题（本项目的
> `surface` 与 `surfaceContainer` 只差 4%）下等于没做。详见 `.ai/MEMORY.md` 长期判据。

#### ④ 为什么徽标不复用解锁页的 `VaultKindBadge`

视觉同款（`primaryContainer` 底 + `onPrimaryContainer` 图标），但不复用：
那一个是 `UnlockScreen` 的 **private** 实现，尺寸与用途都不同（那一处要撑起整屏主角）。
抽公共组件需要同时改两处的尺寸参数 —— 收益不抵风险。KDoc 里写清"同款但不同源"，
避免下一个人误以为是漏抽。

### 7 条源码门禁（`ItemsMoreMenuGroupingTest`）

| # | 用例 | 钉住什么 |
|---|---|---|
| 1 | 外层必须是 `DropdownMenuPopup` 且不含 `DropdownMenu(` | 退回单块菜单 = 分组白做 |
| 2 | 三组内容都包在 `MenuGroup` 里，且正好 3 个 | 少包一组 = 该组跟着外层 Popup 没有底 |
| 3 | 正好 2 个 `MenuGroupGap()` | 库未知时只有 2 组，因此 gap 数固定为 2 |
| 4 | `MenuGroup` 必须带 `border` 且是 `outlineVariant` | 浅色下靠它才分得开 |
| 5 | 三组共用 `MENU_PANEL_WIDTH`，且该常量存在 | 切库时浮层不能变形（2026-10-04 真机对照结论） |
| 6 | 导航项用 `MenuDefaults.itemShape(` | 首/尾项圆角不能手写 `index++` |
| 7 | 四个入口与两个动作一个都不能丢 | **「功能完善」这条硬指标** |

### 四条变异反证（全部转红，还原后复绿）

| 变异 | 结果 |
|---|---|
| `DropdownMenuPopup` → `DropdownMenu` | 用例 1 红 |
| 删掉 `border = …` | 用例 4 红 |
| 删掉一处 `MenuGroupGap()` | 用例 3 红 |
| `itemShape(index, count)` → 固定 `VaultixCorner.Small` | 用例 6 红 |

⚠️ **变异① 首轮是"编译红"不是"测试红"**：`DropdownMenu` 的 import 已在本轮删掉，
换回来直接 `Unresolved reference` —— 那证明不了门禁有效。补回 import 重跑才拿到真正的
`外层必须是 DropdownMenuPopup … FAILED`。
> 判据：**变异反证必须确认"红的是断言，不是编译"**。编译红是假阳性，它只证明代码不完整。

### 踩到的坑

1. **`DropdownMenu` 自带整块底** —— 在它里面套 `DropdownMenuGroup`，"独立卡片"会被
   外层那块底板重新粘成一片。必须换成 `DropdownMenuPopup`。这个坑只能靠读框架源码发现，
   编译器与 detekt 都看不出。
2. **注释与代码用词雷同 ⇒ 门禁假绿**（本仓库第 N 次踩）。`DropdownMenuPopup` 里含
   `DropdownMenu` 子串；`MenuGroup` 的 KDoc 里写着 `border` / `DropdownMenu`。
   ⇒ 门禁一律**先剥整行 `//` 注释 + 按花括号配平截函数体**，不按"下一个 `fun`"截。
3. **Kotlin 字符串里写 ASCII 双引号** ⇒ `Unresolved reference`。
   门禁断言里描述旧形态时写 `"那是一整块"` 就编译失败，改中文引号「一整块」。
4. **实验 API 三处**都要 `@OptIn(ExperimentalMaterial3ExpressiveApi::class)`：
   `DropdownMenuGroup`、`MenuDefaults.itemShape()`、带 `shape` 参数的 `DropdownMenuItem` 重载。
   漏一处就是编译错，`check_experimental_optin.py` 能提前查出来。
5. **预览稿字号写错**：先按 14px 画，实际 M3 `MenuListItemContainerHeight = 48.dp` 配
   bodyLarge 16sp。预览稿与真机的偏差会直接误导判断（"看起来还行"）。
