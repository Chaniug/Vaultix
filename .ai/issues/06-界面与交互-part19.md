## 281. 底栏材质分档：常态磨砂 + 液态玻璃质感回提（2026-11-11 中午，用户反馈）

### 用户原话

> 不开液态玻璃的话，平常状态下的底栏，能做一下通透磨砂，能隐约看到下方内容的效果吗。
> 液态玻璃的底栏效果目前还不达标，质感和通透感还很薄，整体效果不强

两件事：① **明确诉求** —— 关开关时的平常态也要通透磨砂；② **对 #280 的验收结论** ——
玻璃仍「薄、整体效果不强」。⚠️ 第二句是评价不是工单，但连续两轮（#280 之后立刻）
给同一结论，说明不能再用「再调调参数 / 再补一层光」应付。

### 复核：为什么「薄」不是「不够透」

`LiquidGlass.kt` 的 KDoc 完整留着一段**调淡史**，正好解释这次反馈：

| 时间 | 动作 | 当时用户要什么 |
|---|---|---|
| 11-09 精装修 | 模糊 24 → 16dp（现值 18）、填充 0.40 → 0.38 / 0.52、阴影 8 → 6dp | 「淡淡看到下方密码条目」 |
| 11-10 第四轮 | 0.55 → 0.32 → 0.42 上沿高光回提、补饱和度 1.38 | 「玻璃效果看不出来」 |
| #280 第六轮 | 修光晕量纲、把流光搬回绘制层、SDF 折射 / 透镜 | 「通透 / 点击流光 / 折射没完善」 |

一路往「更透、更淡」调，结果玻璃**几乎没有「自己」**：0.38 的填充盖在 18dp 模糊上，
背后条目形状还读得出来、和图标抢视觉，边界又只有一条 0.52 的亮线 ⇒ 既不像玻璃也不像板。

> **判据**：玻璃感来自「透出的内容」与「玻璃自身」的**对比**，不是越透越好。
> 正确做法不是继续加透明度，而是**加大模糊**（让透出的是柔和色块而非可辨文字），
> 给填充腾出回提余量，再补**边界暗部 / 厚度 / 浮起感**。

架构前提（决定了诉求能不能低成本实现）：`AdaptiveMainScaffold` 的底栏是**叠层悬浮**，
内容一直铺到屏幕底，所以「隐约看到下方内容」天然成立，只需让胶囊背景半透明 + 真模糊，
**不用动任何布局 / 列表 `contentPadding`**。

### 五个真问题

| # | 问题 | 说明 |
|---|---|---|
| 1 | 常态是**实色** | `VaultixBottomDock` 的 `else` 分支用 `Surface(color = surfaceContainerHigh)` 全不透明，底下铺了内容也一点看不见 |
| 2 | 源层被开关挡住 | `MainShellScreen.glassSourceActive = liquidGlassDock && isLiquidGlassBlurSupported()`：关开关时 `contentLayer` 不登记 ⇒ 就算给常态加半透明 + 模糊，糊到的也是**空背景**，真机表现为「底栏变灰了一块」 |
| 3 | 「有没有模糊」和「哪种材质」被混成一个布尔 | 开关一关就整条链路停用，无法表达「也要模糊，只是不要折射 / 流光」 |
| 4 | AGSL 是液态玻璃专属，却没有档位概念 | 常态若复用 `glassRenderEffect` 会每帧编译 / 更新 shader uniform，而常态本该安静且零额外开销 |
| 5 | 质感缺的是**暗部与厚度** | 之前只有「上沿高光 + 一圈内描边」，边缘无内阴影 ⇒ 玻璃像贴上去的一层雾，不浮起 |

### 施工

1. **材质分档**：新增 `enum class DockMaterial { Frosted, Liquid }` + `dockMaterialOf(Boolean)`。
   开关语义从「有没有模糊」改为「哪种材质」，两档**共用同一个 `LiquidGlassLayer`**、
   同一条源→效果层链路、同一份坐标偏移 —— 不在 `ui/shell` 另起一套采样
   （#120 / #193 / #195 已因「同一规则写两处」栽过三次）。
2. **常态磨砂**：填充 `0.74 / 0.80`（Haze regular）、模糊 `30dp`、饱和度 1.38，
   **不挂 AGSL**：`LiquidGlassOptics.frostedRenderEffect()` 只做「模糊 + 饱和度」；
   `liquidGlassBackdrop(opticsEnabled = false)` 连按压 uniform 都不算。
   绘制层只画填充 / 更淡的上沿高光 / 更弱的内阴影 / 一条极弱受光 rim / 内描边，
   **不画**中心提亮、表面流光、焦点高光 ⇒ 「平常状态」保持安静、零按压期重组。
3. **液态玻璃质感回提**：模糊 `18 → 24dp`、填充 `0.38/0.52 → 0.50/0.62`、
   镜面 rim `0.52/1.6dp → 0.62/2dp`、下沿暗线 `0.10 → 0.18`、上沿高光 `0.42 → 0.48`、
   阴影 `6 → 8dp`；新增 `drawInsetShadow` 沿 `Outline` 描一圈「上淡下暗」的渐变
   （层 B 的 `.clip(shape)` 会裁掉描边外侧那一半 ⇒ 正好是内阴影，圆角不断）。
   `drawGlass` 液态玻璃档八层、磨砂档五层，`drawOpticalBody` / `drawSurfaceSweep`
   仍只在液态玻璃档调用（31+ 全档可见的判据不变）。
4. **源层接线**：`glassSourceActive = isLiquidGlassBlurSupported()` —— 门槛只剩系统能力，
   **不再乘 `liquidGlassDock`**。静止时 Compose 不重绘 ⇒ 无离屏拷贝；滚动时每帧一次，
   这是「默认态也磨砂」的性能代价，已写进 `next-steps.md` 待真机帧率验收。
5. **降级不被破坏**：`VaultixBottomDock` 三路分支 —— API < 31 仍走原 `Surface` 实色
   （半透明 + 无模糊 = 列表文字穿栏，不可用）；31+ 两态走 `LiquidGlassLayer`。
   设置页副标题同步为「已关闭：底栏为通透磨砂，隐约透出下方内容」。

### 硬边界（沿用 #277 / #279 / #280）

- 两档材质**都不碰** `size / height / width / padding`，胶囊边界与大小恒定；
- 全部几何沿 `Shape.createOutline(...)` + `drawOutline` 画，不写 `drawRect`；
- 三路分支**共用** `DockRow` 与 `VaultixCorner.Pill`（规则 2 钉住 ≥3 处调用，
  刻意不抽公共 lambda，避免以后改一处漏两处）；
- `State<GlassPress>` + `derivedStateOf` 仍只在绘制阶段读 `.value`；
- `liquidGlassStyle` / `LiquidGlassLayer` 的新参数都给默认值，老调用点与预览一行不改。

### 验证与坑

- 编译探针 `:app:compileFullDebugKotlin` 一次过（42s），
  `detekt` + `:app:testFullDebugUnitTest --tests '*LiquidGlass*'`：**38 条全绿**
  （原 31 = 规则 9 + 数值 18 + 源坐标 4；新增 6 条数值规格 + 规则 10）。
- **参数上限**：`glassRenderEffect` 已有 9 个实参（detekt `LongParameterList ≤ 8`），
  再加 `opticsEnabled` 就会撞门禁 ⇒ 改成**两个入口**（`frostedRenderEffect` / 液态玻璃专用），
  顺带把「磨砂永不走 AGSL」变成编译期事实，不靠运行期布尔分支。
- **文本门禁**：规则 1 的 offenders 纳入 `drawInsetShadow`；新增规则 10 同时钉住
  「源层不再乘开关」「磨砂有独立效果入口」「降级 `Surface` 分支还在」——
  这三条都是编译过、detekt 查不到、真机才看得出来的静默错误。
- 交互预览 `/workspace/vaultix-dock-material-preview.html`：四态并排（旧实色 / 新磨砂 /
  #280 液态玻璃 / #281 液态玻璃）、共享同一份滚动列表、深浅色切换、按住拖动看流光；
  **四个滑杆直接对应代码里已参数化的量**（模糊 / 填充 / 内阴影 / rim）。
  用户连续两轮说「不达标」却无法给出具体档位 ⇒ 这轮把可调维度暴露出来，
  下一轮按数值固化，不再靠猜。316 行，花括号 87/87、div 55/55、JS `node --check` 通过。
- **未验证**：真机 `backdrop-filter` 等效观感、磨砂在浅色下是否偏灰、
