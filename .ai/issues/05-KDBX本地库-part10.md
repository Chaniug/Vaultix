## 260. 新建本地 KDBX 库 100% 失败：`CreateDocument` 先建空文件，`failIfExists` 把"存在"当冲突（2026-11-10，真机截图）

- **现象**：设置 → 新建本地 KDBX → 填库名与主密码 → 「创建并选择保存位置」→ 系统面板确认文件名 →
  界面报**「出错了：该位置已存在同名文件，已取消创建以免覆盖」**。用户重复几次都一样。
  再回头打开刚才那个位置的文件，又报**「该文件不是 KDBX 数据库」**。
- **根因（两句话，两个 bug）**：
  1. `ActivityResultContracts.CreateDocument` 在**返回 URI 之前就已经把文件建好了**
     （0 字节占位）。而 `Kdbx.createVault` 用 `failIfExists = true` 写入，
     `SafKdbxFileSource.write` 的判据是 `existing != null` ⇒ **自己刚建的占位被当成"别人的库"**。
     新建路径因此**恒失败**，且只在本地复现（网盘 `PUT` 到不存在的路径不会先建空文件）。
  2. 那个 0 字节文件随后被 `inspectKdbxFormat` 归到 `NotKdbx`（因为 `size < 12`），
     于是打开它得到的是"不是 KDBX 数据库"—— 一句**没有下一步**的结论。
- **解法**：
  - 判据从「文件存在」改成「**文件有内容**」，抽成纯函数 `blocksCreate(existing)`（`SafCreatePolicy.kt`，
    与 `SafCachePolicy` 同一手法：本模块单测不跑 Android 运行时）。三格边界各有测试：
    `null` / 空 / 单字节。
  - 新增 `KdbxFormat.Empty` 与 `KdbxOpenError.EmptyFile`，文案挂在类型上（`guidance`）：
    「这个文件是空的（0 字节）…直接删掉它、重新新建一个即可」。四个消费点
    （`KdbxFailure` message / `formatFailure` / `classifyKdbxError` / 转换路径）各取同一份。
- **为什么敢放过空文件**：`failIfExists` 保护的是**用户已有库的内容**，0 字节没有内容可毁；
  反过来把 0 字节当冲突，会让新建路径永远走不通。若那个空文件是上次失败的残骸，
  覆盖它正是用户想要的（还省掉"先去文件管理器删一次"）。**有内容的同名库仍然一律拒写。**

**★ 判据**：
> **`CreateDocument` 给的是"已经创建好的空文件"，不是"可以创建的位置"。**
> 凡是在它之后接 `failIfExists` 的路径，判据都必须是"有没有字节"而不是"存不存在"。

> ⚠️ 这次的两个 bug 是**一条链**：第一个让新建必失败，第二个把失败留下的残骸
> 报成另一种错误。修完第一个，第二个仍要修 —— 用户设备上已经躺着那种空文件了。
