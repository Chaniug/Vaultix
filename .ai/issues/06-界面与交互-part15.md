## 271. 设置页按「同类放一块」重排：自动填充不在外观里、检查更新藏在版本号下、页尾两个 2 行组（2026-11-10 晚，用户提问）

**用户原话**：

> 设置里面，有哪些设置是零散在各处的。我的想法是，库安全与权限设置之类的放一块，
> 外观一些自定义什么的放一块，关于与开发者设置这些放一块。你认为呢

### 先回答"有哪些是零散的"

把设置页 + 四个二级页 + 两个"就地入口"全量列出来之后，结论是：
**大部分不散，真正错位的只有四处。**

| 设置 | 位置 | 判断 |
|---|---|---|
| 密码库管理 | 首页 · 密码库与安全 | ✅ |
| 锁与安全（指纹 / PIN / 自动锁定 / 自动查看锁） | 首页 → 二级页 | ✅ 全局门锁独立成页 |
| 防截屏 / 剪贴板自动清除 | 首页 · 密码库与安全 | ✅ 隐私承诺的可见证据，刻意留在首页 |
| 权限管理 | 首页 · 密码库与安全 | ✅ 2026-09-28 用户拍板的位置 |
| **自动填充设置** | **首页 · 外观与填充** | 🔴 **错位**：它回答"库怎么用出去"，不是"界面长什么样" |
| 主题 / 取色 / 纯黑 / 玻璃 / 条目显示 | 首页 · 外观与填充 | ✅ 但组名里的"填充"是为上一条打的补丁 |
| 导入与导出 / 回收站清理 | 首页 · 数据 | ✅ |
| **版本（点击 = 检查更新）** | 首页 · 关于 | 🟡 **动作不可发现**：标题只说"版本" |
| 关于 Vaultix / 更新镜像 | 关于二级页 | ✅ |
| **日志 / 保持不锁（debug）** | 首页 · 开发者（独立组） | 🟡 与"关于"两个 2 行组并排，页尾被切碎 |
| 网盘账号 | 密码库管理 → 库的来源 | ✅ 刻意两层：长寿命状态（定稿 §11.7） |
| 条目显示选项 | 另在**条目页顶栏**有一个入口 | ✅ 同一份偏好 + 同一个弹层，就地快捷方式 |
| 回收站清理 | 另在**回收站页顶栏**有一个入口 | ✅ 同上，同一个 `TrashAutoDeleteDialog` |

⚠️ 最后两行**不是**"零散"：它们和设置页那一行读的是同一个 DataStore 键、
弹的是同一个组件。**两个入口 ≠ 两套实装** —— 这是"在哪儿用就在哪儿能改"，
删掉任何一个都会多两次跳转。

### 改了什么

| # | 改动 | 理由 |
|---|---|---|
| 1 | 「自动填充」移入「密码库与安全」，位置在剪贴板之后、权限管理之前 | 与前一条同属"数据离开 App 的方式"（复制 / 填写） |
| 2 | 组名「外观与填充」→「**外观与自定义**」 | 自动填充搬走后，组名不必再兼职 |
| 3 | 开发者两行并入「关于」卡，删除 `group_developer` | debug 合并后 4 行、release 仍是 2 行（`BuildConfig.DEBUG` 编译期常量，R8 直接裁掉） |
| 4 | 「版本」→「**版本与更新**」 | 点击就是检查更新，标题必须把动作说出来 |

**新结构**（仍是 4 组）：

| 组 | 行 |
|---|---|
| 密码库与安全 | 密码库管理 · 锁与安全 · 防截屏 · 剪贴板自动清除 · **自动填充** · 权限管理 |
| 外观与自定义 | 主题模式 · 动态取色 · 纯黑背景 · 液态玻璃底栏 · 条目显示选项 |
| 数据 | 导入与导出 · 回收站清理 |
| 关于 | 版本与更新 · 关于 Vaultix ·（debug）日志 · 保持不锁 |

### 为什么**没有**并成用户说的"三块"

用户提的是三块：库安全与权限 / 外观与自定义 / 关于与开发者。实际落地是四块 ——
多出来的「数据」不是漏合并，而是**并进哪一块都会制造新的错位**：

- 导入导出是**动作**，不是安全策略；
- 回收站清理是**数据生命周期**，不是外观；
- 塞进「关于」更糟：用户找它时不会想到"关于这个 App"。

### 为什么防截屏 / 剪贴板**不**下沉进「锁与安全」

它们确实是安全设置，但：

1. 放在首页是**隐私承诺的可见证据**（用户一眼看到"这个 App 会挡截屏"）；
2. 「锁与安全」页已有四行（指纹 / PIN / 自动锁定 / 自动查看锁），再加两行会变成第二张首页；
3. 这两个开关是"设一次就不动"的，藏一层不会增加日常成本，但也**没有收益**。

⇒ 这条是**知情的不动**，不是遗漏。若以后"锁与安全"页再长，可以重新讨论。

### 验收（真机）

- [ ] 设置首页：自动填充在「密码库与安全」组里，且「外观与自定义」组里**没有**它
- [ ] 「关于」组在 debug 包是 4 行一张卡（版本与更新 / 关于 Vaultix / 日志 / 保持不锁）
- [ ] release 包「关于」只有 2 行，且没有"开发者"标题
- [ ] 点「版本与更新」→ 直接进检查更新对话框

## 273. 对话框的「取消 / 关闭」被逐字摞成竖排 + 权限页「通知」二字竖排（2026-11-10，用户报告）

**用户原话**：

> 设置里面功能按钮，开关，弹窗，提示之类的，风格都遵循了 material3 最新的设计规范了吗？
> 权限管理里面的，通知二字是竖着的，其他的字都是正常的。另外，锁与安全里面的内容是否
> 遵守规范了，都排查一下。有问题就修复

### 症状一：对话框的「取消 / 关闭」两个字上下摞着

**不是字号，也不是字重，是宽度被算错了。**

M3 的 `AlertDialog` 给四个槽位（title / text / confirmButton / dismissButton）都传了
`indentChar = DialogIndentChar`（"horizontal"）。Compose 解析默认参数时，**实参值不属于
默认值表达式** —— 默认值就是标识符 `indentChar`，它按"默认参数"规则解析为**形参名**。
所以这些槽位的 `LocalIndent` 是 "horizontal"。

这个缩进有两个消费者：

1. `Text` 的 `LineBreak.Paragraph` —— 换行依据（中文按字，**不保证两个字不拆开**）；
2. `Modifier.width(IntrinsicSize.Max)` 的测得宽度 —— 只算"最长的一行"。

而我们的「取消」是**直接放进槽位的裸 `OutlinedButton`**：按钮是 `Row`，`Row` **不实现**
`IntrinsicMeasurable` ⇒ 被问固有宽度时退化成 0 ⇒ 由 `widthIn(min = ButtonDefaults.MinWidth)`
兜成 **58dp**。两个汉字约 24dp，塞进 58dp 再减掉左右内边距，要么右侧一条空白，
要么**平均分到 29dp 一格、一个字一行**。真机上是后者。

⇒ 修法只有一条：给按钮显式 `Modifier.width(IntrinsicSize.Min)`，让 intrinsic 查询的目标
变成**按钮自己**（`Row` 会去问子节点），拿到的才是"文字实际宽度 + 内边距"。
在调用点调小 `minWidth` 没用 —— 格子还在，只是窄了一点。

新增 `DialogTextButton` / `DialogOutlinedActionButton`（`ui/common/DialogActionButtons.kt`），
全仓 19 处对话框动作按钮统一改走这两个封装。

### 症状二：权限页「通知」两个字竖排

`TrailingSlot` 写死 `widthIn(min = 112.dp)`，本意是让四行行尾落在同一条右边线上。
但**行尾是硬约束、标题是软约束**：一行放不下时 Compose 先压缩 `weight(1f)` 的标题列，
而不是撑宽卡片。

| 行 | 标题 | 行尾 | 留给标题的宽度 |
|---|---|---|---|
| 相机 | 相机（2 字） | 已允许 | 约 185dp，够 |
| **通知** | **通知（2 字）** | **去设置** | **被挤到 1 字/行** |
| 指纹 / 设备密码 | 8 字 | 设备不支持 | 已折成 2 行，看不出是"被挤的" |

一个 2 字标题被占掉整行宽度三分之一，换来的只是"右边线齐"这件灰度上看不出来的事。
**为了对齐牺牲可读性，是本末倒置。**

⇒ 行尾改 `wrapContentWidth(Alignment.End)`（右边线靠 `contentAlignment` 仍然齐）；
标题补 `widthIn(min = 88dp)` 兜底（窄屏 + 2.0x 字号时宁可让行尾换行）；
副标题补 `maxLines = 2` + 省略号（与 `SettingsRow` 同口径）；
去掉 `TrailingAction` 的 `fillMaxWidth()`（旧版点标题那一侧也会触发「去设置」）。

### 顺带修的两处

| 处 | 问题 | 处理 |
|---|---|---|
| 六个二级页 | 首元素**贴顶栏下沿**（`Scaffold` 已消费 inset，卡片/裸 Text 自身无外边距）⇒ 与自动填充、权限管理两页的 8dp 对不齐 | 各补 `Spacer(Spacing.sm)`，与那两页对齐 |
| 开发者日志对话框 | 三个按钮套了一层 `Row(Arrangement.spacedBy)`，而 M3 的 `AlertDialogFlowRow` 自带 8dp 间距 ⇒ 这一组按钮间距与别处不一致 | 去掉外层 Row |

### 「锁与安全」页的排查结论

**没发现新问题。** 该页全部由 `SettingsRow` 组成 —— 图标列 28dp 顶对齐、标题 `bodyLarge` Medium、
副标题 `bodyMedium` 两行省略、开关走 `SwitchWithTouchTarget`（52×48dp 命中框，M3 要求 ≥48dp）。
自动锁定对话框也已经是 `DialogOutlinedActionButton`（见上）。唯一的改动是从别的页面捎带的：
补了 8dp 顶部留白。

### 新增静态门禁：`SettingsStyleRulesTest`（6 条）

这几类问题**肉眼难查、detekt 查不出、CI 无 SDK 时 Android Studio 的检查跑不到**，
只能钉成断言（直接扫源文件文本）：

1. 对话框动作槽里不许直接写裸 `Button` / `TextButton` / `OutlinedButton`（症状一）；
2. 权限页行尾不许固定最小宽度、副标题必须限行、标题必须有 weight（症状二）；
3. 设置页不许出现硬编码中文（`stringResource` 只在调用时读资源，字面量一样编译通过，
   但进不了翻译流程）；
4. `R.string.xxx` 必须真的存在 —— **引用不存在的资源不会崩**，`getString` 只会返回
   `"ResString(id=0x…)"`，界面上就是一段怪字样。
