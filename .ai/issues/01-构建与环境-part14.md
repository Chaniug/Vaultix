### 291.2 根因：`分支 ≠ buildType`，R8 裁不掉裸 `Log`

`VaultixLog` 默认 `enabled=false`，关闭时**连消息 lambda 都不求值**（零开销），还有
每 tag 50 条 / 60s 限频与「sink 抛异常不拖垮调用方」。但：

- R8 只裁 `if (BuildConfig.DEBUG) { … }` **整块**；源码里一句裸 `Log.d(TAG, msg)` 不在块内，照输出。
- `BuildConfig.DEBUG` 由 **buildType** 决定（编译期常量），不由分支决定 ⇒
  「main 与 rele 源码一致」**不等于**「产物行为一致」。这是 11-11 报告把日志问题
  从 P0 降 P1 时订正的判据（不崩溃、不丢数据，但属日志红线 / 信息泄露）。
- 实测最刺眼的一处：`UnlockViewModel` 把 `reseal $vaultId` 原样写进 logcat ——
  `vaultId` 是规范化服务器 URL 或 `onedrive:…:Keepass/xxx.kdbx`，等于把完整库标识外泄。

### 291.3 S2 修法：8 处收敛到唯一出口

| 文件 | 改动 |
|---|---|
| `QuickUnlockController.kt:867` | `Log.d(TAG, "…${it.message}")` → `VaultixLog.w(TAG, it) { "清除待重装标记失败" }` |
| `UnlockViewModel.kt:926` | 其余库补开失败 → `VaultixLog.w(TAG, it) { … }` |
| `UnlockViewModel.kt:958/960/962` | 3 处 `reseal $vaultId` → `VaultixLog.d/w(TAG) { "reseal ${redact(vaultId)} …" }` |
| `SettingsComponents.kt:470` | 开关热区告警 `Log.w` → `VaultixLog.w(TAG) { … }` |
| `AutofillLogger.kt` | 去掉自建 `BuildConfig.DEBUG` 门禁，两个 `d()` 改走 `VaultixLog.d(...)` |

**三个刻意取舍**：

1. **异常消息交给 `throwable` 参数**，不再拼进字符串 —— 门面能把异常链交给 sink，
   也避免 `${it.message}` 里可能夹带的内容被当普通文案记下。
2. **`vaultId` 用 `redact()` 脱敏** —— `VaultixLog` KDoc 只允许「host（建议经 redact 脱敏）」，
   原来写的是完整值。门面关闭时 lambda 不求值，脱敏本身零开销。
3. **`AutofillLogger` 的 63 个调用点一行未改** —— 签名仍是 `(message: String)` /
   `(tag, message)`。代价是调用点已拼好 String，拿不到「关闭时零拼接」的收益；
   这是保持 63 处不动的刻意取舍，已写进该文件 KDoc，新增日志请直接用 `VaultixLog.d { }`。

收敛后全仓生产代码**只剩 `VaultixApplication.kt` 一处**直接用 `android.util.Log`
（门面 sink 实现），门禁白名单因此可以精确到单个文件。

### 291.4 S3 修法：3 处 `!!` 全部改「局部快照」而非 `requireNotNull`

三处的共同点是**目标都是可变属性**，Kotlin 无法 smart cast，所以当初写了 `!!`；
而判空与断言之间隔着挂起点，UI 回调完全可能改值 —— `!!` 不是「逻辑上不可能为空」，
是「赌它没被改」。

| 文件 | 原来 | 改法 |
|---|---|---|
| `PasskeyCreateActivity.kt:513` | `selectedLoginId!!` | `val targetLoginId = if (createNewLogin) null else selectedLoginId`，空值自然落到「新建」分支 |
| `PasskeyGetActivity.kt:495` | `clientDataHash!!` | `val externalClientDataHash = clientDataHash`，非空分支由智能转换保证，同时钉住本次签名用的那份哈希 |
| `KdbxSyncOrchestrator.kt:198` | `fileSourceFactory(origin)!!` | 抽 `resolveSyncSource()` + 私有 `sealed interface SyncSourceResolution`：工厂**只调一次**、来源实例随 `Remote(source)` 带出，`Halt(outcome)` 收口本地库 / 无来源，`sync` 里零空值断言（见 §291.10） |

第三处顺带修掉一个隐性 TOCTOU：原来 gate 判一次、放行后再调一次工厂，
两次之间若来源被替换 / 解析失败就是同步编排主路径上的 NPE。空值兜底直接复用
`LocalOnlyGate.NO_SOURCE.outcome`，不新造第二句文案，行为等价。

> ⚠️ 没用 `requireNotNull` / `checkNotNull`：那只是把 NPE 换成 `IllegalArgumentException`，
> 对真机用户仍是「点一下就崩」。要的是**空值有去向**。

### 291.6 踩到的坑：同一判据存两份，且 trailing lambda 改了语句形状

改完第一次跑全套门禁，`check_ui_hardcoded_text.py` **红了 2 处**：
`SettingsComponents.kt` 的中文日志文案被判成「未登记的 UI 硬编码」。

根因不是文案变了，是**语句形状变了**：

- 旧写法 `Log.w(\n TAG,\n "中文" + "中文",\n)` 圆括号一直未闭合，
  `_merge_call_lines()` 把中文行并进含 `Log.` 的同一条逻辑行 ⇒ 按日志放行。
- 新写法 `VaultixLog.w(TAG) { "中文" + "中文" }` 的**圆括号已平衡**，合并提前收尾，
  两行中文各自成为独立逻辑行、不含任何 `_ALLOW_HINTS` ⇒ 误报。

⚠️ **不能**简单把花括号算进 `_paren_delta`：那会把 `Column { Text("中文") }` 整块合成一条
逻辑行，块里只要出现过一句 `Log.d` 就顺手放行所有真 UI 文案 —— 门禁会被自己蛀空。

修法：新增 `_log_lambda_mask()`，**只**追踪「起始行命中日志 hint 且花括号未闭合」的
lambda 上下文；普通 Composable 块完全不受影响。`selftest` 从 7 条扩到 **9 条**，
新增两条钉死「日志 lambda 体内放行、块外仍抓」与「普通 Column 块不得被放行」。

> 同一判据确实存了两份：Kotlin 侧 `SettingsStyleRulesTest.nonUiCallSites` 与
> Python 侧 `_ALLOW_HINTS`。本次**两边都补了** `VaultixLog.` 标记。
> 这是项目反复踩的「同一事实存两份」老毛病（#160 同源），下一轮改日志形态时两处都要看。

### 291.10 CI 首轮实测报红：`sync` 圈复杂度 15 > 14

首轮 `Android CI (Debug)` run `43557701747`：`Sandbox unit tests (Kotlin/Java, no SDK)`
success，但 `Lint, test diagnostics, and debug build` **failure**，唯一违规是 detekt：

> `KdbxSyncOrchestrator.kt:157:17` The function sync appears to be too complex
> based on Cyclomatic Complexity (complexity: 15).
> The maximum allowed complexity for methods is set to '14' `[CyclomaticComplexMethod]`

根因不是新逻辑变复杂，是**为消掉 `!!` 加的那句 `?: return` 自带一个分支**：
`sync` 原本就贴着 detekt 上限 14（#290 也在圈复杂度上栽过一次，靠抽
`cloudErrorText()` 压回）。本地 37 项 Python 门禁 + typecheck 8 组全绿都查不出这条 ——
这套门禁管的是**文本形状**，管不到 AST 分支数；`detekt` 只能在 Gradle 里跑。

修法不是 `@Suppress`，是把「解析来源 + 本地闸门」整块抽成 `resolveSyncSource()`
（沿用项目已有的 `private sealed interface` 嵌套写法，见
`FolderRepositoryImpl.Target` / `KdbxUnlockPayload.ChunkResult`）：

- `Remote(source)` 带出**同一个**来源实例，`Halt(outcome)` 收口本地库 / 无来源；
- `sync` 里只剩一个两分支 `when`，`gate != null` / `gate == LOCAL` 两个 `if`
  与那句 `?: return` 一起移走 ⇒ 净减 1 分，回到 14；
- 空值兜底直接复用 `LocalOnlyGate.NO_SOURCE.outcome`，不再新造第二句文案（单一真源）；
  行为与首版完全等价。

本地验证：`./gradlew detekt --no-configuration-cache` **BUILD SUCCESSFUL in 33s**
（2 executed / 8 up-to-date）、`typecheck_kotlin.sh --all data/repository`
**2 组全绿 / 352 例**、37 项门禁复跑全绿。

> ⚠️ **教训**：清零 `!!` 的「空值有去向」不能只加一句 `?: return` 了事 ——
> 在贴着 detekt 上限的函数里，每加一个分支都要重算圈复杂度。
> 抽 helper 比 `@Suppress` 干净，还顺手把「工厂只调一次」的语义钉进类型系统。
