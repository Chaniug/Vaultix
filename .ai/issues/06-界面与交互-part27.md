## 289. 连上 WebDAV 后闪退，重进后网盘账号却已添加

**用户原话**（2026-11-13，真机反馈）：

> 连接上 webdav 后，会闪退出来。重新进入后会发现网盘账号已经添加进去了。

### 现象 → 取证链 → 定性

`账号已添加` 这一句是**决定性的**：它说明凭据已经成功落盘，崩溃点必然在
**成功之后**，不在 `testConnection()` 里。顺着 `probeWebDav()` 往下读：

| 步骤 | 代码 | 出错后果 |
|---|---|---|
| ① 凭据落盘 | `connector.saveWebDavCredential()` → `WebDavCredentialStore.save()` → `SecureCredentialStore.putString()`（Keystore AES-GCM 加密 + SharedPreferences 写） | 已完成 ⇒ 重进账号还在 |
| ② 自检 | `WebDavKdbxFileSource.testConnection()`（PROPFIND 网络往返） | 已通过，否则走的是失败回滚分支 |
| ③ 状态更新 | `_state.update { probe = OK, ... }` + snackbar 资源 id | Compose 重组 / `stringResource` |
| ④ **刷新清单** | `refresh()` → `CloudAccountInventory.list()` | **Room Flow `.first()` + Keystore 解密 + MSAL `listCachedSessions()` + 多账号合并** |

再核死两处历史证据：

- 工程里**没有**全局 `CoroutineExceptionHandler`（`.ai/issues/05-KDBX本地库-part2.md`
  的 #98 实测记录）：`viewModelScope.launch` 里任何未捕获异常都会冒泡成**进程退出**；
- #242 的注释原话：「`launch` 的异常默认抛给 `CoroutineExceptionHandler`，在 ViewModel
  scope 里表现为**静默终止**」，当时只在 `VaultListViewModel` 一处补了兜底。

而 `CloudAccountsViewModel` 与 `AddCloudVaultViewModel` 的所有动作**原先都是裸
`viewModelScope.launch`**。⇒ ④ 这条链路上任何一处抛出（Room 迁移中、Keystore 密钥失效、
MSAL 缓存枚举异常、坏凭据行、资源解析）都会直接杀进程，凭据却已经写进加密存储
—— **与真机现象完全吻合**。

顺带查出第二个问题：`probeWebDav()` 与 `refresh()` 都跑在 `viewModelScope` 默认的
**主线程**上。凭据写入是 Keystore + SharedPreferences 同步 IO、自检是网络往返、
清单读取是 Flow + 解密 + 会话枚举，全都不该压在主线程；Keystore 的 checked exception
还会直接冒泡成进程退出。

**一句话定性**：不是「连接又失败了」，是**成功了但进程死了**。所以不能去猜
「到底是 Room 还是 Keystore 抛的」—— 成功之后的链路有五六处可抛，逐个 try/catch
永远追不完，**要补的是异常边界本身**。

⚠️ **判据反转（对照 #288）**：#288 修的是「连不上」（错误分类 401/403、自检协议
PROPFIND、凭据隔离专用 client），本轮真机反馈把焦点推到**同一条主路径的成功之后**。
上一轮「WebDAV 连接已修好」的完成口径，被下一轮反馈第二次反转。

### 修法（四道防线，全部改生产代码）

1. **两个 ViewModel 的所有动作收口到 `launchGuarded(label, block)`。**
   `CloudAccountsViewModel` 的 `refresh` / `probeWebDav` / `signInOneDrive` /
   `probeOneDriveHealth` / `confirmRemoval`，`AddCloudVaultViewModel` 的
   `refreshConfiguredAccounts` / `pickAccount` / `openDirectory` / `goUp` / `submit`，
   全部改走唯一出口：

   ```kotlin
   private fun launchGuarded(label: String, block: suspend CoroutineScope.() -> Unit): Job =
       viewModelScope.launch {
           runCatching { block() }.onFailure { error ->
               if (error is CancellationException || error is Error) throw error
               val message = error.message?.takeIf { it.isNotBlank() }
                   ?: error.javaClass.simpleName
               VaultixLog.e(TAG, error) { "$label 失败：$message" }
               // 把 busy / loading / PROBING 拉回终态，错误放进可见错误态
           }
       }
   ```

   - **取消与 `Error` 原样重抛**：页面返回不是失败，记 ERROR 或改「失败」都是假的；
   - 其余异常一律转成**看得见的错误态**（`CloudError.Detail(message)` /
     `UnlockUiError.Detail(message)`）+ logcat 可取证，**绝不重抛非取消异常**；
   - 每个文件只保留 `launchGuarded` 定义里**一处**裸 `viewModelScope.launch`
     （由源码门禁钉住，防止后来者再开旁路）。
2. **重 IO 显式下沉 `Dispatchers.IO`，但不在统一入口整体切 dispatcher。**
   设置页 `probeWebDav()` 整块（凭据写入 + 自检 + 回滚 + `refresh()`）与
   `refresh()` 的 `inventory.list()`、添加页 `refreshConfiguredAccounts()` 的
   `cloudAccounts.list()` 都包 `withContext(Dispatchers.IO)`。
   ⚠️ 刻意**不**在 `launchGuarded` 里改 dispatcher：`signInOneDrive()` 走 MSAL，
   必须在主线程调用；统一切 IO 会把登录流程带歪。
3. **`probeWebDav()` 内部两处 `runCatching` 也要区分取消。**
   ① `testConnection()` 的包装里，取消 / `Error` 原样重抛，其余才转成「自检失败」
   并回滚凭据 —— 否则页面返回导致的取消会被吞成失败，**误删刚写好的凭据**；
   ② 回滚 `removeWebDavCredential(credentialId)` 本身也用 `runCatching` 包住并只记
   warning，不让 Keystore 故障盖掉原始失败原因。
4. **添加页同步收口。** `pickAccount` / `openDirectory` / `goUp` / `submit` 全部改
   `launchGuarded(...)`，残留的 `return@launch` 改为 `return@launchGuarded`。
   这条链路是「选账号 → PROPFIND 解析 → 选文件 → KDF 解锁 → Room 写入」，
   用户刚在设置页配好账号紧接着就要走，同样不该让任一环抛出就闪退。

### 6 条坑

1. **工程没有全局 `CoroutineExceptionHandler` 时，裸 `viewModelScope.launch`
   的未捕获异常 = 进程退出。** 「账号已保存」只证明**写盘成功**，不证明
   写盘之后的链路安全 —— 排查要往后读一整段，别停在成功分支。
2. **detekt `TooGenericExceptionCaught` 会拦宽泛 `catch (Exception)`**，而异常边界
   的职责本来就该宽 ⇒ 用 `runCatching { block() }.onFailure { ... }`（与 #242 同款），
   在 `onFailure` 里再分流取消 / `Error` / 其余。
3. **设置页源码门禁 `SettingsStyleRulesTest` 禁止 UI 硬编码中文**，判据是
   `stripComments()` 之后**所有字符串字面量**。`launchGuarded("读取网盘账号清单")`
   这类中文 label 一样会被判成界面文案 —— 本轮全量验证第二次就是被它拦下。
   ⇒ 日志 label 一律用 ASCII 标识（`refreshAccounts` / `probeWebDav` / …）；
   日志正文里的中文只有带 `TAG` / `Log.*` 标记才会被 `nonUiCallSites` 放行。
4. **取消不是失败，而且 `runCatching` 会把 `CancellationException` 也吞掉。**
   必须 `if (error is CancellationException || error is Error) throw error`；
   否则取消态下每个挂起点立刻再抛，回滚链跑不完，还会把凭据误删。
5. **统一入口不要顺手改 dispatcher**：MSAL 登录必须主线程，`signInOneDrive()`
   与 WebDAV 凭据写入共用同一个 `launchGuarded`。重 IO 由各调用点自己
   `withContext(Dispatchers.IO)`，边界层只负责「别杀进程」。
6. **沙箱恢复后 `ANDROID_HOME` / `local.properties` 会丢**，Gradle 报
   `SDK location not found`（`EvalIssueException`，一整片堆栈但**不是代码问题**）。
   `local.properties` 已被 `.gitignore:30` 忽略，补 `sdk.dir=/opt/android-sdk`
   即可，不要误判成构建失败。
