## 278. 密码条目「按站点 / 应用」分组（2026-11-10 深夜，用户两轮咨询后拍板）

**用户原话**：

> 关于密码条目整理的这个功能:你认为该如何做呢，不要增加额外开销，不破坏数据本身传达效果，
> 只做整理归纳的效果，现有的UI结构不要进行破坏的。只在密码条目区域做改动即可吧。

### 背景

用户上一轮问「Monica 那种把同域名 / 同软件的条目归组，Vaultix 能不能做」。核查结论：

- Monica 实际是开源 PRM（个人关系管理），不是密码管理器，其分组是手工标签，交互预期不能照搬；
- Bitwarden / 1Password 主流做法是**独立条目 + 自动填充时给候选**，不在列表里强制按域名分组；
- 浏览器按注册域合并子域账号，是子域多账号用户抱怨最多的设计。

### 定案：做成第 5 种分组方式，默认不开启

- `ItemsGroupMode` 新增 `Site("site")`，`storageKey` 落偏好，向后兼容（旧值照常解析）；
- `DisplayOptionsSheet` 的 `entries.forEach` 自动渲染新选项（icon `Language`，文案「按站点」）；
- **分组键**：主 URI 归一化 —— 第一条 `androidapp://` 优先，否则第一条网站 URI 取
  `PublicSuffixList.baseDomain(host)`（eTLD+1）。一条条目只归一组（列表 `key = it.id`
  不允许重复出现）；
- **≥2 条才成组**：站点分散的库按 host 一组一组切，组头比条目还多，反而更乱
  （8.4「实体数量 ≤ 属性数量时分组收益最明显」的镜像判据）；
- 单条站点 + 无 URI 条目合入尾部「未分组」组（`__ungrouped__`），组内保持原排序；
- 应用组标题走 `AppLabel`（customFields 别名优先 → PackageManager）翻中文，翻不出兜底包名；
  需要 `Context`，所以标题翻译由调用方注入 lambda（`siteLabel: (String, Boolean) -> String`）。

### 数据与 UI 零改动

纯展示层归纳：不改 `VaultItem`、不改同步、不改自动填充匹配；`ItemsScreen` 只在
`rememberGroupedItems` 里多传两个参数，列表结构、`GroupHeader`、折叠语义全部复用。

### 三个坑

1. **无 URI 条目曾被整组丢掉**：`siteKeyOf` 返回 `null` 时直接 `return@forEach`，
   条目从列表里消失（不报错、只是不见了）。修法：收集进 `noSite` 再并回「未分组」。
   这是本轮最危险的一笔——静态门禁查不出「列表少了几条」，靠单测钉住。
2. **`ftp://weird` 这类无 scheme URI 也能被 `UriFormat.classify` 解析出 host**：
   它不是「无站点」，是单条站点。测试预期从 `[1,4,5]` 改 `[1,5,4]` 时确认了这一点。
3. **`github.io` 在 PSL 里**：`a.github.io` 与 `b.github.io` 基域独立，不会误并；
   但 `a.github.com` 与 `b.github.com` 共享 `github.com`，会归一组。这是刻意对齐
   Bitwarden 的 PSL 口径，测试两条都钉了。

### 验证

新增 `ItemsGroupingSiteTest` 7 条：同基域成组、PSL 不合组、应用按包名归组、
一条只归一组（应用优先）、未分组排尾、全不成组、storageKey 兼容。
`app` 模块测试全绿。

## 279. 液态玻璃第五轮：跟随手指的触摸光晕（2026-11-10 深夜，用户附 FlClash 截图）

**用户原话**：

> 你可以看一下fclash项目…它这个项目里面的液态玻璃就做的很好，点按效果，在底栏触摸的时候，
> 还有光照反射的效果之类的。你参考一下，能不能在我目前的液态玻璃底栏上继续精修完善呢

### FlClash 源码调研结论

FlClash 的玻璃来自它的子模块 `prism_ui`（`plugins/prism_ui` → git@github.com:chen08209/prism_ui.git），
核心是 `shaders/liquid_glass.frag`（574 行 GLSL）+ `lib/navigation_dock.dart`（悬浮导航条）。
与本项目相关的四个机制：

1. **触摸光晕**（本轮搬的）：`uGlow(center, strength, reach)` 径向高斯，光心在**手指位置**
   而不是槽中心（注释原话 "UIKit lights the bar from the finger"）；
   strength = peak × press²，亮 120ms / 灭 360ms 非对称。
2. 透镜位移带：折射沿法线在 rim 附近一条带内最强（`smoothstep(0,bevel,inset) ×
   (1-smoothstep(bevel,halfMinor,inset))`）—— 上一轮的 `uDepth × band` 已是同款。
3. 色散沿法线镜像方向分开红蓝 —— 上一轮 `uPart` 已有。
4. shader 内 Vogel-disc frost —— 本项目的模糊由 `RenderEffect.createBlurEffect` 承担，等价。

结论：**只需补第 1 件**，其余两条链路已有对应物。

### 实现（全部只进绘制参数）

- `GlassPress` 新增 `focusY`；`focusX/focusY` 语义从「槽中心」升级为**手指的精确位置**；
- `LiquidGlassOptics` shader 新增 `uniform float4 uGlow`（光心 xy + 强度 + 高斯半径），
  光晕以 screen（往白里滤）叠加在 rim 高光之后，避免把暗线洗白；
- `liquidGlassBackdrop` 把 `focusX/focusY` 折算成 effectLayer 坐标系里的光心；
  强度 `TOUCH_GLOW_PEAK(0.32) × intensity²`，半径 `height × 0.9`；
- `VaultixBottomDock.DockRow` 行级 `pointerInput` 观察手势上报精确位置：
  `awaitFirstDown(requireUnconsumed = false)` → 上报分数坐标；**不消费任何事件**，
  clickable 的点击 / 长按 / 无障碍语义原样保留；松手（手动等到全部指针抬起——
  本项目 Compose 版本的 `waitForUpOrCancellation` 没有 `requireUnconsumed` 参数）后回正中；
- 原先 `DockTabItem` / `AddButton` 经 `PressInteraction` 上报槽中心的管线整体移除
  （interaction 流只剩图标 one-shot 弹跳）。

### 两个坑

1. **`waitForUpOrCancellation(requireUnconsumed = false)` 编译不过**：该函数在本项目
   锁定的 Compose 版本里没有这个参数。改用手动循环
   `while (true) { val event = awaitPointerEvent(); if (event.changes.all { !it.pressed }) break }`。
2. `dockSlotFocus` 不再被生产代码的 DockRow 调用（只剩 `dockIdleFocus` 与单测引用），
   `DOCK_RIGHT_FIRST_SLOT` 常量已删 —— 留着会让下一位接力以为槽位上报还在用。

### 边界不变

光晕是纯 shader uniform + 径向渐变中心：底栏边界、大小、测量全程不变。
`LiquidGlassDockRulesTest` 新增第 7 条规则「触摸光晕只进 uniform 不许参与测量」，
并断言 `uGlow` uniform、`focusX/focusY` 折算、`TOUCH_GLOW_PEAK` 常量三处接线齐全。
`LiquidGlassTest` 新增「触摸光晕规格合法且默认位置居中」。

### 验证

- `app` 模块 glass / items 全部测试绿；CI 口径 `detekt` 全绿（`detektFullDebug` 的
  UseCheckOrError 等 146 条是历史存量，不在 CI 门禁内）；
- 15 个静态门禁 `PASS=15 FAIL=0`。
