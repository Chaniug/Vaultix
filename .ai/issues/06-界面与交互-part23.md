## 285. 六组 UI / 主题 / KDBX 反馈（2026-11-12，用户反馈 + 4 张真机截图）

### 用户原话

> 1. 网盘账号卡片：网盘卡片大小、颜色、UI 要更精美好看，与页面和谐一致。
> 2. 域名分组：按域名分组时，分组头与组内条目不够紧密，不像一个整体；一条一条的域名分组条让页面有割裂感，给优化思路并实施。
> 3. 详情页：条目名稍长时，查看条目页左上角标题显示效果差，不美观不整洁。
> 4. 「+」新建剪影卡：按安卓最新设计规范重新配色，不要奇怪颜色，浅色 / 深色都兼顾，同时每张卡有视觉记忆点。
> 5. 主题模式 / 动态取色：默认浅色配色不够标准，动态取色疑似有 bug，要求修复。
> 6. KDBX 条目页左上角标题统一显示 `KDBX`，不要显示 `xxx.kdbx`，视觉传达更好。

六组**全部改了生产代码**。四张截图分别对应网盘账号页、域名分组列表、详情页长标题、
`valk.kdbx` 顶栏与分组头局部 —— 都是 CI 无真机、detekt 查不出、编译过也单测过，
只有真机才看得出来的观感 / 语义缺陷 ⇒ 沿用「源码文本门禁」口径把写法钉住。

### 第 1 项：网盘账号卡片精修（`CloudAccountsScreen.kt`）

真机截图三个硬伤：

1. **卡片过高**：套的是设置页「**一组多行**」的 `SettingsGroupCard` + `SettingsRow`
   （72dp 行 + 20dp 行内距 + 一整行按钮）⇒ 一个账号占掉一大块又高又空的深灰板；
2. **「已连接」飘在卡片外**单独一行，落在卡片与「添加账号」之间，读起来像第三段正文；
3. **两枚按钮规格不同**：主操作是 48dp 满宽 `PrimaryActionButton`（FilledTonal 胶囊），
   「注销」却是 40dp `OutlinedButton`，中间还被 `Spacer(weight(1f))` 推到屏幕两端
   ⇒ 一个大一个小、一重一轻。

改法（「与页面和谐一致」= **沿用设置页表面语言，不另起色相**）：

- 专用紧凑卡：外壳仍是 `surfaceContainerLow` + `VaultixCorner.Panel`，内部自己排版
  （`Spacing.md` 内距，不再借用 72dp 行规格）；
- 表头 = 来源图标（`UiSize.SecondaryIcon` 直出，与 `SettingsRow` 一样不套圆形底衬）
  + 账号名（`titleSmall` + `maxLines = 1` / `TextOverflow.Ellipsis`）+ 稳定事实副标题
  + 行尾**连接状态徽标**；
- 断开原因（`issue`）收进卡内、贴着表头，不再是一闪而过的 snackbar；
- 动作区两枚**同规格** M3 按钮：`FilledTonalButton` 主操作占 `weight(1f)`，
  `OutlinedButton` 破坏性动作收右端（统一 `ButtonDefaults.outlinedButtonColors` 的
  error 内容色，连边框一起，不是只给 `Text` 上色）。主次靠填充区分，不靠尺寸；
- 主操作 `busy` 时显 `CircularProgressIndicator`（MSAL 拉系统授权页好几秒，
  灰按钮和正在跑的按钮长得一样会被反复点）；
- 「添加账号」与表单「取消」两个全宽按钮改用 `VaultixCorner.Panel`，与卡片同款圆角。

状态**会变**（token 过期 / 凭据被清 / 静默刷新被掐断），所以做成行尾徽标而不是塞进
副标题 —— 副标题只说稳定事实（来源 + 被谁在用），与改前那条纪律一致。徽标用
`secondaryContainer` / `errorContainer` 的 M3 标准 on-container 配对：状态色随主题
翻转是**预期**的，与第 4 项「身份色不随主题翻转」是两类需求，别混用 fixed roles。

门禁：新建 `CloudAccountCardStyleTest` 3 条 —— 卡片自洽（不许套回 `SettingsGroupCard`）、
动作区两枚同规格且不再被 `Spacer(Modifier.weight(1f))` 推开、长账号名单行省略 +
徽标配对 + 三处 `Panel` 圆角。

### 第 2 项：域名分组整体化（`ItemsScreen.kt`）

用户说的「一条一条的域名分组条」有两个来源，缺一不可：

1. **分组头自己是一张卡**：带 `surfaceContainerLow` 底 + `RoundedCornerShape` + `.clip()`，
   与下面同样圆角的条目卡并排 ⇒ 头读成插进列表的分割条，而不是「一节的标题」；
2. **`LazyColumn` 统一 `Arrangement.spacedBy(8dp)`**：「分组头↔首条」「条↔条」
   「上一组末条↔下一组头」三段**等距**，Gestalt 接近性完全失效。

改法：分组头去掉独立背景、退回 M3 无背景 section header（保留 #283 的低调计数、
展开箭头动画、`stateDescription` 读屏态）；列表改 `spacedBy(0.dp)`，由各 item
自己给三档间距 —— **组间 20dp > 组内 4dp > 头与首条 2dp**；非分组模式仍用
8dp 卡间距。整体感交给间距，不交给背景。

门禁：`ItemsRowStyleTest` **反转规则 3**（从「恰好 1 个 `.background(`」改为
「一个都不许有」+ 不许有圆角 / 裁切），**新增规则 6**（钉三档关系：组间 > 组内 >
头间距、不许回到统一 `spacedBy`、非分组模式仍用 `ITEM_CARD_GAP`）。

### 第 3 项：详情页长标题整洁化（`ExpressiveTopBar.kt` / `ItemDetailScreen.kt`）

`TopBarTitle` 原先只在**有副标题**时禁止折两行；详情页条目名没有副标题，
`accounts.spotify.com` 这类长域名会按字符贪心折成 `accounts.spotify.` / `com`
的孤字行，还与右侧编辑 / 删除图标错位。

改法：`TopBarTitle` 加 `singleLine: Boolean = false`，详情页传 `true`；
`TitleBlock` 的 `allowTwoLines = title.subtitle == null && !title.singleLine`。
详情页只走「缩字号 → 省略号」，库名顶栏**仍允许两行**（默认值 `false` 保证不误伤）。

门禁：`TopBarTitleRulesTest` 规则 1 —— 默认值必须是 `false`、`allowTwoLines`
必须保留 `title.subtitle == null` 旧契约、详情页 `TopBarTitle` 调用块必须带
`singleLine = true`。

### 第 4 项：「+」新建剪影卡配色重做（`AddActionSheet.kt`）

**「奇怪颜色」正是 #282 / #283 那套做法本身**：三色系 `primaryContainer` /
`secondaryContainer` / `tertiaryContainer` 在「卡底 / 剪影底 / 重点形状」交叉铺开，
再叠「卡底 0.68 / 剪影底 0.62」两层半透明（深色档还各提到 0.94 / 0.92）。
`xxxContainer` **随主题翻转**（浅色是浅色、深色变暗色），只要还靠它 + alpha 分档，
深浅两档就得各调一遍，近黑 `surface` 上几个色相仍被洗成浑浊灰 —— #283 补过一次
`onContainer` 配对也只是治标。

取证（本轮反编译 + WebSearch）：

- `material3-android:1.5.0-alpha16` 的 `ColorScheme` 已提供 `primaryFixed` /
  `primaryFixedDim` / `onPrimaryFixed` / `onPrimaryFixedVariant` 等 12 个 fixed roles；
  `lightColorScheme-_VG5OTI` / `darkColorScheme-_VG5OTI` 支持这些命名参数；
- `ColorLightTokens.<clinit>` 证明**未显式传 fixed roles 时**，`PrimaryFixed` 回退
  `PaletteTokens.Primary90`（M3 基线紫），`dynamicLightColorScheme31/34` 却把 fixed
  角色显式映射成壁纸派生的 tonal palette ⇒ 「开动态取色 = 壁纸色，关 = 基线紫」两档跳变；
- fixed roles 的设计契约就是**浅色与深色主题下保持同一固定色值**，专供「不随主题
  翻转身份」的强调面（固定徽标、剪影卡、widget）。

改法：`GlyphPalette` 由 5 字段交叉表改成同一色相家族的四档
（`container` / `wash` / `onContainer` / `onContainerVariant`）；卡底直接画**纯**
`xxxFixed` / `xxxFixedDim`，文案与线条用配对的 `onXxxFixed` / `onXxxFixedVariant`。
**删掉全部 7 个 alpha 常量、删掉 `isDarkSurface` 判档、删掉 `dark: Boolean` 参数**。
5 型靠「3 色相 × Fixed / FixedDim 两档」区分（Identity / SshKey 用 Dim 档作卡底、
Fixed 档作 wash，与前三张同色相但明暗反一档），不硬造第 4 个色相。生成器卡单独
取 `tertiaryFixed` 家族。

门禁：`AddActionSheetStyleTest` **三条规则整体重写** —— ① 卡底 / 前景一律 fixed 家族、
不许残留 6 个 `xxxContainer` / `onXxxContainer`；② 浅深同值 ⇒ 不许 `isDarkSurface`、
不许 `TILE_ALPHA_` / `WASH_ALPHA_` / `GLYPH_LINE_ALPHA_` / `GENERATOR_ALPHA_`、
`ItemFieldGlyph` 不许再接 `dark`、卡片绘制函数体不许 `.copy(alpha`；
③ 5 型各有记忆点（`GlyphPalette(` 5 次、`FixedDim` ≥5 次）、前景一律配对
`onContainer` / `onContainerVariant`。

⚠️ 形状内部为画「卡片轮廓」用的 `accent.copy(alpha = 0.16f)`（GlyphCard）与
`0.14f`（GlyphGenerator）、主卡出血水印的 `HERO_GLYPH_*_ALPHA` 都**不是配色分档**，
规则 2 只精确点名 4 组旧常量、且 `.copy(alpha)` 只扫三处卡片绘制函数体，不误伤绘图层次。

### 第 5 项：主题默认值 / 动态取色 bug（`Theme.kt` / `VaultixBrandColor.kt` / `VaultixPreferences.kt` / `MainActivity.kt` / `SettingsScreen.kt`）

两个硬证据（反编译取证，不是猜）：

1. `VaultixBrandColor.Light` / `Dark` 此前**一个 fixed role 都没传** ⇒ 关闭动态取色时
   fixed roles 回退 M3 基线紫，而开动态取色时是壁纸派生色；
2. `VaultixPreferences.dynamicColor` 默认 `true` ⇒ 首次启动直接绕过两轮调校过的
   品牌浅色板（去紫 / 降饱和 / WCAG 实测）。

改法五处：

- `VaultixBrandColor` 给 `Light` / `Dark` 显式传**同一组 12 个 fixed 命名参数**。
  ⚠️ 不抽 `ColorScheme.copy()` helper：本依赖里 `copy` 有 3 个历史重载
  （`copy-_VG5OTI` / `copy-C-Xl9yA` / `copy-G1PFc-w`），写 helper 会撞重载；
- 第一版手挑的 fixed 色值 Python 实测**饱和度 48.9% / 41.7%**，越过项目
  `MAX_CONTAINER_SATURATION = 40%` 上限，且三色相挤在 226° / 230° 蓝与靛几乎同色
  ⇒ 重取蓝 225° / 青 195° / 绿 145° 三冷色系：饱和度 22%~35.5%、`G-R` 全为正、
  `on*Fixed` 前景对比度 6~12:1、`xxxFixed` 亮于 `xxxFixedDim`；
- `dynamicColor` 三处默认值一致改 `false`（`VaultixTheme` 参数默认值 /
  `MainActivity.collectAsStateWithLifecycle(initialValue)` 首帧占位 /
  `VaultixPreferences` 的 `?: false`）。⚠️ 只影响从未动过开关的用户，DataStore
  已有显式值一律以用户选择为准；
- 新增 `supportsDynamicColor(sdkInt: Int = Build.VERSION.SDK_INT)` 作为**版本门控
  单一真源**，取色分支与设置页低版本禁用共用；低版本开关 `enabled = false` +
  换说明文案 `setting_dynamic_color_unsupported`（`SettingsSwitch` 新增 `enabled`
  参数，占位分支禁用时也不接收点击，避免绕过禁用写偏好）；
- OLED 纯黑从「只 `copy(background, surface)`」改为 `applyPureBlack()` 压**整套
  9 档 surface 家族**到纯黑起算的中性灰阶 —— 这是 #283「底栏外围脏」在色板层的残留。

门禁：`VaultixBrandColorTest` 新增 fixed 家族 4 类（浅深同值 / 饱和度与中性 /
前景对比度 / Fixed 亮于 FixedDim）；新建 `ThemeDefaultRulesTest` 4 条（三处默认值
一致为 false / 版本门控单一真源且门槛为 S / 低版本禁用接线 / OLED 覆盖整套 surface）。

### 第 6 项：KDBX 顶栏标题统一显示格式名（`VaultOriginLabel.kt` / `ItemsScreen.kt` / `strings.xml`）

用户要求条目页左上角统一显示 `KDBX`，不显示 `xxx.kdbx`。

改法：在 `VaultOriginLabel.kt`（本来就是「KDBX 该怎么称呼」的单一真源）新增
`@Composable fun vaultTopBarTitle(vault)`：KDBX → `R.string.vault_title_kdbx`（`KDBX`），
其余 → `vault?.name.orEmpty()`；`ItemsTopBar` 的 `vaultName` 改走它。

⚠️ **只改顶栏**：列表状态行 `VaultStatusRow` 仍带文件名，那是用户核对「我打开的是
哪个文件」的地方，两处语义不同。⚠️ 不在 `ItemsScreen` 里再判一次 `kind` ——
#263 / #264 两轮真机反馈都是「同一份库信息在两处各判一遍」漂移出来的，
`check_kdbx_origin_single_source.py` 守的正是这条纪律。

门禁：`TopBarTitleRulesTest` 规则 2 / 3。**精确定位而不是粗放全禁**：`ItemsScreen.kt`
里另有一个合法的 `VaultKind.KDBX ->`（`cloudSyncBadgeOrNull()` 的云同步角标，#263 判据），
所以规则钉的是「`R.string.vault_title_kdbx` 不许出现在 `VaultOriginLabel.kt` 之外」
+ `VaultStatusRow` 不许复用顶栏判据。

### 踩坑清单（本轮实打实踩到的）

1. **`functionBody()` 不含参数签名** —— `ThemeDefaultRulesTest` 规则 3 首跑红在
   「`SettingsSwitch` 缺 enabled 参数」，因为 `enabled: Boolean = true` 在签名里、
   而 helper 从 `{` 起截取。#283 当年踩过同一个坑（`dark: Boolean`），本轮按同一
   口径新增 `functionSignature()` 才修好。**判「有没有某个参数」必须走签名 helper**。
2. **detekt `MagicNumber` 拦函数参数里的裸色值** —— `applyPureBlack()` 内联 7 个
   `Color(0xFF…)` 被拦；`VaultixBrandColor` 里同款字面量在属性声明里却不报
   ⇒ 抽成 `private val PureBlack*` 属性常量再引用。
3. **detekt 圈复杂度** —— `ItemsRowStyleTest` 规则 3 反转后评到 15（上限 14），
   把「计数低调」四条判据抽成 `groupHeaderCountViolations()` helper（#283 同款解法）。
4. **管道吞退出码** —— 后台验证命令用 `gradlew ... | tail`，shell 显示 exit 0、
   实际 `=== FULL VERIFY EXIT=1 ===`（`:app:detekt FAILED`）。判 rc 一律
   `cmd > log 2>&1; rc=$?; ...; exit $rc`，不要靠 `PIPESTATUS` / 尾部 `tail`。
5. **门禁判据本身要随反馈反转** —— 改生产代码前先确认旧门禁不会「钉住旧写法」：
   `AddActionSheetStyleTest` 三条整体重写、`ItemsRowStyleTest` 规则 3 反转、规则 6 新增。
6. **禁止粗放全禁字符串** —— 写 KDBX 顶栏门禁时差点写 `!items.contains("VaultKind.KDBX")`，
   实际 `ItemsScreen.kt:2443` 有合法的云同步角标分支；改成精确点名资源名。
7. **fixed 色值也要量化验证** —— 手挑的第一版饱和度 48.9% 越过 40% 上限、
   三色相几乎同色，Python 实测后重取；「按规范取名」不等于「颜色合规」。
8. **`SettingsStyleRulesTest` 规则 3/4 扫整个 `ui/settings/`** —— 新增 UI 不得硬编码
   中文、`R.string.*` 必须真实存在。本轮两个新文案都在 `strings.xml` 登记，
   账号卡复用既有文案，没触发这两条。
