## 305. 指纹门锁 KEK 显式生物失效设置（2026-11-24 · KeePassDX #2805 借鉴）

### 来源与实证

- 调查 KeePassDX 近期更新时，4.5.9（2026-11-23）修了 issue #2805：Samsung S22 / Android 8.0
  上录入新指纹后，旧 KEK 仍能被新指纹解开。根因是厂商 overlay 未遵守
  「`setInvalidatedByBiometricEnrollment` 默认为 true」，`a52970d` 的修法是显式调用它。
- Vaultix 的 `LocalUnlockKeyStore` 指纹 KEK 同为 auth-per-use + minSdk 26 的同类密钥，
  却只在第 219 行注释写「默认 true」，正文无显式调用 —— 同类防御缺口。

### 修复

- `obtainOrCreateKey()` 显式加 `.setInvalidatedByBiometricEnrollment(true)`，注释收敛为
  what + 编号引用。不改变主流机行为，只在 OEM 不守默认时兜住「生物变更即失效」。
- 新增源码门禁 `.ai/tools/check_biometric_invalidation.py`，剥注释后断言
  `obtainOrCreateKey()` 函数体含显式 true、不含 false；接入 `ci-debug.yml` 两步。
- ⚠️ 判据必须剥 `//` 与 `/* */` 注释：旧源码注释里就写着「默认 true」，朴素 `in`
  会把注释误当代码而假绿。本关只管指纹门锁这一把，不误伤
  `AutoUnlockKeyStore` / `KdbxDerivedKeyDiskCache` 两把**刻意 false** 的钥匙（在别的文件）。

### TDD 与本地验证

- 门禁自测 3 组变异全抓到：删调用 / 改 false / 只写进注释（后者专测剥注释判据）。
- 旧实现红灯：当前源码被判「未显式 setInvalidatedByBiometricEnrollment(true)」；
  加显式调用后转绿。均为有效行为断言，非编译/脚本错误。
- 本地：`data/repository` 199+161 例、`core/crypto` 195 例共 555 例全绿；
  静态门禁 26/26（新增门禁已计入）、workflow shell 门禁与 YAML 语法通过。
- 这是纯加固 + 门禁，无运行时逻辑改动；真机验证（新增/删除指纹后是否回主密码）
  仍属边界，静态门禁不能替代。
