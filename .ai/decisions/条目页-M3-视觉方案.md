# Vaultix · 条目三页（新建 / 编辑 / 详情）M3 视觉重构方案

> 2026-11-09 · **P0 已实施**（`30673842`）；P1 / P2 未实施，但方向已由用户拍板（见 §8）。
> 基于当前代码实测（行号可核对），不是通用 M3 教程。

---

## 0. 一句话结论

这三页的问题**不是"不够 Material 3"**，而是：

1. **Typography 从未定义** —— `Theme.kt` 只传了 `colorScheme` 和 `shapes`，全 App 吃的是 M3 的**拉丁文默认值**；
2. 于是每处都在**就地手调**（`EntryCard` 把 `titleMedium` 行高从 24 改成 21），三页各调各的；
3. 结果：同一个"分区标题"在表单是 14sp、在详情是 16sp；同一个"分区卡"在表单是 `Highest`、在详情是 `Low`。

⇒ **先立唯一真源（字阶 + 语义色），再改版式**。直接换皮的话，三个月后又是三套。

## 2. 唯一真源：`VaultixTypography`

### 2.1 为什么必须自己定义（M3 默认值在中文上的三个具体问题）

| 问题 | M3 默认 | 中文实际 |
|---|---|---|
| **字距** | `bodyLarge` letterSpacing = **0.5sp**、`bodyMedium` = 0.25sp | 拉丁文靠字距提升可读性；**中文加字距会"漏风"**，整段松散 |
| **行高** | `bodyMedium` 14/20 (1.43)、`bodySmall` 12/16 (1.33) | 中文没有 x-height，字面占满 1em，**1.43 偏挤** |
| **字重** | 600 = SemiBold（`EntryCard` 在用） | Noto Sans CJK 的稳定档只有 400/500/700；**600 会被合成**，小字号下发糊 |

> 这不是"审美偏好"。`EntryCard.kt:187` 那行「`titleMedium` 行高 24sp → 21sp」**就是 D1 的账单** ——
> 因为主题没定义，只能在这一处手调；下一个页面遇到同样问题，再手调一次。

### 2.2 建议的 12 档（不是 13 档全上）

| Token | 字号 | 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|---|
| `displaySmall` | 36 | 44 | 400 | 0 | 仅解锁页 / 空态大标题 |
| `headlineMedium` | 28 | 36 | 500 | 0 | 页面级大标题（详情页 hero 可选） |
| `headlineSmall` | 24 | 32 | 500 | 0 | **页面主标题**、表单里的条目名 |
| `titleLarge` | 22 | 28 | 500 | 0 | 顶栏展开标题 |
| `titleMedium` | 16 | 24 | 500 | 0.1 | 卡片标题、条目名、**分区标题** |
| `titleSmall` | 14 | 20 | 500 | 0.1 | 卡内小节标题、字段组名 |
| `bodyLarge` | 16 | 24 | 400 | **0** | 详情页字段值（主信息） |
| `bodyMedium` | 14 | **22** | 400 | **0** | 表单字段名、正文 |
| `bodySmall` | 12 | **18** | 400 | **0** | 辅助说明、摘要、时间戳 |
| `labelLarge` | 14 | 20 | 500 | 0.1 | 按钮文字 |
| `labelMedium` | 12 | 16 | 500 | 0.2 | 徽章、字段名（详情页行） |
| `labelSmall` | 11 | 16 | 500 | 0.2 | 极小标注（仅徽标内） |

三条纪律：

1. **字距归零（body 系列）** —— 这是中文适配的第一刀，也是观感变化最明显的一刀。
2. **body 行高 +2sp**（14/20→14/22、12/16→12/18）—— title 系列**不动**（标题行高紧一点更精神）。
3. **`titleMedium` 恢复 24sp 行高**，把 `EntryCard` 的 21sp 局部调整**收回去**：那是补丁，不是规格。
   ⚠️ 这一条会改变列表卡片高度（每行约 +3dp），**必须真机对比**再定。

### 2.3 接入方式

```kotlin
// theme/VaultixTypography.kt（新建）
internal val VaultixTypography = Typography(
    headlineSmall = TextStyle(fontSize = 24.sp, lineHeight = 32.sp, fontWeight = FontWeight.Medium),
    ...
)
// Theme.kt：MaterialTheme(colorScheme = colorScheme, shapes = VaultixShapes, typography = VaultixTypography, ...)
```

⚠️ **动态取色不管字阶**，所以这份 typography 对"动态色 / 固定色板"两条分支**同时生效**，不需要分支。

## 3. 表单页（新建 / 编辑条目）

### 3.1 现状骨架

```
┌ 顶栏  编辑条目 ─────────────────────────┐
│ 卡1  [文件夹▾] [类型▾]  ★名称           │  ← 归属 / 分类 / 身份 挤在一张卡
│ 卡2  登录信息                           │
│      用户名 / 密码(强调底) / 网址 / 2FA  │  ← 5 个框同级平铺
│ 卡3  自定义字段 / 备注 / 主密码保护      │
└ 底栏  取消(Outlined)      保存(Filled) ─┘
```

**三个具体问题**

1. **名称是主标识，却排在卡 1 最下面**，且与"文件夹""类型"同字号同级 —— 用户扫视时先看到一堆次要字段。
2. **卡 2 的 5 个框没有内部分组** —— 账号（用户名/密码/网址/2FA）与"这条目叫什么"是两件事，混在一张卡里只靠间距区分。
3. **类型用下拉**，而它只有 2~5 个固定选项、且**只在新建时可选**（`typeEditable`）—— 下拉在这里是"为了省地方"牺牲了一次点击。

### 3.2 建议骨架（M3 Expressive：身份上浮 + 分组卡片）

```
┌ 顶栏  新建条目 ─────────────────────────┐
│  ╭────╮  条目名称（headlineSmall, 无框） │  ← 身份区，直接铺在 surface 上
│  │ 48 │  用户名（bodyMedium, 无框）      │     不进卡片，不与表单字段同级
│  ╰────╯                                  │
│  类型  [登录][卡片][身份][SSH][安全笔记]  │  ← FilterChip 单选，FlowRow 可换行
│                                          │     （typeEditable=false 时显示只读徽章）
│ 卡1  账号                                │
│      用户名 / 密码 / 网址                 │
│ 卡2  验证                                │
│      一次性验证码                          │
│ 卡3  备注与扩展                           │
│      备注 / 自定义字段                    │
│ 卡4  归属                                │
│      文件夹 / 主密码保护                  │
└ 底栏  取消(TextButton)    保存(Filled) ──┘
```

### 3.3 逐条理由

| 变更 | 理由 | 风险 |
|---|---|---|
| 名称上浮、改 `headlineSmall`、无边框 | M3 的"页面标题不属于表单"；Bitwarden / 1Password 编辑页同构 | 低（纯版式） |
| 类型下拉 → `FilterChip` 行 | 少一次点击；5 个选项一次全见，不用记住下拉里有什么 | 中：5 个 chip 需 `FlowRow` 两行，占 ~72dp |
| 卡 2 拆成「账号 / 验证 / 备注 / 归属」 | 现在的 5 个框里混了"登录凭据"和"2FA"两类，拆开后每卡 ≤3 个字段，扫视成本降 | 中：卡片数 3→4，页面变长 |
| 卡片内边距 20 → `Spacing.lg`(16) | 回到标尺（D5）；16dp 也是 `EntryCard` 的内边距，两处统一 | 低 |
| 底部「取消」改 `TextButton` | 两个带轮廓的按钮并列会争主次（D8）；M3 里次要动作就是无框 | 低 |

⚠️ **`FilterChip` 而不是 `SegmentedButton`**：`SegmentedButton` 适合 2~3 段（见 `AddKdbxScreen` 的两种模式），
5 段在 360dp 宽屏上每段只剩 60dp，「安全笔记」会被截断。`FilterChip` 天然可换行。

## 4. 详情页

### 4.1 现状骨架

```
┌ 顶栏  条目名（随滚动收缩）──────────────┐
│ [图标] 3 条网址 · 含 2FA · 1 个通行密钥  │
│        user@example.com   [登录]         │
│ 登录信息 卡                              │
│ 网址 卡                                  │
│ 2FA 卡                                   │
│ 通行密钥 卡                              │
│ 卡包 / SSH / 身份 / 自定义字段 / 备注     │
│ 创建于 … · 修改于 …（一行小字）           │
└──────────────────────────────────────────┘
```

**三个具体问题**

1. **9 张卡、9 个 16sp 主色标题** —— 每个标题都在喊"看我"，等于没有重点（D7）。
2. **"网址 / 2FA / 通行密钥"是同一件事的三个面**（这条目能怎么登录），却各占一张卡，中间隔着 24dp 空白。
3. **字段行是自绘 `Row`**（`DetailFieldRow`），行高、水波纹范围、读屏语义都要自己维护；而 M3 的 `ListItem` 免费给这三样。

### 4.2 建议骨架

```
┌ 顶栏  条目名（Expressive 收缩，保留）────┐
│ ╭──────╮  3 条网址 · 含 2FA · 1 个密钥   │  ← 图标放 primaryContainer 圆角方底
│ │ 56dp │  user@example.com               │     摘要 bodySmall / 账号 titleMedium
│ ╰──────╯  [登录]                         │
│                                          │
│ 账号与密码                                │  ← titleSmall + onSurfaceVariant（不再 primary）
│ ┌──────────────────────────────────────┐ │
│ │ 用户名   user@example.com        ⧉   │ │  ← ListItem：overline=字段名 / headline=值
│ │ 密码     ••••••••••        👁  ⧉    │ │
│ └──────────────────────────────────────┘ │
│ 访问方式                                  │  ← 三卡合一，内部分隔线
│ ┌──────────────────────────────────────┐ │
│ │ 网址 3 条                        ▾   │ │
│ │ ──────────────────────────────────── │ │
│ │ 一次性验证码                      👁  │ │
│ │ ──────────────────────────────────── │ │
│ │ 通行密钥 1 个                     ›  │ │
│ └──────────────────────────────────────┘ │
│ 备注 / 卡包 / SSH / 身份 / 自定义字段     │
│ 创建于 … · 修改于 …                       │
└──────────────────────────────────────────┘
```

### 4.3 逐条理由

| 变更 | 理由 | 风险 |
|---|---|---|
| 字段行换 `ListItem` | 标准 56/72dp 行高、水波纹只覆盖行、读屏自动念"用户名 / user@..." | 中：`DetailFieldRow` 有自定义排版，需逐项迁移 |
| 网址 + 2FA + 通行密钥合并一张卡 | 三者在语义上都是"怎么登录"，用户连着看；卡片 9→7 | 中：折叠/展开交互要重做 |
| 分区标题 `titleMedium`+`primary` → `titleSmall`+`onSurfaceVariant` | 把"重点"还给内容；9 个主色标题是反效果 | **🛑 与 2026-09-13 用户明确反馈冲突**（原话"小标题是否要稍微大一点"）——**需你拍板** |
| 头部图标加 `primaryContainer` 底 | 现在图标直接贴在 surface 上，与下方卡片没有层次 | 低 |

## 5. 配色：不动主色，补一层语义

主色板有 WCAG 单测钉着（`VaultixBrandColorTest`），**本方案一个色值都不改**。要动的是"用哪一档"。

### 5.1 三条硬规则

| 用途 | 该用 | 不该用 |
|---|---|---|
| 主操作按钮 | `primary` / `onPrimary` | `tertiary`（信息色，不是动作色） |
| 分区标题 / 图标 | `onSurfaceVariant`（推荐）或 `primary`（强调时） | **同一行混两色**（D3） |
| 字段名 | `onSurfaceVariant` | `primary`（会被误读成可点） |
| 危险操作 | `error` / `onError` | 降饱和（会削弱"危险"） |
| 卡片底（详情） | `surfaceContainerLow` | — |
| 卡片底（表单全屏 Dialog） | `surfaceContainerHighest` 或统一到 `Low` | 两页各挑一档且无说明（D4） |
| 卡片内嵌套元素 | 往**低**走一档（`Lowest`） | **同色叠 alpha**（8.4 明令禁止） |

### 5.2 把散落的 `copy(alpha=)` 收进 token

现在 `EmphasisBlock` 用 `tertiaryContainer.copy(alpha = 0.10f)`，注释里记了两次翻车史。
建议提为：

```kotlin
object VaultixTint {
    /** 关键字段的"淡圈"，不复用 surface 家族，避免同色叠 alpha。 */
    val FieldEmphasis = tertiaryContainer.copy(alpha = 0.10f)
    val CardBorder = outlineVariant
    val BadgeContainer = tertiaryContainer
    val BadgeOnContainer = onTertiaryContainer
}
```
⚠️ 它必须接受动态取色的考验（`tertiaryContainer` 在深色动态下可能是亮粉紫）——
提成 token 后**只需在 token 注释里写一次这条警告**，不用每处重复。

## 6. 按钮与操作层级

| 位置 | 现状 | 建议 | 理由 |
|---|---|---|---|
| 表单底栏主操作 | `Button`（filled） | **保留** | 唯一主操作，正确 |
| 表单底栏次要 | `OutlinedButton` | → `TextButton` | 两个轮廓按钮并列，主次不清（D8） |
| 破坏性（移除验证码） | `TextButton` + `error`，靠左 | **保留** | 左置 + 红字，与主操作物理隔离，正确 |
| 详情页行内 | `IconButton` | **保留** | — |
| 列表新建 | `FloatingActionButton` | **保留** | — |
| 表单里的"扫码 / 生成" | `IconButton` 在 `trailingIcon` | **保留** | 位置对（贴近它作用的字段） |

一条 M3 判据写进 8.4：**同一屏只有一个 Filled 按钮**。现在全 App 满足，改版时别破坏。

| 决策项 | 结论 | 备注 |

收回会让标题与图标错位。

## 附：不做的事（明确排除）

- **不引入自定义字体文件**：APK 体积 + 中文字体动辄 10MB+，且系统字体在中文上已足够。
- **不换成 M3 Expressive 的 alpha 组件**（`ButtonGroup` / `LoadingIndicator`）：与 `8.8 §6①` 一致，等 stable。
- **不动 `VaultixBrandColor` 的任何色值**：有 WCAG 单测，改色值会让 CI 红，且现在没有配色问题。
- **不给详情页加动态验证码**：8.4 已定"降功耗，只提示不滚动刷新"。
