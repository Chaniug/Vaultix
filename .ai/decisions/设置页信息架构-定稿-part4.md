## §12 第四轮修订（2026-09-18 · 「关于」段的权限管理行改为进应用内页）

> 起因：用户当天口头提「权限管理界面能优化一下。加一点规范的引导，打开什么权限之类的」。
> 提交 `a4c8686`。这一节只记**对本定稿的改动**；页面本身的实现说明在
> `.ai/SESSION-2026-09-18.md` §8。

### 12.1 改了什么

| 项 | §5.2 定稿（09-15） | 现在 |
|---|---|---|
| 点击行为 | **直接跳系统应用信息页** | **先进应用内权限引导页**（`PermissionsRoute`） |
| `permission_management_subtitle` | 在系统设置页查看与调整应用权限 | **看看这个应用要什么权限、拿去做什么** |
| 行的位置 / 组 | 「关于」段 | **不变** |
| `permission_management_title` | 权限管理 | **不变** |

### 12.2 ★ 为什么 §5.2 定下的副标题**必须重写**

§5.2 当时把原副标题「在系统应用信息页查看 / 调整 **Vaultix** 的权限」改成
「在系统设置页查看与调整应用权限」—— 这**在当时是对的**（那行的确跳系统页，
是在**指路**）。

但 §4 文案三条规则**明令禁止指路语**（"关闭入口见下方列表"就是被这条删掉的）。
所以那一版是个**妥协**：功能上需要指路，规则上不许指路。

⇒ 现在那一行**不再跳系统页**，指路的必要**消失了** ⇒ 副标题正好可以回到规则的
正解：**说清"这一行能让你看到什么"**，而不是"点下去会去哪"。

「看看这个应用要什么权限、拿去做什么」正是这个意思 —— **它描述的是内容，不是跳转。**

> ⇒ 这条修订**没有推翻 §4**，恰恰是**让 §4 收回了它本该有的作用**。
> 同时它印证了 §4 那条规则的价值：只要行还在跳系统页，就永远写不出合规的副标题。

### 12.3 与 §7 边界的关系

§7 里"不要在这一页增加新的一级分组"等边界**没有被推翻** —— 权限页是**二级页**，
不进设置首页。设置首页那一行仍是**同一个位置、同一个标题、同一段**。

### 12.4 新增的边界（**不要做**）

1. **不要**把合并清单里的 `NFC` / `USE_FINGERPRINT` /
   `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` 列进权限页。
   它们是传递依赖（NFC ← MSAL → YubiKit）与签名级内部权限，
   用户既看不见也管不着 —— 列进去只会稀释真正要管的四项。
   证据与完整推导见 `.ai/SESSION-2026-09-18.md` §8.2。
2. **不要**给 `SettingsScreen.onOpenPermissions` 加默认值。
   设置页有两个调用点，默认空实现会让主界面设置 Tab 那一处**静默失效**。
3. **不要**用 `shouldShowRequestPermissionRationale` 控制扫码页那条
   "去系统设置里开启"出口的显隐（它是二义值，见 §8.3）。

### 12.5 装机验收（在 §8.1 基础上补）

- [ ] 设置 → 关于 → 权限管理：**进的是应用内页**，不是系统页
- [ ] 状态卡在有未授予项时显示「有 N 项待允许」，全授予后变「一切就绪」
- [ ] 点相机「授予」→ 就地弹系统框；授予后返回，**状态卡立刻更新**（不留旧状态）
- [ ] 拒绝相机 → 从系统设置手动开 → **回前台状态卡跟着变**（`ON_RESUME` 重算）
- [ ] 无指纹录入的设备：指纹行显示「设备不支持」且**没有按钮**
- [ ] 扫码页把相机权限选「拒绝且不再询问」→ 页面仍有「去系统设置里开启」，点了能跳
- [ ] **Android 13 以下**：通知行显示「已允许」，且**没有**按钮（单测覆盖不到这一支）

## §13 第五轮修订（2026-09-18 · 网盘账号：把「配置」从「添加库」里搬出去）

> 起因：用户「好像项目现在的云盘接入的逻辑没有 bastion 好，你看看它那边是如何接入云盘的，
> 设置里面的」。对比结论在 `/workspace/网盘接入对比-Bastion-vs-Vaultix.md`，
> 本轮**不搬 Bastion 的任何文件**，只补自家定稿 §11.7 里**早已排好、但没做完**的两步。

### 13.1 核心判断：**不是设计不如 Bastion，是施工没做完**

Bastion 的观感优势是**结构性的**：`LocalKeePassScreen` 是「库管理中心」，
挂载网盘 = 一个 BottomSheet 浏览器（【测试连接】+ 状态卡 + 建目录/建库）。
但对照自家 §11.7 会发现：**它要求的几乎就是同一件事** ——
「网盘账号」页负责**配账号**，「添加库」页负责**选账号 + 选文件**。

⇒ 所以这是**施工进度差**，不是设计差。补完即可，不需要推翻任何已定稿的东西。

### 13.2 改了什么（P0：网盘账号页真正能配账号）

| 项 | 改前 | 改后 |
|---|---|---|
| 「网盘账号」页 | **只读清单**（从库的 origin 反推，配了没建库的账号列不出来） | **可操作**：加账号 / 一键登录 / 切换账号 / 重新填写 / 注销 |
| WebDAV 配置入口 | 在「添加库」页（填地址+账号+密码才能往下走） | 搬到「网盘账号」页，**先测连接再保存** |
| OneDrive 配置 | 散落在添加页（`signInOneDrive` / `switchOneDriveAccount` / `signOutOneDrive`） | 搬到「网盘账号」页，添加页只剩「选账号」 |
| 配置失败 | 凭据**已落盘**，留下永远用不到的密文 | 探测失败**回滚**（沿用既有纪律） |

### 13.3 ★ 卡住 P1 的那个真问题：credentialId **反推不出地址**

credentialId 是「服务器 + 用户名」的 **SHA-256 前 8 字节**，从 id 反推不出地址
⇒ 「我配过哪些账号」这个问题**原本答不出来**
⇒ `CloudAccountInventory` 只能从**库的 origin 反推**
⇒ 「配了凭据、但还没建库」的账号**列不出来**
⇒ 一旦把配置入口搬到网盘账号页，用户配完会以为「没配上」——**搬了就是死路**。

**解法**：给 `WebDavCredentialStore` 加一份**索引**（`webdav_account_index`，
`\n` 分记录、`\t` 分字段），`inventory.list()` 改为**两路合并**：

1. 已存凭据 / 已缓存会话 ⇒ 回答「我配过哪些账号」；
2. 库的 origin ⇒ 回答「每个账号被哪些库用着」+ `browseRoot`。

#### 13.3.1 为什么这份索引**不是**「第二份真相」

本项目反复被咬的正是「两处独立维护的真相必然漂移」。索引规避了它的三个前提：

- **不存密码** —— 只是「哪些 id 存在」的一份目录；
- **同处、同次调用维护** —— `save` / `remove` 各自末尾一行，
  不存在「删了凭据却忘了删索引」的可能；
- **丢了也只影响可见性** —— 索引损坏的后果是「列不出来」，凭据照常可用、库照常解锁。

⇒ 这是「让现有真相**可枚举**」，不是「另建一份真相」。

### 13.4 ★ 凭据写入的**唯一入口**：`CloudAccountConnector`

两个 ViewModel（`CloudAccountsViewModel` / `AddCloudVaultViewModel`）原本各自
`save` / `remove` 凭据 ⇒ 落盘格式一旦要改就得改两处。
新增 `CloudAccountConnector` 收敛成**一处**：保存 → 探测 → 构造 source → 登录 / 注销。

同时把 `WebDavCredentialStore.save` 的签名从
`save(credentialId, username, password)` 改成 `save(serverUrl, username, password): String`
（id 由内部算出并返回）。

> ⚠️ **这次改动藏着一个编译器抓不到的坑**：两个参数**都是 `String`**，
> 旧的 `save(credentialId, user, pass)` 调用点会**照常编译**，
> 但把 credentialId 当服务器地址写进去 —— 表现是「配成功了，连不上」。
> 收工前已在 `remote/` 全树确认只剩一处 `.save(`。

### 13.5 顺手补的一处缺口：WebDAV「重新填写」

注销之外，用户还需要「**只重填密码**」（密码改了、令牌过期）。
`startReconfigure(account)` 预填：

- `serverUrl` ← `account.browseRoot`（**不是** `label` —— label 会剥掉路径，填回去会 404）；
- `username` ← `connector.readWebDavUsername(credentialId)`（★ 不返回密码）；
- 密码**留空** —— 不预填。

「重新填写」按钮只在 **WebDAV 且未连接**时出现（OneDrive 走「登录/切换」）。

### 13.6 改了什么（P1：添加库页摘掉表单）

| 项 | 改前 | 改后 |
|---|---|---|
| 添加库 · 云盘 | 一张地址/账号/密码表单 | **三态分发**：浏览中 / 加载中 / **无账号（引导去配置）** / **选账号** |
| 没有账号时 | 让用户当场填（与网盘账号页重复） | 显示引导文案 + 「去网盘账号」按钮 —— **不是表单** |
| `resetConnection()` | 清凭据 | 只清选中 id / 目录栈 —— **凭据归网盘账号页管** |

### 13.8 新增的边界（**不要做**）

1. **不要**把 `browseRoot` 当 `serverUrl` 预填之外的用途 —— 它可能含子路径。
2. **不要**给 `readWebDavUsername` 加「顺便返回密码」的重载 —— 索引与展示都不该碰密码。
3. **不要**在「网盘账号」页做**建库 / 建目录**（Bastion 有，那是它的库管理中心职责；
   本项目的对应位置仍是「添加库」页）。

### 13.9 装机验收（真机）

- [ ] 设置 → 网盘账号 → 加 WebDAV：填错密码 → 【测试连接】报错 → 凭据**未落盘**
- [ ] 填对 → 保存 → 该账号**立刻出现在清单里**（哪怕一个库都还没建）
- [ ] 添加库 → 云盘：看到的是**账号列表**，不是表单
- [ ] 选账号 → 浏览目录 → 选文件 → 能加上
- [ ] 网盘账号 → 某个 WebDAV 未连接 → 【重新填写】→ 用户名是预填的、密码是空的
- [ ] 【注销】→ 弹窗**说明会影响 N 个库**；确认后只删凭据，**库本身还在**
- [ ] OneDrive：【登录】拉起 MSAL，回来后账号出现；【切换】能换号
