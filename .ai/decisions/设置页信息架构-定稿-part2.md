## §10 第二轮修订（2026-09-15 · 密码库管理合并）

> 用户原话：「设置页面的密码库，添加密码库，快速解锁设置，这几个好像都属于密码库管理的内容，
> 我在想这些能不能放到一起管理。然后这些界面的ui，按钮，设置的逻辑是否需要重新优化，
> 你按照material3最新的设计理念，来优化这些内容。可以吗」
>
> ⚠️ **这一节是「修订」不是「推翻」**：§2 的三处病因（破坏性动作错位 / 单行成组 /
> 语义重叠）与 §4 的文案三规则**继续有效**，§7 的边界除本处显式说明者外也都继续有效。

### 10.1 改了什么

| 项 | §3 原定稿 | §10 修订后 |
|---|---|---|
| 「密码库」组 | 当前密码库 · 添加密码库（2 行） | **只留 1 行**「密码库管理」→ 二级页 |
| 「快速解锁」 | 在「**解锁与隐私**」组 | 移到**密码库管理二级页** |
| 「解锁与隐私」组 | 快速解锁 · 自动锁定 · 防截屏 · 剪贴板清除 | 自动锁定 · 防截屏 · 剪贴板清除（3 行） |

新增文件 `app/src/main/java/io/vaultix/vaultix/ui/settings/VaultManagementScreen.kt`，
新增路由 `VaultManagementRoute`。

### 10.2 为什么这不算推翻 §2③

§2③ 的结论是「"安全"里混了三类东西」，于是分出「解锁与隐私」——
**这个诊断依然对**。本轮只是发现「快速解锁」被分错了边：它是**按库**登记的
（`SettingsViewModel.quickUnlockVaults` 的形态就是"每库一行"），
属于「库怎么打开」，不属于「隐私」。

判据（可复用）：**一条设置项如果它的主语是"某个库"而不是"这个 App"，它就属于库管理。**

### 10.3 为什么二级页而不是"在首页摊开"

首页的职责是**分流**，不是干活。三件事摊在首页会：
1. 让「密码库」组变成 5~6 行（选库 / 加库 / 每个库的指纹与 PIN…）—— 与 §2② 要消灭的
   "体量失衡"是同一类问题；
2. 把 `ActiveVaultDialog` / `QuickUnlockManageDialog` 及其连带的 KDBX 待验证 id、
   PIN 两步流程等一串状态重新压回 `SettingsScreen` ⇒ 必然顶破 detekt `LongMethod ≤150`
   （这正是当初把它们拆出去的原因）。

⇒ 与 `AutofillSettingsScreen` / `ImportExportScreen` 保持同一层级：**首页一行 → 二级页干活**。

### 10.4 §7 边界的更新

- §7「❌ 不新增任何设置项、不改变任何开关的默认值或行为」—— **仍然有效**。
  本轮**没有**新增 / 删除任何设置项，也没有改任何默认值；只是把三个已有入口
  从两个组挪到同一页，并**保留全部原有对话框与分支逻辑**（含未解锁库 → 直连解锁页）。
- §7「❌ 不动 `AutofillSettingsScreen` 内部」—— **仍然有效**。
- ⚠️ **新增边界**：`VaultManagementScreen` 与 `SettingsScreen` **共用同一批对话框
  composable**（`ActiveVaultDialog` / `QuickUnlockManageDialog` / `PinDialogHost` /
  `KdbxQuickUnlockPasswordDialog` 已从 `private` 提升为 `internal`），
  **不要**在任一侧复制一份出来改——两份必然漂移。

### 10.5 装机验收（在 §8.1 基础上补）

1. 设置首页从上到下：**5 个组**，其中「密码库」组**只有 1 行**「密码库管理」，
   副标题显示当前库名；
2. 点进「密码库管理」：3 行（当前密码库 / 添加密码库 / 快速解锁），
   点「当前密码库」的选库对话框行为与改前一致：
   - 点**已解锁**的库 → 直接切过去；
   - 点**未解锁**的库 → **去解锁页**（不能切过去，否则空白页 bug 复发）；
   - 「设为默认」→ 只改冷启动目标，不要求当下解锁；
3. 「快速解锁」点开的对话框与改前**完全一致**（每库两行：指纹 / 应用内 PIN，
   KDBX 勾选后先要主密码）；
4. 「解锁与隐私」组里**不再有**「快速解锁」，只剩自动锁定 / 防截屏 / 剪贴板清除。
