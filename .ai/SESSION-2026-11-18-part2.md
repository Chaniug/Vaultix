## 0. 一句话结论

**「图标不好看」要先拆成「形态不对」还是「颜色撞车 + 不够跳」——这两个答案指向完全不同的路。**
用户最终确认折纸 V 形态满意，真问题是白/折痕对比度只有 1.69:1（小尺寸糊成一团）
且底色落在密码管理器最拥挤蓝区。把底压深到 `#1B2B63` 一个改动同时解决两件事，
几何一个顶点没动。主题色则按拍板做「4 套预设 + 默认档不动」，门禁从「主色锁蓝区」
改成「默认档锁蓝区、可选档独立判据」，WCAG 底线一条没放。

## 2. 根因 / 约束

### 2.1 配色不是加几行色值（这章回答：为什么不能直接加松石青/石墨）

`VaultixBrandColorTest` 钉死：主色 S≤58%、容器 S≤40% / L≤96%、
**主色相锁 200–250°**、18 对 WCAG 逐对钉住。加青/石墨会直接跑红 ⇒
必须先改门禁为「默认档继承原蓝区约束，可选档用色相稳定 + 饱和度 + 对比度」。

主题模式其实**三态**（`ThemeMode.SYSTEM/LIGHT/DARK`）+ 动态取色（API 31+，默认 false）
+ OLED 纯黑 + 液态玻璃；用户说「只有两种」是没算「跟随系统」。

### 2.2 V 在手机上不跳的量化根因（这章回答：为什么形态没问题却不好看）

现行三色「白 `#FFFFFF` / 折痕 `#B9C6F0` / 底 `#3B5BC4`」中：

- **白 / 折痕 = 1.69:1** ⇒ 24dp 下两半糊成一团淡色，折纸层次消失；
- 折痕 / 底 = 3.56:1；
- 底色 `#3B5BC4` 正落在密码管理器最拥挤蓝区（Bitwarden `#175DDC`、1Password `#0572EC`）。

同一蓝底下白/折痕与折痕/底此消彼长，**三档要同时拉开只能压深底**：

| 方案 | 白/折 | 折/底 | 白/底 | 竞品距离 |
|---|---|---|---|---|
| 现行 | 1.69 ❌ | 3.56 | 6.04 | 近 |
| **④ 深海军 `#1B2B63` + `#7690D4`** | **3.13** | **4.27** | 13.36 | 远 |
| ⑤ 更深 `#151F4A` + `#6A84C9` | 3.65 | 4.34 | 15.82 | 最远 |
| 石墨 `#2F3B4A` + `#7690D4` | 3.13 | 3.64 | 11.38 | 最远但色相割裂 |

选 ④ 不选 ⑤：⑤ 底已近黑，深色壁纸上边界消隐只剩白 V 浮着，失去保险库实体感；
④ 白/底 13.36 已足够跳，折痕 3.13 刚过 WCAG 非文本 3:1 门槛。
石墨竞品区分最强但属灰蓝色相，与 App 内主题蓝是两色；④ 仍是蓝家族只深一档，品牌割裂最小。

### 2.3 第二页渲染事故（这章回答：HTML 方案页为什么第一次看不到效果）

JS 占位符用了裸 `L`/`S`/`BG`，`replaceAll('L', L)` 把 SVG 路径命令 `L`（LineTo）
一起替换成颜色 ⇒ 12 个 path 全坏。修法：改独特 token `@@L@@` 等，Python 校验
所有 `d` 属性合法、无残留；第三页改用 CSS 变量 `var(--ibg)` 上色，从根上不做字符串替换。
**纪律：HTML 里做模板替换，占位符绝不能与 SVG/HTML 语法字符撞。**

另一条发散教训：第一页 10 个方案全困在「V 字母 + 单符号」框里，
等于让用户在同一个不满意方向上继续挑 ⇒ 再出方案必须**换设计语言维度**。

## 3. 做法

### 3.1 图标方案④（形态零改动）

只改 `res/values/colors.xml` 三值：底 `#3B5BC4` → `#1B2B63`、受光 `#FFFFFF` 不变、
折痕 `#B9C6F0` → `#7690D4`。启动页 V 按用户拍板**跟随图标色**（单一真源，不另建常量）。
同步 3 处文件头 + 真源脚本 `tools/icon/generate_launcher_icon.py` 注释；
更新 `Docs/assets/README.md` 里已废弃的三档渐变说明。

**陈旧残留**：`Docs/assets/vaultix-icon.png` 居然还是 09-30 的「蓝渐变 + 白盾 + 黑 V」，
README 却写「与 App 完全一致」⇒ 用 Java 按真源几何重绘为折纸 V（深蓝底 + squircle 圆角），
6.8KB → 8.3KB。

### 3.2 主题色 A 档 4 预设（commit `a81a6bf5`）

- 新增 `VaultixAccentPalette.kt`：`blue`（默认，直接返回原色板，零重复定义）/ `teal` /
  `slate` / `indigo`；只覆盖 primary / secondary 强调色与 fixed 角色，
  surface / error / tertiary 不动。色值用 HSL 脚本按门禁生成并逐对验算 WCAG
  （teal 主色压到 `#337C84` 让白字过 4.82）。
- 偏好层新增 `accent_palette` 键（函数数 32，未越 40 上限）；`MainActivity` 收集后注入
  `VaultixTheme(accentPalette = …)`，与 `dynamicColor` 二选一不叠加。
- 设置页「外观」新增「主题色」一行 → 四色单选对话框，色块直接取 `colorSchemeOf(...).primary`
  与真实渲染同源；动态取色开启时该行禁用（写了也不生效）。
- 门禁改法：默认档继承原蓝区约束，可选档用色相稳定 + 饱和度 + WCAG；
  新增 `VaultixAccentPaletteTest` 5 例（WCAG AA / 饱和度 / 默认档逐项相等 / 未知值回退 / 只换强调色）。

### 3.3 填充面板标识方案 B（commit `9d342dcd`，见主篇发版章）

取证发现盾+钥匙孔 `ic_autofill_vaultix.xml` 用在**三处**：面板 header 12dp、
认证行 24dp、库列表空态 72dp。四方案中选 B：折纸 V 单色剪影 + 接上明暗 tint。

- 几何取 `ic_launcher_monochrome.xml` 两块 path，按 V 外接框 34 → 16 缩放
  （`(x-37)*16/34 + 4`，`y` 同理），**不是**桌面三色缩小（白半在浅色面板会消失）。
  `strokeWidth 0.7` = 真源 1.5 同系数缩放。
- header 本来就接了 `iconTint()`（方案页初稿写错，读代码后纠正），
  真正漏的是认证行 `tintIcon=false` ⇒ 固定黑在深色面板 **1.23:1**，改 true 后浅 8.34 / 深 9.99。
- 库列表空态 72dp 自动跟随 primary ⇒ 三处品牌形态首次统一。
- 新增 `AutofillBrandIconTest` 4 例（几何反算 / 无盾牌残留 / 认证行接线 / 明暗对比度）。

## 4. 验证

- 图标几何门禁 **13 项全 PASS**（pathData 逐字符一致，确认只改颜色）；
  面板图标几何按同一公式反算逐顶点 PASS；XML 注释无连续短横线（aapt2 硬限制）。
- 色板独立编译 0 error；`VaultixAccentPaletteTest` 5 例全绿；
  `AutofillBrandIconTest` 4 例全绿。
- 变异反证：放松一处 fixed 对比度 / 面板顶点漂移 / 关 tint / 放松浅色 tint ⇒ 各自精确红后还原。
- CI 抓到两处本地漏检：`UiSize` 漏 import（detekt 与单测都不查跨文件引用，编译才报）、
  `ThemeDefaultRulesTest` 用已删的 `DarkColorScheme` 当源码边界锚点（截出空串误报）。
  ⚠️ 源码锚点必须跟着真实声明走；按「下一个 `fun`」截最后一个函数同样会截出空串
  （`buildFallback` 那次），改为锚定调用点实参。
