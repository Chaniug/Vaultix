## 三、两个反直觉的点（本篇最该记住的）

### 3.1 Dependabot alerts 对 Gradle 项目默认是半瘫的

alerts 读的是 GitHub 的**依赖图**；而 Gradle 的依赖版本在**构建期**才最终确定
（BOM、冲突决议、plugins、多模块），GitHub 无法静态解析 `build.gradle.kts` ——
官方明确说要靠 Dependency Submission API 补。

⇒ 只开 alerts 而不提交快照，会得到一个**空的安全面板**，并且容易误读成「我这个项目很安全」。

因此新增 `.github/workflows/dependency-submission.yml`（`gradle/actions/dependency-submission@v6`），
只在构建脚本变动时跑：改 Kotlin 源码不影响依赖图。

> ⚠️ 删掉它的后果不是「少一个 workflow」，是**第 2 项整体失效**。

### 3.2 CodeQL 对 Kotlin 不支持 `build-mode: none`

官方文档：Java 支持 none / autobuild / manual，**Kotlin 只有 autobuild / manual**。
Default setup 一旦检测到 Kotlin 就切 autobuild ⇒ 在 Android 项目上会跑 `./gradlew build`，
缺 SDK 平台包就挂，还会顺带跑 lint/test ⇒ **分析链因无关原因变红，
「红了」和「代码有问题」分不开**。

`reference/bastion/workflows/codeql.yml` 已踩过并写进注释，本篇直接沿用其结论，只改两处：
JDK 21 → **17**（本仓库用 17）、`assembleDebug` → **`:app:assembleFullDebug`**（本仓库多 flavor）。

另加一个 `languages: actions` 的 job：本仓库 workflow 里有大量手写 shell
（heredoc 生成 changelog、`find` 收 APK、base64 解 keystore），
2026-11-01 刚出过「两条 echo 写成一行、`bash -n` 判合法、页面照常生成」的事故（见 #226 同族）。
CodeQL 的 actions 查询能抓「未信任的 `${{ }}` 拼进 `run:`」「权限过宽」「action 引用未固定」，
这三类 `check_workflow_shell.py` 覆盖不到。

## 六、坑：这次踩到的三个（都不是业务代码）

### 6.1 `git commit` 在 partial clone 里会挂住

现象：`git commit` 无输出、90 秒超时；`GIT_TRACE=1` 显示它在跑
`git fetch origin --filter=blob:none --stdin` —— **提交时为了写 tree，去懒加载缺失的 blob**，
而网络上不去 ⇒ 永久挂起。

之后关掉 promisor（`remote.origin.promisor false`）再提交，报的是
`error: invalid object … for '.ai/archive/…'`（写 tree 需要校验每个条目存在）。

**唯一正确的解**：一次性把 blob 拉全，而不是逐个懒加载 ——

```bash
git fetch --refetch --filter=blob:limit=64m --no-tags origin +refs/heads/main:refs/remotes/origin/main
```

（≈28MB，单包；比逐文件懒加载快两个数量级。跑完 `git commit` 立刻正常，
`git diff` 也不再用等网络。）

### 6.2 别在这个仓库里随手 `git diff`

同理：`git diff` 要读旧 blob ⇒ 触发懒加载 ⇒ 看起来像「命令卡死」。
判读改动请直接读文件或 `git show --stat`。

### 6.3 连接器 Token 失效 ≠ 没有通道

`agent-gateway` 返回的 `ghu_…` token 被 GitHub 判 `401 Bad credentials`
（API 与 git push 都一样），但**仓库本身是公开的、SSH 也能认证** ——
「命令失败」和「权限不足」是两件事，先分清再决定要不要请用户重新授权。

### 7.1 ★ CodeQL「构建成功但提取为 0」= 构建缓存命中，不是构建失败

首跑报：

```
ERROR: CodeQL detected code written in Java/Kotlin but this run didn't build any of it,
or CodeQL could not process any of it. Ensure that you have provided manual build steps…
```

而**上一步 `Build for CodeQL extraction` 是 success** —— 这句话会把人往
「build-mode 配错了 / 缺构建步骤」的方向带，其实方向完全相反：

同 commit 的 `ci-debug` 早几分钟刚跑完，把 `:app:compileFullDebugKotlin` 的产物
暖进了 Gradle **build cache**；这一步直接 `FROM-CACHE` 还原 ⇒ **编译器根本没执行**
⇒ 提取器一个编译单元都拿不到。

**修法**：`--no-build-cache -Dorg.gradle.caching=false`，并把 job 级
`GRADLE_OPTS` 里的 `-Dorg.gradle.caching=true` 去掉（依赖下载缓存保留，那才是慢的部分）。

> 判据：**「Build 绿 + 提取为空」几乎必然是缓存命中**。
> 若真是 build-mode 配错，Build 那步通常自己就红了。

### 7.2 ★ 这个仓库的 Dependency graph 是**关闭**的

两条流水线当场给出同因：

```
Dependency Review     → Dependency review is not supported on this repository.
                        Please ensure that Dependency graph is enabled.
Dependency Submission → The Dependency graph is disabled for this repository.
                        Please enable it before submitting snapshots.
```

⇒ 「提交 Gradle 依赖图」这件事本身没问题（构建阶段全过、SDK 检测正常），
只差仓库设置里的一个开关。**这是设置项，SSH 改不了，必须人点**
（Settings → Code security and analysis → Dependency graph）。

顺带修正了本篇 §3.1 的因果链：不是「Gradle 静态解析不出来 ⇒ 图是空的」，
而是 **先有「图功能没开」这一层，再往下一层才是「Gradle 需要提交快照」**。
两层都要过，alerts 才会有内容。

### 7.3 顺手修的：`dependency-submission.yml` 的 `paths` 漏了自己

首轮它没被触发（本 commit 只改 `.github/**`，不匹配任何构建脚本），
于是「改了提交逻辑却看不到它跑」—— 与 #145.3「改了门禁、门禁不跑」同族。

### 9.2 本批最值得记的四条

1. **根组 uuid 是随机的**（#235）。把 `groupPaths` 喂进内容指纹时顺手把根组也算进去了，
   而 `KeePassDatabase.Ver4x.create` 每次给根组**随机 uuid** ⇒ 「同一份内容建两次库」指纹不同
   ⇒ 每次保存都判「内容过期」⇒ **用户一条都存不进去**。是 `KdbxWriteBaselineTest` 当场抓出来的。
2. **`nextExpectedRanges` 不保证只增**（#236）。它是「服务端缺口」不是进度条；拿它当进度会写出
   **错位的文件**（后一片覆盖前一片），KDBX 错一个字节就整库打不开。所以服务端超前时一律**夹回**。
3. **`0-` 有两种含义**（#236）。本地确认位也是 0 ⇒ 原地重发（会话是好的）；本地 > 0 ⇒ 会话被清。
   第一版一刀切判 Restart，于是**第一片就失败的库永远传不上去**。
4. **412 不能当网络抖动**（#236）。它是「远端不是你以为的那一版」，吞进续传会一直重试，
   一旦条件重新成立就**静默覆盖别人的改动**。

### 9.3 两个第一版用例本身是错的

| 用例 | 错在哪 | 换成什么 |
|---|---|---|
| 「子组上移一层，指纹必须变」（#235） | 路径字符串会变，而路径早就在 `folders[i].name` 里 ⇒ 测的是路径，**不是分组树**。变异停掉整段后依然全绿 | `folders` 完全相同、`groupPaths` 多一个同名节点 |
| 「第一片失败，必须续传」（#236） | 本地确认位是 0，**没有断点可续** | 第二片失败 |

> 教训：**变异之后仍然全绿，先怀疑这条用例没在测它声称的东西**，再怀疑编译。
