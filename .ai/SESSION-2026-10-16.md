## 一、bug 现象与根因

**现象**：KDBX 库新建一条**空备注的安全笔记**（表单备注字段可空，只填标题 +
自定义字段完全合法），保存时看着正常；退出再进 / 下次解锁，条目**变成登录**——
用户名/密码两行空字段杵在详情页，条目落进「登录」分类与筛选。

**根因**：KDBX **没有条目类型概念**（KeePass 标准五键里没有"这是安全笔记"），
`KdbxItemMapper.toVaultItem` 靠纯启发式推导：

```
无用户名 && 无密码 && 有笔记 ⇒ SecureNote，否则 Login
```

空笔记的安全笔记三个标准字段全空 ⇒ `isNote=false` ⇒ **类型静默翻转**。
写入侧从未把类型信息落盘，读侧自然无从恢复。
Bitwarden 侧类型是服务端显式存储字段，无此问题 —— 又是「两个库两种命运」。

## 二、修法：沿用 A1 的 `VPX_` 工具区模式，读侧三态

| 文件 | 改动 |
|---|---|
| `KdbxToolFields.kt` | 新增 `SECURE_NOTE` / `SECURE_NOTE_TRUE`；`isSecureNoteTrue` 与 `isFavoriteTrue` 共走私有 `isTruthyFlag`（宽松真值 `true`/`1`/`yes` 唯一口径） |
| `KdbxItemMapper.kt` | `isNote = fields.secureNoteMarker() ?: 启发式`；新增文件级私有扩展 `secureNoteMarker()`（大小写不敏感查键，同 `favoriteFlag`） |
| `KdbxItemWriter.kt` | 链上插入 `applySecureNote`：类型未变一字不动 / SecureNote 写 `"true"`（已是则不碰）/ 离开 SecureNote 删键（含大小写变体） |
| `KdbxItemWriterTest.kt` | 9 条新用例（见下） |

**两个刻意的设计决策**（KDoc 有完整论证，ISSUES #169 有摘要）：

1. **读侧三态，不压布尔**：`secureNoteMarker()` 的 `null` = 「没有标记」
   （第三方条目 ⇒ 回落启发式），`false` = 「标记显式为假值」（用户把安全笔记
   改成了登录型 ⇒ 信标记）。压成布尔就等于宣布「没有标记的条目都不是笔记」——
   第三方库里的安全笔记会一夜之间全部变成登录，**比原 bug 波及面更大**。
   这是 #121「三态压二值」的同款事故，本篇第二次撞同一堵墙。
2. **只写 `"true"` 不写 `"false"`**：收藏「缺失即假」是对的（没星就是没星），
   而类型**缺失不等于登录**——第三方工具写的笔记型条目靠启发式判安全笔记，
   KeePass 生态就是这个 convention。给每条登录镶一个恒假字段纯属噪音。
   代价：「Vaultix 自建的、只有笔记的登录条目」仍会被启发式判成安全笔记——
   该内容形态本身歧义，且与第三方工具的解释一致，可接受。

## 三、测试与验证

**9 条新用例**（`KdbxItemWriterTest`「安全笔记类型标记（A4）」节）：

| 用例 | 钉住什么 |
|---|---|
| 新建空笔记的安全笔记_读回仍是安全笔记（核心回归） | bug 本体 + 工具区不以自定义字段身份泄漏 |
| 新建带笔记的安全笔记_读回是安全笔记 | 标记与启发式一致时不打架 |
| 新建登录条目不写 VPX_SECURE_NOTE | 不产空字段 |
| 未标记的第三方笔记型条目_仍按启发式判安全笔记 | **兼容性闸**：升级不误伤第三方库 |
| 未标记的第三方登录型条目_仍是登录（反证） | 启发式没被改坏 |
| 第三方把标记写成 1_读回是安全笔记 | 宽松真值口径 |
| 标记显式为 false 时_即使是笔记型内容也判登录 | 三态的另一半：显式假值压倒启发式 |
| 未变更的类型不被重写（保持第三方写的 1） | 写侧纪律：一次无关编辑不改写用户库 |
| 更新空笔记的安全笔记_类型不翻回登录 | 更新路径同样闭环 |

**变异验证**（把 `secureNoteMarker()` 调用还原成纯启发式）：恰好 5 条 marker
相关用例报红，两条「无标记回落启发式」的兼容用例保持绿——正反两半都兜住。

**⚠️ 自记失误（本轮最大的一条）**：变异验证后还原时用了
`git checkout -- KdbxItemMapper.kt` —— 该命令从 **HEAD/索引**还原，
而 A4 读侧改动**从未提交**，被一并抹掉。紧随的复跑因此仍是 5 条红
（154 tests / 5 failed），与"还原后应该全绿"的预期矛盾——而
`grep secureNoteMarker` 无输出这个信号就在同一条命令里，被忽略了。
⇒ 纪律：**还原未提交的改动不能用 `git checkout -- <path>`**
（它按 HEAD 覆盖，不是"撤销上一步编辑"）；要么先提交再变异还原，
要么手工改回。复跑结果与预期矛盾时，**先怀疑还原动作本身**，
不要直接进去改代码。

**detekt 门禁补刀**：首轮全量门禁 `:data:kdbx:detekt` 报 1 处
`MaxLineLength`（新测试一行 154 字符）——此前只跑 `testDebugUnitTest`
没跑 detekt，漏了。教训：**"模块测试绿"不等于"门禁绿"**，
detekt / lint 要跟测试任务一起跑，别等 CI 报。修法：拆行 + 局部变量
改名（`item` 与函数内后文的 `item` 撞名，编译报 Conflicting declarations——
拆分长行时顺手检查作用域）。
