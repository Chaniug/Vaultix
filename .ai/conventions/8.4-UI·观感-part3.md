## 液态玻璃（Liquid Glass）—— 能做与不能做，都写清楚

| 能力 | 结论 | 为什么 |
|---|---|---|
| 半透明填充 + 上沿高光 + 内描边 | ✅ 做 | 纯绘制，任何版本都能画 |
| **实时模糊其后内容** | ✅ 做，**仅 API 31+** | 把内容区录进 `GraphicsLayer`（源），浮层再 `layer.renderEffect = blur` + `drawLayer(layer)` 画出来（消费）。**不是**给浮层自己的图层挂 `renderEffect` —— 见下面的 🔴 |
| 模糊背后的像素 | ❌ 不存在 | Compose **没有**这个 API。`Modifier.blur` 模糊的是**自己**绘制的内容，不是身后像素 |
| iOS 26 那种**透镜折射** | ❌ **有意不做** | 需把背景当纹理喂 AGSL `RuntimeShader`，`graphicsLayer` 拿不到可控采样源；硬做只剩 `PixelCopy` 逐帧回读 ⇒ 滚动帧率打穿 |

**唯一实现点**：`app/src/main/java/io/vaultix/vaultix/ui/glass/`
- `LiquidGlass.kt` —— 视觉参数（`object LiquidGlass`）、`LiquidGlassLayer`（浮层两层结构）、
  `drawGlass`（填充 / 上沿高光 / 内描边）、`isLiquidGlassBlurSupported` / `shouldApplyBlur`；
- `LiquidGlassSource.kt` —— **源 → 消费**机制：`rememberLiquidGlassSource()` /
  `Modifier.liquidGlassSource(…)`（源，录内容）/ `Modifier.liquidGlassBackdrop(…)`（消费，画糊影）。

> 🔴 **不要在别处再叠"半透明白色蒙层假装磨砂"** —— 会和真模糊互相打架，
> 表现为同一台机器上"有时糊有时不糊"，且极难解释。

### 🔴 第一版架构是错的（2026-10-27 真机截图证伪，详见 `.ai/issues/06` §198.1）

> **`RenderEffect` 模糊的是该图层的输出，包含它全部子内容。**
> 挂到"包住图标"的 Box 上 ⇒ **图标自己也被糊**，真机表现就是"按钮都看不清"。

✅ **必须分两层（兄弟节点，不是同一个 modifier 链）**：

```kotlin
Box(modifier) {
    Box(Modifier.matchParentSize().clip(shape).liquidGlassBackdrop(source, offset, r))  // 层 A：唯一带模糊
    Box(Modifier.matchParentSize().clip(shape).drawBehind { drawGlass(…) }) { content() } // 层 B：图标零模糊
}
```

层 A 只画"源被模糊之后的样子"，层 B 画填充/高光/描边 + 图标。填充与高光**必须画在层 B**：
写在层 A 会被同一个 `renderEffect` 糊掉（上沿高光那条细带会消失）。

### 四处**静默失效**陷阱（都不报错，只表现为"开关坏了"）

1. **源的子树里不能有不透明铺底**（`Surface(color=…)` / `Modifier.background`）：录到的是
   "子树自己画了什么"，铺底会盖掉底下的一切 ⇒ 录下一块纯色，模糊它等于没做。
   本项目 Tab 页背景透明（`VaultixTheme` 的 `Surface` 在更外层），而**顶栏是不透明 `Surface`**
   ⇒ 源必须挂在顶栏**下方**的内容区，不能含顶栏。
2. **层 A 必须 `clip(shape)`**：源录的是整块内容区，比胶囊高得多，不裁剪会把糊影画到胶囊外。
3. **填充 alpha 必须 `< 1f`（真模糊档）**：不透明填充把模糊结果整块盖掉。重构配色时最容易被顺手改坏
   ⇒ 单测 `真模糊档填充保持半透明且深色更实` 反向锁定。
   数值直接对齐 Haze `HazeMaterials` 的 `thin` 档（**浅 0.60 / 深 0.65，深色更实**）：
   深色背景更暗、模糊结果更接近黑，填充再薄就分不清"玻璃"与"背景"。
4. **降级禁止静默**：API 30 及以下没有 `RenderEffect`。开关打开却什么都不提示 = 用户认为功能坏了。
   ⇒ 设置页副标题换成「当前系统版本不支持实时模糊，将使用实色底栏」，
   且降级**直接画全不透明**（`FALLBACK_ALPHA = 1f`），不是"半透明 + 补偿"：
   半透明底栏浮在滚动列表上，条目会从图标之间透出来 ⇒ 读不清，那是"不可用"不是"不好看"。
   （Haze 对无模糊平台同样画 flat scrim。）

### 开关落地位置（用户明确指定）

设置 → **主题模式**组内、「OLED 纯黑」之后。命名 `liquid_glass_dock`，**默认关闭**。
偏好链：`VaultixPreferences` → `SettingsViewModel`（`StateFlow<Boolean?>`，**初值 null**，
遵守"布尔开关初值一律 null"契约）→ `SettingsScreen.DisplaySection` →
`MainActivity` → `VaultixApp` → `vaultEntryGraph` → `MainShellScreen` → `VaultixBottomDock`。

> ⚠️ **加穿透参数前先 grep"谁真正构造那个 Composable"**：`VaultixApp` 的真正构造点在
> 同文件的私有函数 `vaultEntryGraph` 里（本轮连报三次 `Unresolved reference` 才发现）。

> ⚠️ **两种外观必须共用同一份布局**：`VaultixBottomDock` 抽出 `DockRow`，
> 玻璃态与实体态只差外框。否则"同一规则写两处、只改一处"会让两种外观悄悄分叉
> （同 #120 / #193 / #195 的失败模型）。

### 🔴 2026-10-28 补：两条**硬纪律**（#200，整页变白那次事故）

1. **把子树接管到离屏 `GraphicsLayer` 时，必须先回答"屏幕上的像素由谁负责"。**
   `record { drawContent() }` 之后**必须** `drawLayer(layer)`（或 `drawContent()`）把内容画回屏幕。
   只录不画 ⇒ 没被浮层覆盖的区域**没有任何绘制命令** ⇒ 露出窗口底色（浅色主题 = 白屏），
   而 Compose **不报错**。判据：**"没人画"是露底色，不是"透明"**。
2. **一块 layer 只有一个 `renderEffect`，被谁消费就影响谁。**
   内容一旦靠 `drawLayer(contentLayer)` 回屏，模糊就不能再挂 `contentLayer`
   （会连屏幕那份一起糊）⇒ 模糊一律挂**独立的 effectLayer**
   （`record(源尺寸) { drawLayer(contentLayer) }` → 挂模糊 → 画到浮层）。
   源层永远干净，效果层永远只有一个消费者。

> ⚠️ 采样偏移的符号：`canvas.translate(offset.x, offset.y)` 用的是
> **`backdropOffset()` 的返回值本身**（源左上角 − 浮层左上角），**不是**它的相反数。
> 写反了不报错，只表现为"糊的是屏幕外一块空白"。已抽纯函数 + 单测钉住，别手写字面减法。

### 🔴 2026-10-28 补：第三条硬纪律（#205，底栏消失那次）

3. **`matchParentSize()` 的语义是「跟随父尺寸，且不参与父的尺寸计算」——
   一屋子子节点都用它，父容器就没人告诉它该多大。**
   `Box` 的测量源码（`foundation-layout` `Box.kt`）写得很直白：
   `var boxHeight = constraints.minHeight` → 只对 `!matchesParentSize` 的子节点
   `boxHeight = max(boxHeight, placeable.height)` → `layout(boxWidth, boxHeight)`。
   全是 `matchParentSize` ⇒ `boxHeight` 停在 `constraints.minHeight` = **0**，
   随后这些子节点本身也被 `Constraints(minHeight = 0, maxHeight = 0)` 测成 0 高
   ⇒ 再被 `clip(shape)` 裁一刀 ⇒ **整条底栏不可见，且没有任何报错/日志**。
   判据：**`matchParentSize` 只能用来"盖在别人身上"，不能用来"撑起父容器"。**
   每写一个都必须能指出"是谁在决定父尺寸"；指不出来就是 0。
   （同族写法见 `PressAndSwipeToDelete` / `ItemsScreen`：那两处父 Box 都有正常子节点。）

### 换组件 / 换底色 / 换标题字号：2026-11-09 三条定案

#### 1. 换用标准 M3 组件前，先逐项对默认值

迁详情页字段行（手写 `Row` → `ListItem`）时踩到：组件带着它自己的默认值，
而本页已有一套真机验证过的规格，不改就会**静默**改变观感。

| 属性 | M3 默认 | 本页规格 | 不改会怎样 |
|---|---|---|---|
| `overlineContent` 字号 | `labelSmall` 11sp | `labelLarge` 14sp | 退回 2026-11-07 已否决的层级 |
| 容器色 | `surface` | `Color.Transparent` | 每个字段行在卡片上变成一条白条 |
| `TextField` / `OutlinedTextField` 容器色 | 跟随 surface 家族 | 视宿主而定 | 同上，出现比宿主更亮的矩形 |

⇒ **"换成标准组件"≠"白拿标准行为"**。迁移清单里必须有一列"默认值 vs 本页规格"。

#### 2. 容器底色按「要不要从栏下穿过」选，不按「两页该不该一致」选

实测亮度比（vs `surface`，M3 亮色基线）：

| 色档 | 亮度比 |
|---|---|
| `surfaceContainerLow` | **1.049**（肉眼等同同色） |
| `surfaceContainerHigh` | 1.164 |
| `surfaceContainerHighest` | **1.232** |

- **有沉浸式顶栏、内容会从栏下滑过**的页面（表单全屏页）⇒ 必须 `Highest`。
  2026-09-20 用户反馈「不透明，上边标题部分遮住了显示内容」，根因就是 `Low` 与栏同色。
- **没有这个需求**的页面（详情页）⇒ `Low`，保持轻。

⚠️ 两页底色不同是**有意的**，别再以"统一"为由改回去。
⚠️ 这条曾被写成"统一到 `Low`"并拍板，后来把上面这组数字摆出来才推翻 ——
**提案里凡写"会改变观感"，先去代码注释里找实测数据**；把一个可以算的问题
交给印象判断，是提案的失职。

#### 3. 分区标题的职责是分层，不是强调

详情页最多 9 张卡，9 个 16sp `primary` 标题同时喊"看我" = **整页没有重点**，
用户扫视时先看到九个彩色标题而不是他要的用户名与密码。

- 现规格：`titleSmall`(14sp) + `onSurfaceVariant`
- **图标保留 `primary`** —— 它是唯一的彩色锚点；去掉后整页只剩灰阶，
  而卡片描边只有 0.5dp `outlineVariant`，分区边界会彻底消失
- ⇒ 一页**只有分区标题的图标是彩色**

⚠️ 与 2026-09-13「小标题稍微大一点」方向相反，是用户在看到"九个主色标题互相稀释"
的证据后**重新拍的**，不是擅自改口。
⚠️ 表单页的 `SectionLabel` 仍是整行 `primary`，不适用本条：表单卡少（3 张），
且卡内需要强分组。
