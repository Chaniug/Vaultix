# 8.11 七类「不报错的错」—— 各自需要不同的门禁（2026-11-01 沉淀）

> 回答什么问题：**为什么门禁全绿、包也对，内容却是错的**？每类错该配什么门禁？
> 来源：2026-11-01 一轮内连续踩到七种判据，从 `MEMORY.md` §9.0 拆出（8.9 §7.1 篇 ≤300 行）。
> ⚠️ 这是**判据篇**，不是状态篇 —— 现状见 `.ai/README.md` 顶部。


这一轮连续踩到七种「**门禁全绿、包也对、只有内容错**」的错，性质各不相同：

| 错误形态 | 为什么门禁抓不到 | 该配什么门禁 |
|---|---|---|
| 两条命令挤一行（#218.3） | `bash -n` 只验语法；`echo` 参数变多仍合法 | 扫描 workflow 文本形状（`check_workflow_shell.py`） |
| 同一口径两份实现（#218.2） | 两边各自都对，只是不一致；只在页面显示错数字 | 从**真源**抽实现来对账（`selftest_version_code.py`，16 例） |
| 兜底路径从没跑过（#218.4） | 主路径成功时兜底根本不执行 | **让主路径失败的测试**（`selftest_apk_signer.py`）+ 变异测试 |
| **两端协议对不上**（#218.8） | workflow 与 gradle 各说各话，**两边单独看都没错** | 跨文件抽名字求交集（`check_signing_var_names.py`）+ 对着已知坏状态验它判红 |
| **能力只接了一侧**（#219） | 「支持某类条目」被拆成写侧 / 读侧两半，**只补一侧时两边各自都能跑通**：写侧单测断言字段存在（绿）、读侧对空数据不报错（绿） | **往返测试**（`Item → KDBX → Item` 全字段相等），且改哪侧都要跑同一条 |
| **赋值时机晚于使用点**（#220） | 接缝「构造后赋值」，而 `init` 在构造期间读取 ⇒ 守卫条件**恒为真**，注入从未生效；CAS 守卫又让随后那次 `startObservers()` 静默返回。**不报错、不告警、测试还绿** | 接缝放进**构造参数**；再加一条**正面断言**（"构造后、自启前 `observersStarted == false`"），并用**变异**（改回无条件启动）验证它会红 |
| **结构合法、语义丢失**（#221） | YAML 把 `files:` 吃进 `body:` —— **语法完全合法**，解析器接受的是一行更长的文本，`with.files` 这个键**不存在**；action 走「没有 files」分支，建 release、不传文件、退出码 0。五道关卡全绿（`bash -n`、yaml、artifact 上传、metadata、Publish 结论），**只有点进 Assets 才看得出是空的** | 静态检查「键是否真的解析出来了」+ `fail_on_unmatched_files: true`，更根本的是**去读副作用的结果**（`assets > 0`）而不是读步骤结论 |

> **判据**：每加一条兜底，就要加一个能让主路径失败的测试。
> 否则那不是兜底，是一段"看起来像兜底"的代码 —— 它只在事故发生时才被告知是没用的。
>
> **判据（第 5 类补）**：「领域模型有字段」「DTO 有字段」「写侧写了字段」三者**都不等于**
> 用户能用上。密码管理器的"支持"一词必须以**往返**为证 —— 写进文件却读不回来，
> 是最难发现的一种丢法（文件里躺着、界面上没有、日志全空）。
>
> **判据（第 7 类补）**：**「命令成功」不等于「副作用发生」。** 退出码 0 只说明程序没崩。
> 凡是带外部副作用的步骤（发 Release、上传产物、推镜像、发消息），验收标准必须
> **去读副作用的结果**（`gh release view --json assets` 的数、远端对象的 etag、收件箱里
> 真有一封），而不是「这一步的结论是绿的」。日志里那句 `Uploading asset` 的有无，
> 比 21 个绿色对勾更能说明问题。
>
> **判据（第 6 类补）**：**接缝的赋值时机必须早于「用到它的第一个协程」**。
> `init` / 属性初始化块 / `apply {}` 全都在构造期间跑 —— 任何「构造后赋值」对它们
> 都**等于没设**。这类失败最贵的地方在于：它让后面所有"确定性等待"变成错觉
> （`advanceUntilIdle()` 推的是一条没人用的时钟），测试因此**看起来**在验证，
> 实际只是在自证。
>
> **判据（第 4 类补）**：「配置写下来了」不等于「配置被读走了」。凡是跨进程/跨工具的协议
> （环境变量名、gradle 属性名、文件名），两端必须各有独立来源，并配一条**能对着已知坏状态
> 判红**的检查 —— 门禁写完先在"已知会失败"的状态下跑一遍，看到红，才算它能用。

本轮实例：`apksigner` 不在 runner PATH 上、`META-INF/*.RSA` 对 v2 签名包不存在，
两条路同时落空，功能上线但**零作用**，页面一直显示「未能读取」。
