### 新纪律 1：**「按钮高度」不是需求，是规格**

改前主 CTA 有 **40 / 48 / 56** 三种视觉高、**filled / tonal** 两种填充，共 9 种写法。
**2026-10-19 已收敛**：`ui/common/PrimaryActionButton.kt`（`toned` 切填充，
`height` 默认 `PRIMARY_ACTION_HEIGHT`=48dp，`AddKdbxScreen` 传 `PRIMARY_ACTION_HEIGHT_TALL`=56dp）。
⇒ **新增主按钮前先找 `PrimaryActionButton`**，不要就地写 `height(...)`；
这一条与第 ⑤ 条（触摸目标 ≠ 视觉高度）是一条纪律的两半。

> 🔴 触摸目标补法：`IconButton` 用 **`Modifier.minimumInteractiveComponentSize()`**，
> **不要**手写 `heightIn(min = 48.dp)` —— 后者会把 `IconButton` 的水波纹一起拉大。
> `heightIn(min)` 只对自绘 `clickable` 容器是对的（那种地方本来就没有水波纹要保）。

> 🔴 **`MatchingDeclarationName` 拦得住"组件 + 它的枚举"**：detekt 要求一个文件**只能有一个**
> 非 `private` 顶层声明且文件名与它同名。**挪文件不解决**（这条规则按"非 private 顶层声明"算，
> 换文件名只是把矛盾换个地方）。要么把辅助类型改成 `private`/内嵌，要么换成 `Boolean`
> 或内嵌 `sealed`。这轮因为这件事连踩两次，记死。

### 新纪律 2：**「让位高度」必须调函数，不许写字面量**

`VaultListScreen` 曾把底栏让位写死 `96.dp`，而真实需要 `86dp + 字体增量 + 手势条`（≈118dp）
⇒ 4 键手势机下最后一条被压住。**2026-10-19 已函数化为 `rememberBottomDockInset()`**：
占位 `BottomDockOccupiedHeight`(86dp) + 字体增量（`DOCK_MAX_FONT_GROWTH`=16dp 按
`(fontScale-1f).coerceIn(0f,1f)` 线性插值）+ `WindowInsets.navigationBars`。

这是本文件 §「`contentPadding` 不做外层 padding」的**同族错误**：
知道要让位、但把"让多少"当成了常量。

> **判据（三项缺一都不行）**：让位 = **占位高度 + 字体增量 + 系统内边距**。
> 漏字体增量 ⇒ 2.0x 下压住；漏系统内边距 ⇒ 新手势机压住；漏占位 ⇒ 全都压住。

> 判据：凡是能写成 `rememberBottomDockInset()` / `rememberImmersiveBarPadding()` /
> `rememberQuickFilterRowInset()` 的，**一律不写字面量**。

### 新纪律 3：**自绘组件的语义不是可选项**

改前 `grep "Role.Tab"` = **0**，而底栏 4 个 tab 全是自绘 `clickable`。
**2026-10-19 已补 5 处**：底栏 tab（`Role.Tab`+`selected`）、`DisplayOptionsSheet`、
`SettingsComponents.SingleChoiceRow`（`Role.RadioButton`+`selected`）、
`ItemsScreen` 分组折叠（`stateDescription`）、`AddCloudVaultScreen` 账号列表（`Role.RadioButton`，
**不加 `selected`** —— 那里确实没有选中态）。
⇒ 「观感」这个词里包含**读屏用户看到的观感**；这几个不是审美问题，是功能缺失。

> 🔴 **`role` 与 `selected` 是两件事**：`clickable(role = …)` 只改**播报措辞**，
> **不带选中态**。要读屏说"已选中"，必须显式 `semantics { selected = … }`。
> 自绘组件两个都得自己写，`clickable` 一个都不给。
> `contentDescription` 同理：内层 `Icon` 要给 `null`，否则与外层 label 重复播报。

### 新纪律 4：**没有 `@Preview`，观感迭代就是装包 × N**

改前全项目 `@Preview` = **0**，而 `.ai/ISSUES.md` 里"观感"类反馈的修法几乎全靠真机截图。
**2026-10-19 基建已落地**：`ui/preview/`（`PreviewCanvas.kt` + `ComponentPreviews.kt`），
已覆盖 `VaultixBottomDock` / `EntryCard` / `SettingsRow` 三个规格中心，11 条。
⇒ 动到"规格中心"（`EntryCard` / `SettingsGroupCard` / 顶栏 / `VaultixBottomDock` / 空态 /
主 CTA），**顺手补一个 `@Preview`，并至少带 2.0x 档 + 深色档**。

> 🔴 **字体档必须覆写 `LocalDensity.fontScale`，设 `textSize` 是假的**：
> 只有前者才走到 `sp → px` 那条路径，才能验证 `rememberBottomDockInset()` 读
> `LocalDensity.current.fontScale` 的补偿逻辑。用 `textSize` 只能看"字会不会挤出边框"，
> 看不到"布局有没有把字体增量算进去"。
>
> 🔴 Preview 里 `VaultixTheme(dynamicColor = **false**)`：真机开了 Monet 后颜色随壁纸变，
> Preview 是给"规格"看的，颜色必须可复现。

### 顺带纠正一条旧口径

本文件此前没有区分**「间距」与「圆角」两套标尺**。间距走 `Spacing`（8dp 标尺），

## 2026-10-21 增补：三张「尺寸表」的分工 + 文案哨兵

### 新纪律 5：`Spacing` / `VaultixCorner` / `UiSize` 是三件事，别混

| 表 | 回答的问题 | 判据 |
|---|---|---|
| `Spacing` | 两个元素**之间**留多少 | 它在两个东西**中间** |
| `VaultixCorner` | 元素**外轮廓**有多圆 | 看它有多高（分档不按组件） |
| `UiSize` | 元素**自己**有多大 | 它是**独立存在**的图标 / 进度圈 |

⚠️ **`UiSize` 里 18 与 20 并存是历史事实，不是重复**：18dp 基本只在 `TextButton`
的默认图标槽内（**不改按钮高度**），20dp 用于标题旁 / 独立图形。判据 = **它和谁并排**，
不是"哪个更常见"。合并这两个值会在某一类位置上让按钮变高或让图标显小。

⚠️ `Spacing` 纪律里那条「**不在标尺上的值保持字面量**」有边界：它只在
"每个字面量都是**独立的版式决定**"时成立。一旦同一语义的值在几十个文件里反复出现
（本轮实测：18dp×26 文件 / 20dp×18 / 6dp×19 / 2dp×19 / 10dp×6），它就已经是**语义**了，
该升级成常量 —— 否则"调整一档"要改 80 处。

### 新纪律 6：文案双源有门禁了 —— `check_ui_hardcoded_text.py`

改前 `strings.xml` 没有那些中文，而 `check_orphan_strings.py` 查的是**反方向**
（"资源定义了没人用"）⇒ **Kotlin 里写死的中文是盲区**。

现在补上了正方向的门禁：`python3 .ai/tools/check_ui_hardcoded_text.py`
（自检 `--selftest`，5 条）。判据不是"禁止中文"，是"**禁止未登记的中文**"：

| 用途 | 处理 |
|---|---|
| 日志 / `error(` / `checkNotNull(` / 注释 KDoc | 自动放行 |
| `ui/preview/**` 整目录 | 豁免（示例数据永远不上屏） |
| 其它 | 进 `strings.xml`，或登记进 `.ai/tools/ui_text_baseline.txt`（三列必须写"为什么不进资源"） |

> 🔴 **写基线时最容易踩的坑**：特征串是拿在「**引号之间的内容**」上做 `in` 判断的，
> **不是整行代码**。写成 `FALLBACK_TITLE =` 会永远不命中，而三列齐全、脚本不报错
> ⇒ 表现为"登记了但没用"，极难自查（2026-10-21 踩过）。正确写法是 `验证码`。

> 🔴 **同一文件里两处字面量内容相同时，一条特征串会同时放行两处** —— 原因列要把两处都写清。

### 文案双源的正确修法：三类「Res / Detail」封了同一个判据

本轮把「我们自己写的」与「来源层已翻译好的」在类型上分开，四处同一判据：

| 类型 | 用在哪 | 为什么另起一个 |
|---|---|---|
| `UnlockUiError.Validation` + `validationTextRes` | 解锁 / 添加库 | 复用已有范式，扩展枚举即可 |
| `CloudError` | 网盘账号 | `Res` 映射的资源集合不同 |
| `QuickUnlockText` | 快速解锁对话框 | 需要**格式化参数**（剩余次数、位数） |
| `SyncNotice` | 同步 / 删除的结果提示 | 跨 `vaultlist` 与 `settings` 两包复用 |

> 🔴 **判据**：**这句话是不是我们自己写的？** 是 ⇒ `Res`（必须进 `strings.xml`）；
> 来源层已经翻译好 ⇒ `Detail`（原样透传，**不要套前缀**，否则变成「操作失败：主密码不正确」）。
> 想抽公共抽象前先问：除了"有 Res 和 Detail 两个分支"，它们还有共同行为吗？**目前没有。**

> 🔴 **`data class` 里不要用 `vararg`**：会退化成数组引用比较，`copy()` 后判不相等。
> 用 `val args: List<Any>` + 外部 `text(id, vararg)` 便捷构造。

### 兜底文案的位置：**能在 UI 层兜，就别在 ViewModel 里兜**

三个 ViewModel 曾各自写 `error.message ?: "未知错误"`。正确做法是事件字段改
`message: String?`，**原样传 null**，由 UI 在拼模板时换成 `error_unknown_no_detail`。
理由是「异常没细节时说什么」是**呈现决定**，而文案只有一个家。

### 非 Composable 的共享层拿不到资源，不代表可以写死中文

`LocalUnlockFanout` 拿不到 `Context`，于是"镜像"了一份中文字面量，注释写着
"与另一处措辞必须一致，靠 review 守" —— 那就是**靠人守的双源**。
正确形态：共享层只产出**带资源 id 的枚举**（`LocalUnlockMessage`），解析交给有
`Context` 的调用方。**"拿不到 `Context`"不是写死中文的理由。**

## 2026-11-09 增补：**「未知」必须显式建态，而且必须进分支条件**

### 新纪律 7：延迟只能加在"表现"上，不能加在"状态判定"上

详情页抓到的这一帧：「点进条目闪一下『此条目不存在或已删除』」，**两种库都中**。

```kotlin
when {
    showProgress && item == null -> 转圈   // showProgress 要等 120ms 才为真
    deleting -> Unit
    item == null -> Text("条目不存在")       // ← 前 120ms 全落这里
    else -> 内容
}
```

判据其实早就写对了（`itemLoaded` 区分"还没解出来"与"确实没有"），`loading` 也作为
参数传进来了 —— **但它没出现在任何分支条件里**，只被当作转圈延迟的开关。
于是"未知"这个状态在 UI 上根本不存在，空值直接落进了"确认没有"。

⇒ 三条判据：

1. **未知态是一个显式分支，且排在最前**，从第 0 帧就成立，**不吃任何延迟**；
2. 防闪烁的延迟（`DETAIL_PROGRESS_DELAY_MS = 120`）只能决定"要不要画 spinner"，
   **不能决定"这算哪个状态"** —— 状态机不能跟着表现延迟；
3. 未知态要**占住内容位**（`DETAIL_UNKNOWN_MIN_HEIGHT`），并把顶栏让位与真实内容对齐，
   否则内容到达时会出现「先缩后撑」的二次跳变。

### 新纪律 8：未知态**不画文字**，也不画骨架屏

- 画「加载中」= 把一次 50ms 的缓存读取说成"正在加载"，比闪一帧更吵；
- 画骨架屏需要先知道条目类型 / 字段数，而这时**恰恰还不知道**，猜错反而更显眼。

⇒ 空白占位 + 真慢（>120ms）时才叠转圈，是唯一不自相矛盾的形态。

### 新纪律 9：给"删除 / 低价值内容"降级时，先问它的视觉重量对不对

- 时间戳原本整张卡片 + 分区标题，与「网址」「备注」同等重量 —— 降成页脚一行小字；
- 网址超 3 条折叠，其余收进「另外 N 个网址」（渐进披露，**不排序不去重**）；
- 设置行图标必须**顶对齐标题行**，整行垂直居中会让并排的两行图标上下跳。

### 新纪律 10：**"删掉元素"能解决拥挤，但会制造空旷**

⋮ 菜单的同步 / 锁定一天改了四轮：合成一栏 ⇒ 各占一行 ⇒ 同步只异常时出现 +
锁定缩右下角 ⇒ **定稿 `[灯] [同步] ←weight→ [锁定]`，全部不写字**。
第三轮把常态那颗绿点一起藏了，用户原话「孤零零的，也没有颜色灯」。
⇒ 拥挤时先试"元素保留、文字去掉"，再考虑删元素；**状态词交给顶部横幅，菜单里不复述**。
详见 [`SESSION-2026-11-09.md`](../SESSION-2026-11-09.md) §4.3。
