## 踩坑（本轮新增）
1. **`stringResource()` 不能用于 `LaunchedEffect`/协程体内**（非 Composable 上下文，
   编译直接报错）：改用 `LocalContext.current.getString(...)`，文案仍留在资源里
2. **`when` 作表达式返回值时（executeOperation 返回 CipherResponse?）必须穷尽或 else**：
   字符串常量分支（"CREATE" 等）不满足穷尽性，补 `else -> null`；未知 op 按成功移除，
   防毒丸条目卡死整条队列（重试会无限重发）
3. **改动 Room entity 必须同步 version + Migration**（v1→v2 ALTER TABLE ADD COLUMN），
   DatabaseModule 挂 `.addMigrations()`；本项目禁 fallbackToDestructiveMigration
4. `data:repository` 分类 401/400 需要 retrofit 类型 → 补 `libs.retrofit.core` 依赖
5. 读 `HttpException.response()?.errorBody()?.string()` 分类 two_factor 时 body 只可读一次，
   注意放最后
6. `VaultItem` 补字段用**命名参数**构造（本轮全仓库仅 3 处 VaultItem( 且均为命名参数，

  paths 增加 `config/**`

## 清零过程踩坑
1. **Compose PascalCase 误报 FunctionNaming** → `naming:FunctionNaming: ignoreAnnotated: ['Composable']`
2. **UI 数字噪音** → `style:MagicNumber: ignoreNamedArgument: true`（命名参数如 height=48.dp 放行，
   裸位置参数仍查）；但 `coerceAtMost(24)` / `delay(2_000)` 之类要真改常量

## Vaultix 落地（差异与简化）
- **档位**：`VaultixPreferences.autoLockTimeoutMs`(ms) → **`autoLockMinutes`(Int)**：
  0=立即 / >0=N 分钟（默认 5）/ <0=从不。**-2（重启后锁定）不需要**：Vaultix 对称
  密钥只在内存，进程重启天然锁定
- **`AutoLockPolicy`**（app/security，纯函数可单测）：lockImmediatelyOnBackground(0) /
  backgroundTimeoutElapsed(now, since, minutes) / screenLockRequiresRelock / neverAutoLock
- **`AutoLockController` v2**：onStop：档位 0 → 立即 lockAllNow，否则记 backgroundedAt；
  onStart：keyguard 仍锁 OR 超时 → lockAllNow + lockEvents 代次回根
- 单测：app/src/test/.../AutoLockPolicyTest（4 用例，:app:testFullDebugUnitTest）

## 本轮大坑：Hilt 构造期依赖环（此前潜伏）
- 现象：`:app:hiltJavaCompileFullDebug` 报 `OkHttpClient ↔ Retrofit.Builder` cycle
- 根因链：OkHttpClient→Authenticator→TokenRefresher→BitwardenAuthRepository→
  ApiFactory→Retrofit.Builder→OkHttpClient。这条环在 M1 接入 401 刷新时就存在，
  但 Hilt 只在依赖图被**入口展开**时检测：此前无注入点消费该链（app 编译靠
  hiltJavaCompile 缓存/未展开所以全绿），第四轮 AutoLockController 注入
  VaultRepository→SyncService→ApiFactory 全链暴露
- **断环**：`BitwardenAuthenticator(refresher: Provider<TokenRefresher>)`——
  Authenticator 构造不再触发 refresher 求值，真正 401 回调时才 `provider.get()`，
  彼时认证仓库必已构造完成（懒断环，别用 eager 断环会死锁）
- 教训：Hilt 环可能在「新注入点出现」时才炸；依赖链设计时就要识别
  client→auth→client 型自环
