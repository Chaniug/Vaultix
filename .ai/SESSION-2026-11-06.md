## §2 液态玻璃光学层（第二批）

**回答「折射必须每帧 `toImageBitmap()` 回读吗」——在 API 33+ 不必**

调研来源：FlClash 的 UI 在独立子模块 `chen08209/prism_ui`，玻璃靠
`shaders/liquid_glass.frag` + `LiquidGlassHost` 的**一次降采样共享捕获**完成；
底栏 `NavigationDock` 另有可拖动 lens、弹簧与 goo 融合（**本轮不搬**）。

旧 KDoc 断言「折射要把背景当纹理喂给 shader ⇒ 每帧 GPU→CPU→GPU 回读」。
`createRuntimeShaderEffect` 让 AGSL 直接采样 RenderNode 内容，再
`createChainEffect(模糊, shader)` 串起来，全程留在 GPU——正是
「一次捕获共享」的 Compose 版，而 `LiquidGlassSource.effectLayer` 就是那张共享图。

| 系统 | 链路 |
|---|---|
| ≥ 33 | 模糊 → AGSL 边缘折射 / RGB 分色 / rim 暗线 / 高光 |
| 31–32 | 仅模糊（观感由静态装饰补足） |
| < 31 | 无模糊，`liquidGlassStyle` 给不透明实色 |

**做法**：新增 `ui/glass/LiquidGlassOptics.kt`（shader 与链对象进程级缓存、每帧只设 uniform、
失败**钉住降级**避免每帧重试抛异常）；`LiquidGlass.kt` 补所有版本生效的上沿 1dp 折边 +
下沿 rim 暗线并更正旧 KDoc；`LiquidGlassSource.kt` 传胶囊在源坐标系的 `Rect` 并改用
`glassRenderEffect`。**零新动画**。

同批设置页：两处 `AlertDialog(text = 长文本)`（关于开源许可 / 自动填充磁贴提示）
收敛为 `LongTextInfoDialog`（限高 + 自带滚动 + `bodyMedium` + 单一「关闭」）。
**刻意未动**：设置分组结构（有 IA 定稿）、`VaultActionResultDialog` 的「完成 / 关闭」分流
（KDoc 说明失败结果不能写「完成」——先取证才没误改）。

**验证**：`e5a77947` 首轮 detekt 报 `rect[3]` 的 `MagicNumber` → 改传 `Rect` 的
`22e56c09` 全链路绿（4m16s、编译通过）。`a0c676ef` 把文档「进行中」写实。

⚠️ **未验收**：AGSL 字符串是**运行时**编译，CI 编译门禁覆盖不到；失败自动退回
「仅模糊 + 静态装饰」，不崩。真机需看折射是否生效与滚动帧率。

## §3 设置页：开关闪烁 + 弹窗规格（第三批）

**回答「开关为什么闪一下才停」「弹窗为什么又大又简陋」**

**开关双因**（「锁与安全 → 进入 App 时仍需验证」）：

1. `stateIn(initialValue = true)` ⇒ 实际为「关」时首帧假开再跳变；
2. 写入走 `writeScope.launch` 异步，而 `Switch` 是**受控组件**，落盘前 `checked`
   仍是旧值 ⇒ thumb 回弹一次。

修法：`StateFlow<Boolean?>` + `null` 初值（未读出由 `SettingsSwitch` 画同尺寸占位，不猜）；
`combine` 乐观值即时上屏，`first{}` 等落盘回流后撤销，`withTimeoutOrNull(3s)` 兜底，
连点取消旧 `Job`；副标题同步改为「不确定就不显示」。文件：`SettingsViewModel.kt`、
`UnlockMethodScreen.kt`。

**弹窗三项规格**（`ui/common/DialogShell.kt`）：

| 问题 | 原因 | 改法 |
|---|---|---|
| 又大 | `fillMaxHeight(0.8f)` 写死，KDoc 还把「内容少也是大面板」当优点 | `wrapContentHeight` + `heightIn(max = 520.dp)` |
| 按钮没边框 | 三个语义按钮全是裸 `TextButton` | `OutlinedButton` + 新增 Primary(filled) / Secondary / Danger |
| 版式层级 | 标题 `titleLarge`、动作区贴底 | `headlineSmall`、动作区补下边距、PIN 完成补静态成功图标 |

`AddVaultTypeDialog` / `ReportDialog` 两处 `weight(1f, fill=false)` 随之改成
`heightIn(max)` + `verticalScroll`（**顺序不能反**，见 `UpdateNotesBox` 的教训）。
PIN 修改 / 关闭 PIN / 忘记 PIN / 逐库主密码 / 文件夹保存 / 添加库类型弹窗统一套用。

⚠️ M3 原生 `AlertDialog` 默认动作本就是无边框 `TextButton`：这次不是「补 M3 标准」，
而是按用户要的视觉重量改用 M3 组件体系里更明确的 outlined + filled 组合。

**验证**：`7c1428df` → `42205962679` 全绿（4m30s、编译通过），文档门禁绿。

**回答「下次遇到同类问题先问什么」**

2. **状态文字会过期**：「待 CI / 进行中」写进文档前先向远端取证，收工再写实一次。
3. **前置门禁红 ⇒ 后续 skipped 步骤不算通过**，别被「没编译」误导成没改代码。
4. **「一致性」不能凌驾于内容比例**：写死大面板让短弹窗显得空，自适应 + 上界才对。
5. **先取证再动刀**：本轮两处「看起来该统一」的地方（结果弹窗文案分流、设置分组）
   读注释后发现是有意设计，改了就是回归。

7. 本机 heredoc 跑 Python 会被这台 bash 解析坏 ⇒ 落临时 `.py`（`build/` 已忽略）再执行，

## §6 弹窗与按钮：三张真机截图驱动的规格收口

**回答「主按钮为什么被裁成一条竖条」「同页卡片为什么比表单窄」「按钮为什么像没做」**

| 截图 | 实证 | 根因 |
|---|---|---|
| 添加密码库 | 第三张卡副标题被截、窗口拥挤 | 滚动区 `heightIn(max=320.dp)` 小于「提示 + 三张 76dp 起跳、副标题 2~3 行」总高 |
| 修改 PIN | 「继续」只剩屏幕右边一条浅紫竖条 | `DialogActions` 是单 `Row`，三按钮 + `weight` 空隙超出可用宽度 |
| 网盘账号 | 卡片比下方输入框窄一圈 | 卡片自叠 `start=24dp/end=16dp`，表单只有外层统一 `24dp` |

**做法（先减法后加法，8.4 纪律）**：

- 添加库：卡片 76→56dp、上下内边距 12→8dp、卡间距 4→3dp；副标题限一行并精简
  4 条文案；提示句不再复述三个选项的分类。缩完三卡总高远小于滚动上界，裁切消失。
  上界**保留**——`verticalScroll` 拿无界高度会在 measure 阶段抛异常。
- 颜色区分按用户提议做，但**只落在 28dp 图标槽**（primary / secondary / tertiary
  三档 container），卡片底仍统一 `surfaceContainerLow`：整卡换色会变成三块彩色积木，
  也破坏「嵌套容器必须换档」的色阶纪律。
- `DialogActions`：`Row` → 可换行 `FlowRow`，删掉 3 处 `weight` Spacer；
  六个语义按钮统一 `contentPadding(16dp, 8dp)`。放不下就换行，任何字号 / 按钮数都不裁。
  破坏性动作仍排最前 + danger 色，换行时自成一行，与返回 / 继续分开。
- 网盘账号：去掉卡片与分组标题各自多叠的水平 padding，同页统一由外层 `24dp` 控制。
- 按钮规格：settings 目录与共用弹窗外壳共 **39 处**裸 `TextButton` → `OutlinedButton`；
  `DialogSectionTitle` 标题 `labelLarge(14sp)` → `titleSmall(16sp)`，修正
  「小标题比输入框 label 还小」的层级倒挂。

**判据**：① `Row` 装可变数量按钮 ⇒ 溢出是必然而非偶发，要么换行、要么减到两个；
② `verticalScroll` 必须有上界，但上界要按**缩小后的内容**重算，写死必然裁尾；
③ 同页两套水平边距是「宽度不匹配」最常见的来源，先量再改；
④ 用户说「用颜色区分」时，先用图标槽而不是整卡验证，避免彩色积木。

**刻意保留**：页面内行内低强调按钮（条目表单 / 列表页等 16 个文件）仍用 `TextButton`
—— 它们不是弹窗动作，全加边框会喧宾夺主。玻璃文件本批仍未改动。
