## 二、逐条修法（细节在 ISSUES #164–#167 + 04 篇 #161）

### B6 通行密钥写回（`de0ab2e`）

`updateFido2Credentials` / `removeFido2Credential` 去掉一刀切拒绝；
解锁校验改双会话模型各问各的；`loadItem` 增 KDBX 分支（回收站在 `trashItems`，
`items` 取不到即「不存在」）；写回经 `updateItem` 既有分流委托
`KdbxItemRepository`。`requireNotKdbx` 收缩为只剩「旧孤儿行回收站清理」
（`PASSKEY_READ_ONLY_REASON` → `KDBX_TRASH_CLEANUP_REASON`）。
详情页文案「由服务器 / 平台管理」→「不可编辑」。

### A1 收藏读写（`f2a4e03`）

落 `VPX_FAVORITE` 工具区（候选方案逐个否决的记录在 `KdbxToolFields.FAVORITE` KDoc：
Tags 用户可删 / 自定义字段名撞名 / Icon 语义不对）。读 = 宽松真值缺失即假；
写 = 未变一字不动、收藏写 `"true"`、取消删键。

### A2 文件夹可见（`cd99bbb`）

`observeFolders` 按库分流，读侧判据与 `ItemRepositoryImpl` 逐字同构；
KDBX 分支用 `KdbxSessionFlow` 当触发器；未解锁返回空列表（不泄露组数）。

### A3 表单裁剪 + 三层防线（`a3782ca`）

`ItemTypePolicy` 纯函数（表单）→ 卡包三门控（FAB/addRequest/空态）→
`KdbxItemRepository.requireSupportedType`（仓储硬闸，专截导入路径）。
三处判据同源，各自单测钉住。

### B5 忘记 PIN（`47ca162`，#161）

「忘记 PIN？」= 不验任何东西清信封（`disablePinLock`）；PIN 不是根凭据。
`onForgetPin` 一个方法兼顾打开/确认（该类顶 `TooManyFunctions` 40 上限）；
`newPinInvalid` 挪文件级 internal（腾位 + 可单测）。补了 2026-10-04 漏的
`SettingsDivider()`。

## 四、提交拆分与一次自记失误

按修复域拆 7 个提交（license 头修正 / B6 / A1 / A2 / A3 / B5 / docs）。
`strings.xml` 四个 hunk 分属三个域 ⇒ 写脚本按 hunk 切补丁再
`git apply --cached`（同法处理 `FolderRepositoryImpl` 的许可证头 hunk）。

⚠️ **自记**：B5 提交漏带 `HouseKeyStoreTest.kt`（提交信息里写了测试、
文件没暂存）。补救时 `git commit --amend` **打错了对象**（ amend 到了 HEAD
的 docs 提交上），回退两个提交重提才对。
⇒ 纪律：**amend 前先 `git log --oneline -1` 确认 HEAD 就是目标提交**；
提交后 `git show --stat` 核对文件清单与提交信息声称的内容一致
（这次两条都违反，各错一次）。
