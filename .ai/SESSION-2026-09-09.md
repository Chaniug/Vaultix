## 第二十轮（2026-09-09 · 用户反馈三缺陷：永不锁定失效 / Edge 填充失效 / 条目不能关联 App）

### Bug① 选了「永久开启（永不锁定）」仍一会儿就锁
- 定性：`AutoLockPolicy.neverAutoLock()` 写了却**没在控制器里接线**——
  `AutoLockController.onStart` 无条件走 `screenLockRequiresRelock(screenLocked)`，
  息屏 / 锁屏后回前台即 lockAll，「永不」档位形同虚设；
  另有一处竞态：`autoLockMinutes` 缓存在 `@Volatile` 字段（初值 5），冷启动首帧
  DataStore 值还没到，用户选了「从不」也会被按默认 5 分钟档判定。
- 修复：新增 `AutoLockPolicy.shouldLockOnResume(minutes, screenLocked, timedOut)`
  （never 优先，直接短路）；控制器改为**每次判定现取** `prefs.autoLockMinutes.first()`，
  删掉缓存字段。补 3 例单测（含「never + 屏幕锁定 + 超时」仍不锁）。

### Bug② Edge 浏览器填充失效（对齐 Bitwarden AutofillParserImpl）
- 根因链（参考 Bastion + Bitwarden 源码）：
  1. Edge/三星/Opera 等 WebView **不总上报 `ViewNode.webDomain`** → 匹配器拿不到域名；
  2. Chromium 系在 WebView 表单下发的是 `webUsername` / `webPassword` hint，
     原 `HintClassifier` 只认 `username` / `password`；
  3. 浏览器字段语义常只存在于 `htmlInfo`（type/name/id/placeholder）与资源 id。
- 落地：
  - 新 `autofill/parser/BrowserUrlBars.kt`：URL_BARS 表（Edge/三星/Opera/Brave/Vivaldi/
    Firefox 全渠道/Chrome/DDG/Via…30+）地址栏兜底 + 结构文本 BFS 域名扫描（深度 ≤6，
    只认末段为字母的 host，排除搜索词/版本号/IP/localhost）；
  - `AssistStructureParser`：收集地址栏 host → `ParsedStructure.fallbackWebDomain`
    （**非权威，只用于匹配不用于拒绝**）；节点文本信号扩展为
    text → hint → **idEntry** → **htmlInfo 属性**；地址栏节点**不入可填充字段**
    （否则含 "login" 的地址栏会被启发式判成用户名框）；
  - 「密码框上方最近的文本框升格为用户名」（Bitwarden 同款 missing-username 兜底，
    邮箱框优先）；
  - `HintClassifier`：补 `webUsername/webPassword/newUsername/webEmail/webTel` 等别名，
    且**遍历全部 hint**（不只第一个）；
  - 新 `autofill/match/AutofillRequestContextPolicy.kt`：浏览器包名闸门（无域名时禁止
    退化包名匹配）+ Bitwarden 同款 blocked packages（android/settings/自身/一加锁）。
- 单测：`BrowserUrlBarsTest`（10 例）、`AutofillRequestContextPolicyTest`（5 例）、
  `HintClassifierTest` 增 2 例；detekt 全绿、app 编译通过。

### 工程经验
- 「永不锁定」类档位必须在**策略层**给最高优先级并写单测，否则任何新增规则

## 第二十二轮（2026-09-09 · C 自动填充保存流程 `onSaveRequest`）

### 根因（比想象的更靠前）
`onSaveRequest` 是空实现，**且 FillResponse 从未挂 `SaveInfo`**——框架只在响应里带了
SaveInfo 时才在用户提交表单后回调保存。所以「保存流程没做」的真因不在保存回调，
而在填充响应缺 SaveInfo。

### 落地（app/autofill/save/）
- `AutofillSaveInfo.build(parsed)`：`SAVE_DATA_TYPE_USERNAME | SAVE_DATA_TYPE_PASSWORD`
  + `requiredIds`（API 28+ 传账号框 + 密码框，两者都有值才提示，避免「填个搜索词就弹保存」）。
  **fallback（无匹配）分支同样挂 SaveInfo**——没有匹配项恰恰是最需要保存的场景
  （用户首次在某站点登录）。`AutofillDatasets.buildFallback` 加 `saveInfo` 参数。
- `AutofillSaveMatcher`（纯函数、可单测）：
  - `targetUri`：网页 → `https://host`（含地址栏/结构兜底域名）；App → `androidapp://pkg`；
  - `findExisting`：同基域 + 同账号 → 命中「更新」；账号为空不做按账号匹配（防把所有
    无名条目当同一个）；
  - `defaultTitle`：域名去 `www.` → 应用名（PackageManager）→ 包名。
- `AutofillSaveActivity/ViewModel`：透明卡片确认页；**新建 / 更新二合一**；
  更新时把本次来源网址**并入**条目 uris（Bitwarden 同款行为：同账号多域名不重复建条目）；
  库未解锁只引导解锁，**绝不暂存明文**（密钥只在内存会话，锁定时无法写密文）。
- `VaultixPreferences.autofillSavePrompt`（默认开）+ 设置页「保存提示」开关。
- 单测 `AutofillSaveMatcherTest` 9 例；app 编译 + detekt 0 违规 + 单测全绿。

### 工程经验
- Android 自动填充的保存链路三段缺一不可：**FillResponse 挂 SaveInfo → 框架回调
  onSaveRequest → 自己拉起确认界面落库**。只实现第三段等于没做。
- 保存要在**解锁会话**内完成：密文写入需要内存对称密钥，锁定态下既不能落盘也不能排队。
