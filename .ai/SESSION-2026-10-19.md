| 文件 | 内容 |

| `PreviewCanvas.kt` | 渲染脚手架：`PreviewFontScale`（1.0x / 1.3x / 2.0x）、`PreviewNight`（浅 / 深）、`PreviewCanvas`（`LocalDensity.fontScale` 覆写 + `VaultixTheme`）、`PreviewSpecLabel`、`PreviewPlaceholderBlock`、`previewName()` |

### 关键设计

**字体档怎么模拟**：不是设 `textSize`，而是覆写 `LocalDensity`：

```kotlin
CompositionLocalProvider(
    LocalDensity provides Density(density = LocalDensity.current.density, fontScale = fontScale.scale),
) { VaultixTheme(…) { content() } }
```

这才会真正走到 `sp → px` 的那条路径，也才能验证 `rememberBottomDockInset()` 里
读 `LocalDensity.current.fontScale` 的补偿逻辑 —— **用 `textSize` 是假的**。

**为什么要 `dynamicColor = false`**：真机开了 Monet 后颜色随壁纸变，
Preview 是给"规格"看的，颜色必须可复现。

### 踩坑

- `Column(content = content)` 类型不匹配：`content: @Composable () -> Unit` 是
  `ComposableFunction0`，而 `Column` 要 `ComposableFunction1<ColumnScope, Unit>`。
  **改法**：`) { content() }`。
- detekt `MagicNumber` 命中 `1.3f` ⇒ 抽 `FONT_SCALE_NORMAL/LARGE/MAX` 三个常量。
- `ui-tooling` 离线未缓存 ⇒ 需**联网跑一次** `:app:dependencies` 拉包，之后离线可用。

## 二、#32 P0（真 bug + 功能缺失）

### ① 库列表底部让位是魔法数，且**小于**实际需要

改前 `VaultListScreen` 写死 `contentPadding.bottom = 96.dp`。而底栏实际占用：

| 部分 | 值 |
|---|---|
| `BottomDockOccupiedHeight` | 86dp |
| 字体放大增量 | 0 ~ 16dp |
| `navigationBars` 内边距（4 键手势机） | ≈ 32dp |

**真实需要 ≈118dp，写的是 96dp** ⇒ 首个落地页在 4 键手势机上最后一条点不到。

改后函数化（`VaultixBottomDock.kt`）：

```kotlin
private val DOCK_MAX_FONT_GROWTH = 16.dp

@Composable
fun rememberBottomDockInset(): Dp {
    val fontScale = LocalDensity.current.fontScale
    val growth = DOCK_MAX_FONT_GROWTH * ((fontScale - 1f) / 1f).coerceIn(0f, 1f)
    return BottomDockOccupiedHeight + growth +
        WindowInsets.navigationBars.asPaddingValues().calculateBottomPadding()
}
```

> **判据（写死）**：凡是"让位"类的 dp，**不许写字面量**。
> 让位 = 占位高度 + 字体增量 + 系统内边距，三项缺一都会在某种设备上翻车。
> 字体增量按 `(fontScale - 1f).coerceIn(0f, 1f)` 线性插值 —— 2.0x 时吃满 16dp。

### ② 自绘 tab 缺语义（`Role.Tab` 全项目 0 处）

`clickable(role = Role.Tab)` **只改播报措辞，不带选中态**。必须显式声明：

```kotlin
.clickable(
    interactionSource = remember { MutableInteractionSource() },
    indication = null,
    role = Role.Tab,
    onClick = { onClick() },
)
.semantics {
    this.selected = isSelected
    contentDescription = label
}
```

同时：`Column.height(48.dp)` → `heightIn(min = 48.dp)`（字体放大不裁切）；
`Icon.contentDescription` → `null`（避免与外层 label 重复播报）。

其余 4 处：`DisplayOptionsSheet` / `SettingsComponents` 用 `Role.RadioButton` + `selected`；
`ItemsScreen` 分组折叠用 `stateDescription`（新增 `items_group_expanded` / `items_group_collapsed`）；
`AddCloudVaultScreen` 账号列表补 `Role.RadioButton`（**不加 `selected`** —— 那里确实没有选中态）。

> **判据**：`role` 与 `selected` 是**两件事**。`role` 决定"读屏叫它什么"，
> `selected` 决定"读屏说没说它选中"。自绘组件两个都得自己写，`clickable` 一个都不给。

## 三、#33 P1 主 CTA 收敛

### 改前：3 种填充色 × 3 种高度 × 2 种宽度 = 9 种写法

新增 `ui/common/PrimaryActionButton.kt`（`PRIMARY_ACTION_HEIGHT = 48.dp` /
`PRIMARY_ACTION_HEIGHT_TALL = 56.dp`），9 处调用点全部替换：
`UnlockScreen`×2、`AddVaultScreen`、`TwoFactorStep`、`AddCloudVaultScreen`×2、
`CloudAccountsScreen`×3（`ProbeButton` 用 `toned = false`）、`AddKdbxScreen`
（`height = PRIMARY_ACTION_HEIGHT_TALL`）。转圈统一 18dp（原 18/20dp 两档）。

`busy` 态加 `stateDescription`（`action_in_progress` / `action_unavailable`），
读屏能听到"正在处理，请稍候"而不是只有一个转圈图形。

### 踩坑：detekt `MatchingDeclarationName` 连报 4 次

- 先尝试 `enum class PrimaryActionEmphasis { Primary, Tonal }` ⇒ 报
  `'PrimaryActionButton' does not match … 'PrimaryActionEmphasis'`。
- 拆出 `PrimaryActionSpec.kt` 还是报（同名规则按"非 `private` 顶层声明"算，挪文件不解决）。
- 合并回单文件仍报。
- **最终解法**：删掉枚举，把"两档"的信息并进函数 KDoc 的表格，
  参数改成 `toned: Boolean = false`。

> **判据**：detekt `MatchingDeclarationName` 要求文件里**只能有一个**非 `private` 顶层声明，
> 且文件名必须与它同名。想在一个文件里放"组件 + 它的枚举"是**做不到**的 ——
> 要么把枚举改成 `private`/内嵌，要么换成 `Boolean`/`sealed` 内嵌类型。

### 其他

- `TotpCodesScreen` 的 `IconButton`：`36.dp` 固定高 → `Modifier.minimumInteractiveComponentSize()`。
  **优于**手写 `heightIn(min = 48.dp)` —— 后者会把 `IconButton` 的水波纹一起拉大。
- `PasswordGeneratorDialog.GenToggle` 的 `.height(40.dp)` → `heightIn(min = 40.dp)`。

## 四、#34 P2 空态与圆角收敛

### ① 空态：5 套独立实现 → 1 个组件

`bottomInset` / `iconSize`），替换 5 处：`ItemsScreen` / `TrashScreen` /
`TotpCodesScreen` / `PasskeysScreen` / `CardWalletScreen`。

卡包的空态**拆成标题 + 正文**（新增 `card_wallet_empty_title/body`、
`card_wallet_empty_kdbx_title/body`、`card_wallet_no_match_title/body`；
删除被取代的 `card_wallet_empty` / `card_wallet_empty_kdbx` / `card_wallet_no_match`）。
理由是它原来只有一句灰字，"搜索没命中"和"这个库本来就没有卡"是同一团字。

`VaultListScreen` 品牌页的魔法数同时收敛：`28.dp → Spacing.xl`、`72.dp → EMPTY_BRAND_ICON`、
`6.dp → Spacing.xs`、`36.dp → EMPTY_ACTIONS_TOP_GAP`。

### ② 圆角：6 种取值 → 3 个语义档位

新增 `ui/theme/VaultixCorner.kt`：

| 档位 | 值 | 用在哪 |
|---|---|---|
| `Small` | 12dp | 高度 < 64dp 的**小面**：徽章、提示条、日志框、表单可选卡 |
| `Panel` | 16dp | 高度 ≥ 64dp 的**大面**：条目卡、设置分组卡、tab pill、库卡 |
| `Pill` | 50% | 两端半圆的药丸：底栏胶囊、搜索栏 |

判定规则一句话：**看它有多高**。20dp 归 `Panel`（它和 `EntryCard` 是同一种东西）；
28dp 只留给 M3 对话框，**不进**三档。

### ③ 「幽灵圆角」：`CardDefaults.shape`

`VaultixShapes` 原来只覆盖 `extraSmall` ⇒ **6 处不传 `shape` 的 `Card`** 吃的是
M3 基线 12dp —— 一个既不在代码里、也不在主题里、只存在于 M3 默认值里的圆角
（`VaultListScreen:496` / `TrashScreen:204` / `ImportExportScreen:424,454` / `ConversionScreen:573,658`）。

补 `medium = VaultixCorner.Panel` 后 6 处自动归位，且以后 `Card { }` 不传 shape
也落在同一个值上。

> **判据**：`Shapes(...)` 是**全量替换**还是**部分覆盖**？`Shapes()` 的每个参数都有默认值，
> 你只传 `extraSmall` 时其余档位吃的是 M3 基线，**不是**你上一次的取值。
> 只要项目里存在"不传 shape 的 Material 组件"，就必须把对应档位补齐。

### 踩坑（4 个，全部当场修掉）

1. **`RoundedCornerShape(VaultixCorner.Panel)` 是双重包裹** —— `Card` 的 `shape`
   参数类型已经是 `Shape`，再包一层 `RoundedCornerShape(...)` 编译不过
   （`AddVaultTypeDialog:165` / `ItemFormDialog:441,488`）。
2. **删常量没换引用**：`PressAndSwipeToDelete:181` 的 `RoundedCornerShape(REVEAL_CORNER_DP)`
   中 `REVEAL_CORNER_DP` 已删 ⇒ 改 `VaultixCorner.Panel`。
3. **`EntryCard` 的 `val shape = …` 需要显式类型**：原来是 `RoundedCornerShape(CARD_CORNER)`
   推成 `RoundedCornerShape`，改成 `VaultixCorner.Panel` 后 `RoundedCornerShape` import
   成孤儿 ⇒ 显式写 `val shape: Shape`。
4. **`VaultixShapes.kt` 里放了两个 public 顶层声明** ⇒ `MatchingDeclarationName` 报
   `'VaultixShapes' does not match … 'VaultixCorner'`。**拆成 `VaultixCorner.kt` + `VaultixShapes.kt` 两个文件**
   （跟 §三 的 `PrimaryActionEmphasis` 同一个坑，这轮踩了两次）。

清理：`RoundedCornerShape` 孤儿 import 6 个（`AddVaultTypeDialog` / `PressAndSwipeToDelete` /
`CloudAccountsScreen` / `SettingsComponents` / `SettingsScreen` / `VaultListScreen`），
孤儿常量 3 个（`CARD_CORNER` / `SETTINGS_CARD_CORNER` / `PILL_CORNER_PERCENT`）。
