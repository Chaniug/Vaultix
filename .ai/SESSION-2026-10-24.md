## 3. 改法

### 3.1 间距（两处解耦，互不牵动）

```kotlin
private val QUICK_FILTER_ROW_PADDING_TOP    = Spacing.sm   // 8dp：上面挨着顶栏，够了
private val QUICK_FILTER_ROW_PADDING_BOTTOM = Spacing.md   // 12dp：下面挨着卡片
private val QUICK_FILTER_ROW_HEIGHT =
    QUICK_FILTER_ROW_PADDING_TOP + FILTER_CHIP_HEIGHT + QUICK_FILTER_ROW_PADDING_BOTTOM
private val QUICK_FILTER_LIST_GAP = Spacing.sm             // 8dp：只加在"让位"侧
```

- 面板真实高度 = `20 + 32 + 12 = 64dp`（原 48dp）；
- 列表让位 = 面板高度 + 8dp 呼吸缝 = **72dp**（原 48dp）；
- **组织 chip 行仍是 8dp 下内边距**（`QUICK_FILTER_ORG_ROW_HEIGHT = 8 + 32` 不变）——
  个人账号用户（没有组织行）看到的面板高度变化只来自 chip 行内边距，这一点是有意的。

> 为什么"呼吸缝"不直接并进下内边距：那样"面板有多高"与"列表让多少"共用一个值，
> 日后调任何一个都会牵动另一个。缝是**面板之外的空白**，属于让位的职责。

### 3.2 滚动后展开（外壳下移 + 反向补偿）

`rememberListEdgeHolder()` 判定"面板展开 **且** 列表已滚离顶部"→ `holding = true`：

| 环节 | 做法 |
|---|---|
| 让位 | `ItemsPullToRefresh(modifier = Modifier.padding(top = reveal))`，`reveal = 56dp` |
| 列表 `contentPadding.top` | 同步 `+ reveal`（`itemsShellTopInset`） |
| 滚动位 | `scrollToItem(0, anchorPx)`，`anchorPx = 56dp` |
| 反向补偿 | 每个 item 的 `Modifier.compensate()` → `graphicsLayer { translationY = -revealPx }` |

净效果：`contentPadding.top` 把首项压到面板下沿，外壳下移 56dp，绘制时再减回 56dp
⇒ **可见内容一像素都不跳**，用户只看到"面板盖住了上面几行"。

- 列表本就在顶部：`holding = false` ⇒ `reveal = 0.dp`，与 2026-10-24 之前**逐字节一致**；
- 用 `graphicsLayer` 而不是继续改 `contentPadding`：后者会挪动真实布局位置，首项也跟着动，
  等于白补偿。代价是补偿量在**根层**（`LazyColumn`）绘制，LazyColumn 内部不做裁剪
  （它不对子项加 clip），所以不会被视口上边界切掉。

### 3.3 🔴 顺序是硬性的：先让位、再滚

`scrollToItem(0, anchor)` 的可用上限是 `contentPadding.top - viewport`。
而 `padding` / `contentPadding` 的变化要**下一帧**才生效。若"点开就滚"：
那一刻 `contentPadding.top` 还是旧的（≈0），锚点被夹到 0 ⇒ **滚了等于没滚**
（`scrollToItem` 只记录目标位，不会在让位生效后自己修正）。

⇒ 实现用两帧：

```kotlin
holding = true                       // ① 外壳/让位打上去（下一帧生效）
withFrameNanos { }                   //   等一帧
listState.scrollToItem(0, anchorPx)  // ② 再滚
```

### 3.4 与"切筛选回顶部"（规则一）的分工

`rememberFilterBarCollapse` 仍然 `LaunchedEffect(filter) { scrollToItem(0) }`。
面板已展开时用户是在"看面板期间切 chip"：那次直接回第 0 项，`firstVisibleItemScrollOffset`
归零 ⇒ `rememberScrollCollapseFraction` 读成"未收起" ⇒ 顶栏不会缩一下
（2026-09-15 那个毛病不会回来）。因此"面板展开期间冻结收起度"这条**保持不变**即可，
不需要额外改动。

## 5. 待真机验收（三条）

1. 列表在顶部点开面板：chip 行与首条卡片之间应是**明显的一道缝**（视觉上 ≈ 半个 chip 高）；
2. 往下滑几屏再点库名：面板下方应**立刻能看到列表顶端**（库状态行 / 第一条），而不是一片空；
3. 面板展开期间连点 chip（全部 → 验证码 → 通行密钥 → 再回全部）：顶栏标题**不应**缩一下，
   列表也不应出现"整体下沉"的跳动。

若第 1 条仍嫌窄，只改 `QUICK_FILTER_LIST_GAP`（一处，两帧同步）；若第 2 条露得太少，
改 `QUICK_FILTER_TOP_ANCHOR`（一处，外壳 / `contentPadding` / `translationY` 三处都引用它）。

## 6. 本轮没做的事（有意）

- **没做窗口级滚动同步**（不是"外壳 + 补偿"，而是让内容跟着面板逐帧上移）：
  那需要自绘滚动容器或在 `LazyColumn` 外层叠一个同步滚动的容器，
  收益（动画期间内容跟手）与风险（手势、回收、性能）不成比例。当前实现是**终态正确**，
  200ms 动画期间面板下方可能出现半帧空白。
- **没有动 `rele` 分支**（用户未指示合入）。
- **`HANDOFF-2026-10-02.md` / `HANDOFF-2026-10-05.md` 索引重叠**仍未处理（早前记录的老待办）。
