## 1. 根因：源「只录不画」（#200）

第二轮（#198.1）为了修"图标被一起糊掉"，把源改成：

```kotlin
source.layer.record { this@drawWithContent.drawContent() }   // ← 只有这一句
```

KDoc 里写的是"屏幕上不落任何像素，真正显示它的是浮层"，并自称这是**与 Haze 的有意分歧**。

**分歧不成立**：浮层只覆盖底栏那一小块，源录的是**整屏 Tab 内容** ⇒ 其余 95% 区域
在屏幕上没有任何绘制命令 ⇒ 直接露出窗口底色（浅色主题 = 白）。
**"没人画"在 Compose 里不是报错，是露底色。**

Haze 的做法恰恰是**先录、再画回屏幕**：

```kotlin
contentLayer.record { this@draw.drawContentSafely() }
drawLayer(contentLayer)                                  // 屏幕上的清晰那份
```

## 2. 修法（三处，缺一不可）

| # | 改动 | 不改会怎样 |
|---|---|---|
| 1 | 源 `record` 之后 `drawLayer(contentLayer)` **画回屏幕** | 整页变白（本 bug） |
| 2 | 模糊改挂**独立的 `effectLayer`**（`record(源尺寸){ drawLayer(contentLayer) }` → 挂模糊） | 一块 layer 只有一个 `renderEffect` ⇒ 屏幕那份**一起糊** |
| 3 | `canvas.translate(offset.x, offset.y)` 用 **offset 本身**（原为 `-offset`） | 底栏糊的是屏幕外一块空白 |

配套：
- `LiquidGlassSource` 由「一个 layer」变「`contentLayer` + `effectLayer`」，
  并在 `onGloballyPositioned` 里记下源的 `IntSize`（`record` 不传 size 会按**浮层**尺寸裁内容）；
- 抽 `backdropOffset(源, 浮层)` 纯函数 + `LiquidGlassSourceTest` 4 例，把**符号**钉死；
- 源的 `enabled` 改为 `开关 && isLiquidGlassBlurSupported()` —— API < 31 根本没有
  `RenderEffect`，别让老设备每帧白拷一次全屏。

## 3. 为什么这三条都是"不报错"的

| 现象 | 报错？ | 只能靠 |
|---|---|---|
| 只录不画 | 否，露底色 | 真机 / 懂"谁负责画屏幕" |
| 模糊挂错层 | 否，整屏糊 | 真机 |
| 偏移取反 | 否，糊错区域 | 真机（且被前一个 bug 盖住） |
| `record` 写在 `drawBehind` 里 | **是**（`Unresolved reference`：`record` 只有 `ContentDrawScope` 的成员扩展） | 编译 |

⇒ 前三条**只能真机验收**，验收清单见 `issues/06-界面与交互.md` #200.6。

### 5.1 失败根因（#201）：lint fatal 只在发版那天才跑

```
Execution failed for task ':app:lintVitalFullRelease'
> Lint found fatal errors while assembling a release target.
  app/src/main/res/xml/backup_rules.xml:28: Error: Unexpected domain cache …
  app/src/main/res/xml/data_extraction_rules.xml:23 / :30（同上）
```

| 环节 | 跑不跑 lint |
|---|---|
| `ci-debug.yml` 的 `Run lint` | **带 `if: github.event_name != 'push'`** ⇒ push `main` 时**根本不跑**（只有 PR 跑） |
| release 构建 | 默认跑 `lintVital`，**fatal 直接中断** |

⇒ **"CI 绿"推不出"能发版"**：两条路的检查集合不同，缺口正好在只影响发版的那半边。
（另一条同源教训：资源 XML 的错误不在 Kotlin 编译里 —— 该日志 `e:` 为 **0** 却 `BUILD FAILED`。）

修法 = 删掉那三行 `<exclude domain="cache" path="." />`：合法 domain 只有
`file`/`database`/`sharedpref`/`external`/`root`（及 `device_*`），**没有 `cache`**；
而 cache 目录本来就不参与备份，#186 写它是想"显式声明以防将来改"，结果换来一个 fatal。

## 6. 继续开发 · Bitwarden 导出/导入**往返保真度**（密码历史 + 时间戳）

积压清单（上一棒 §7）第 4 条里的"导出丢密码历史 / 时间戳"。挑它的理由：
**用户导出是"最后的退路"**，而这条链报成功、其实只导了半份 —— 与本项目审计传统
（"报了成功、其实没有"）完全同构，且改动集中在 mapper 层、可用纯 JVM 单测钉住。

### 6.1 缺口

| 层 | 状态（改前） |
|---|---|
| 领域模型 | 2026-10-21 起就有 `passwordHistory` / `createdAt` / `updatedAt`（界面上看得到） |
| 导出 | `passwordHistory = null`、`revisionDate = null`、`creationDate = null`（**恒空**） |
| 导入 | 三个字段**根本不读** |

⇒ 导出 → 再导入，密码历史与时间戳归零，全程不报错。

### 6.2 落地

| # | 改动 |
|---|---|
| 1 | 新增 `BitwardenTimestamps`（`data:bitwarden/time`）：解析 + 格式化**收敛一处**（此前只有 `CipherMapper` 里一个**私有** parse，反向没有） |
| 2 | `CipherMapper` 的 3 处调用改为复用它（删掉私有函数，注释搬到新文件） |
| 3 | 导出侧填三字段；导入侧**成对**读回（只改一侧会出现"测试半绿半红"，最容易被顺手删掉红的那一半） |

### 6.3 三个判断

1. **格式用 `DateTimeFormatter` 显式毫秒，不用 `Instant.toString()`** —— 后者整秒时省掉
   `.SSS`，与官方 `rfc3339_millis` 形状不一致（能被解析，但"我们导出的文件长得和官方不一样"
   会让互操作问题难定位）。
2. **历史时间缺失时导出空串，不是 null**：官方 `last_used_date` 是**非空** `String`，
   字段缺失会让官方导入器在**反序列化阶段**整份文件失败；空串不是假时间（"现在"/1970 才是），
   本 App 导入时按 blank → `null`。
3. **时间解析失败一律 null**：兜默认值的症状是"详情页显示一个看起来合理但完全错误的时间"
   （假信息），比不显示更坏。

### 6.4 测试

`BitwardenExportRoundTripTest` 8 例：往返保真 · JSON 字段名与官方一致 · 空值不假造 ·
缺失时间的空串闭环 · 非法串 → null · 格式恒毫秒 UTC · 解析兼容 Z/无毫秒/带偏移。

门禁：**本地跑不了编译**（无 Gradle / 无 Android SDK）⇒ 以 CI 为准。
