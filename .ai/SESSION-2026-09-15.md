## 1. 设置页信息架构（定稿 → 落地）

依据 `.ai/decisions/设置页信息架构-定稿.md`（结构用户已拍板，**不重新论证**）。

### 做了什么

- **文案**（`res/values/strings.xml`）：§5.1 六个行标题 / §5.2 六个副标题 / §5.3 三个组名，
  全部照定稿改；另删 `group_others`、新增 `settings_add_vault_desc_another`。
- **结构**（`SettingsScreen.kt`）：
  `SecuritySection → UnlockPrivacySection`（去掉「退出数据库」）、
  `AppearanceSection + AutofillSection → DisplaySection`（自动填充入口并入）、
  `OthersSection → AboutSection`（权限管理并入）、`DataSection` 末尾加回「退出数据库」。
- 为守 detekt `LongMethod ≤150`，把顶栏抽成 `BoxScope.SettingsTopBar`。

### 实测结果

**5 组 / 无单行组 / 破坏性动作置底 —— 与定稿逐行一致**（脚本抓 `SettingsGroupTitle` 顺序核对）。

### 两处刻意偏离定稿（**已在定稿 §6.1 写明理由**）

1. **`group_autofill` 没删** —— 它是 `AutofillSettingsScreen` 二级页的**顶栏标题**，
   删了会让二级页编译失败。定稿这条是漏看了引用。
2. **「添加密码库」的条件文案多带了类型说明** —— 落地为
   「添加另一个密码库：Bitwarden 云端或本机 .kdbx 文件」。定稿只写「添加另一个密码库」，
   但我认为"能加哪两种库"是**有用信息**而非指路语，丢了不划算。

### 一个顺带的发现

`quick_unlock_disabled` = 「未启用（**点右侧「启用」即可**）」也是指路语，已改为「未启用」。
⚠️ 同类的 `detail_totp_hidden`（详情页）**本轮没动**（超出"设置页"范围），留待下一轮。

## 2. M3 Expressive P0

依据 `.ai/conventions/8.8-M3Expressive-采纳范围与顺序.md` §4。

### P0-1 间距标尺 —— 369 处已替换

| 项 | 数字 |
|---|---|
| 手写 `.dp` 总数 | 539 处 / 43 文件 |
| 落在 8dp 标尺上 | **373**（69%）→ 已替换 |
| 不在标尺上（保持原样） | 166（`0/2/6/18/20/48/72`…） |
| 实际替换 | **369** 处 / 41 文件 |

新建 `ui/theme/Spacing.kt`（`xs4 / sm8 / md12 / lg16 / xl24 / xxl32`），
**`0.dp` 不进标尺**（它是"没有间距"这个语义本身）。

✅ **等价性用反演法证明**：把改后的 `Spacing.*` 展开回数值 `.dp`，与 HEAD 逐行比对 ——
**41 个文件全部逐字符一致**。⇒ 这是纯等价替换，**版式一个像素都没变**。

⚠️ 撞了 2 处 `MaxLineLength`：`Spacing.lg` 比 `16.dp` 长，两行 `PaddingValues(...)` 撑到
121/123 字符 ⇒ 已拆成多行修复。

### P0-2 表达式搜索栏 —— 只做观感

`ui/common/SearchTopAppBar.kt` 的 `title` 槽：透明裸输入框 → `surfaceContainerHigh`
**胶囊容器**（`RoundedCornerShape(28.dp)`）+ 左侧搜索图标。

- ⚠️ **没用 alpha 的 `SearchBar` 组件**：8.8 §6① 要求"交互框架等 beta/stable 再换"，
  这里用稳定的 `TextField` 自绘同样观感，**零 alpha API 依赖**。
- ✅ **inset 一行没动**：容器固定 56dp、外层仍是同一个 `TopAppBar`（64dp）
  ⇒ `itemsTopInset` 等让位计算完全不受影响（#67 / #76 的坑没被惊动）。
- ⚠️ 该组件被 **4 个页面**共用（Items / CardWallet / Passkeys / Totp）⇒ 验收要四个都看。

### P1 / P2 为什么没做

三项都要引入 **material3 1.5.0-alpha16 的新 API**（`LoadingIndicator` / `ButtonGroup` /
Styles API）。alpha 会改名改语义，而**本轮没有编译环境** ⇒ 无法确认确切签名。
**在能编译之前凭记忆写 alpha API，是把不确定性直接写进代码** —— 不值得。已写明前置条件。
