> 汇总 AutofillPicker 重构、保底机制、对照 Bitwarden、以及 Via/Edge/OTP/OneDrive/图标等浏览器与设备专项修复。
> 最后整理：2026-08-27。对外用户文档见 `BastionDocs/docs/02.配置/02.相关文档/03.Bastion-Android-自动填充与保底机制.md`。

## 1. 自动填充架构与重构（Bastion/docs/autofill）

- **AutofillPicker UI 重构**：用 MD3 风格 `AutofillPickerActivity` 选择器替代系统原生列表（"一切从简从易用"原则）。相关文档：`REDESIGN.md`/`REFACTOR_SUMMARY.md`/`RELEASE_NOTES.md`（v2.0）。
- **保底机制**：`BastionDocs` 文档站有专门「自动填充与保底机制」页，描述无障碍/AccessibilityService 等多通道保底策略（`ACCESSIBILITY_SERVICE_GUIDE.md`）。
- **对照 Bitwarden**：`BITWARDEN_COMPARISON_AND_REFACTOR_PLAN.md` —— Bitwarden 填充更准确的原因"不是算法更聪明，而是架构哲学不同"（判定机制分层 vs 朴素匹配），据此改造 bastion 判定。
- **集成与测试**：`INTEGRATION_CHECKLIST.md`/`TESTING_CHECKLIST.md`/`QUICK_TEST_CHECKLIST.md`/`DIAGNOSTIC_TEST_SCRIPT.md`/`device-specific-guides.md`（各主流品牌设备特定设置）。
- **文档群说明**：`Bastion/docs/autofill/` 下 33 篇多为同轮 AutofillPicker 改造的过程记录（README/FAQ/QUICK_REFERENCE/quick-start-guide/troubleshooting-guide 等），内容高度重叠，本篇为唯一权威摘要。

## 2. 密码自动保存（onSaveRequest）

- 现象类问题：保存失败、回调不触发、跨设备/浏览器差异。
- 关键文档：`PASSWORD_SAVE_IMPLEMENTATION.md`（2025-11-08 实现）、`PASSWORD_SAVE_FAILURE_ANALYSIS.md`、`ONSAVEREQUEST_TROUBLESHOOTING.md`、`SAVE_REQUEST_DEBUG_GUIDE.md`、`ROOT_CAUSE_ANALYSIS.md`（SaveInfo 配置确认）。
- 要点：SaveInfo 正确配置但 `onSaveRequest()` 不触发，多因系统/厂商定制；需结合设备特定设置与保底机制。

## 3. 浏览器专项修复

### 3.1 Via 浏览器（系统 WebView 内核，mark.via）
- 多轮修复（`Via系统WebView密码框修复计划_第三轮/第四轮.md`、`Via系统WebView密码框回填不可靠修复计划.md`）：

### 3.2 Edge 浏览器
- `Edge浏览器Discord填充半填充Bug修复计划.md`：登录 Discord 只填用户名、密码空白（TOTP 正常复制）。参照 Bitwarden `AutofillCompletionManagerImpl` / `FilledAutofillItemCollection` 修正填充链。
- `otp-clipboard-edge-bug-plan.md`：Edge/WebView 自动填充后 TOTP 不进输入法剪贴板。根因两层：①OTP 自动复制默认关闭开关（`isAutoCopyOtpEnabled`/`isOtpNotificationEnabled` 默认 `false`）；②剪贴板注入路径在 Edge 下未触发。状态：待确认。

## 4. OneDrive 登录

- `onedrive-login-bug-diagnosis.md`：登录报错 `invalid_request: redirect_uri`。根因 Azure 门户 redirect URI 配置与代码不一致（或需自注册 Azure 应用，见 `azure-app-registration-guide.md`）。状态：根因已定位，需 Azure 门户操作修复。
