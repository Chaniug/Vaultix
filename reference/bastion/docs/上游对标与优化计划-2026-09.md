# 上游对标与优化计划（2026-09-05）

> 调研对象：Bitwarden 官方 Android（2026.6.0）、Keyguard（v2.14.2）、Monica（V1.0.302）。
> 方法：对照三者 release notes 与 bastion 代码现状逐项核实，只保留「不影响功能、可落地」的项。
> 前置结论：批 5 后真机日志 `instruction limit` 0 命中，PasswordListContent 拆分全案收官。

## 一、上游修复中 bastion 存在同款隐患的（按优先级）

### P1 恒定时间比较 MAC/哈希（来源 Keyguard `compare cipher MACs by MessageDigest.isEqual()`）
- 隐患：bastion 校验加密 payload 完整性（GCM tag 之外的 HMAC/hash 比对、token 指纹比对）若用 `==`/`contentEquals`，存在时序侧信道。
- 动作：全局审计 `==` 比较 hash/MAC/token 摘要的位置，统一改 `MessageDigest.isEqual(byteArray1, byteArray2)`。
- 风险：低；纯等价替换。

### P1 TOTP 进度环 50ms 高频刷新（来源 Monica V1.0.302「验证码进度低频采样+平滑绘制」）
- 现状：`ui/totp/TotpTicker.kt` 的 `smoothTicker` 以 **50ms** 发射（WhileSubscribed(5s) 保护）。密码列表若同时显示 N 张 TOTP 卡 → 每秒 20×N 次行重组，长列表滑动掉帧（Monica 实测同样问题，HyperOS 设备更明显）。
- 动作：列表行内改「秒级 tick 数据 + 动画 API 平滑」——用 `secondTicker` + `animateFloatAsState`（tween 填满 1s）绘制进度环，仅详情页/大卡保留 smooth 模式。
- 风险：中；需逐处回归进度环视觉。

### P1 备份恢复后 passkey 私钥完整性（来源 Monica「WebDAV/OneDrive 备份恢复后通行密钥私钥缺失」）
- 隐患：bastion 的 passkey 私钥由 Keystore 加密，跨设备恢复后 Keystore 密钥不可迁移 → 私钥记录存在但不可用（与 Monica 同款缺陷）。
- 动作：备份导出时校验 passkey 私钥可解密性；恢复后重加密重写；不可恢复的记录降级为「不可用元数据」并不再出现在系统 passkey 登录列表；备份报告统计 passkey 数量与完整性。
- 风险：中；涉及备份格式，需兼容旧备份。

### P2 同步失败不得清空本地数据（来源 Monica「网络不可用时继续使用本地缓存」+ Bitwarden 2026.1.1「离线 vault 迁移行为」）
- 现状：`BitwardenRepository.clearVaultLocalReferences()` 走 `passwordEntryDao.deleteAllByBitwardenVaultId()`。需审计其调用链：仅允许「用户显式解绑 vault」触发；**token 过期/网络失败/sync 异常路径绝不可达**。
- 动作：为 clearVault 调用链加守卫测试（模拟 sync 失败断言本地数据保留）。
- 风险：低；测试为主。

### P2 Bitwarden 附件缓存地址过期（来源 Monica「附件下载重新获取有效地址，避免缓存地址过期」）
- 隐患：bastion `bitwarden/api/BitwardenApi.kt` 的附件下载若缓存了带签名的临时 URL，过期后 403 → 用户看到附件丢失。
- 动作：附件下载 403/404 时重取真实地址重试一次；本地缓存仅存内容不存地址。
- 风险：低。

### P2 OkHttp 响应泄漏与原子计数（来源 Keyguard v2.13.0）
- 动作：审计所有 `response.body` 提前 return/抛异常路径是否 `use{}` 全覆盖；下载进度计数改 `AtomicInteger`。
- 风险：低。

### P3 Bitwarden 同步健壮性（来源 Keyguard「Do not treat 404 as terminal file upload failure」「optimistic concurrency control」）
- 动作：上传/同步对 5xx/404 采用可重试分类（非终态），失败带指数退避；多端并发同步引入 revision 比对防互相覆盖。
- 风险：中；涉及同步状态机。

## 二、直接可用的性能优化（不影响功能）

1. **TOTP 进度环**（见上 P1，预期收益最大——列表滑动掉帧主因之一）。
2. **主列表 contentType 已达标**：`PasswordListRows.kt` 已按分组头/堆叠组/补充项/5 种卡片分池复用（Monica/Keyguard 同款优化 bastion 已做，无需动）。
3. **堆叠卡片动画状态管理**（Monica「优化堆叠卡片的图层绘制与动画状态管理」）：`StackCardMode.AUTO` 下展开/收起时检查离屏卡片是否仍参与动画重组（`graphicsLayer` 才免重组）。
4. **autofill OTP 通知 tick**：`AutofillOtpNotificationService` 的 `delay(1000)` 通知刷新在通知不可见时应停（`session` 结束即取消，确认无空转）。
5. **剪贴板自动清除默认值**（Bitwarden 2026.4.1 默认 5 分钟）：对齐安全默认。

## 三、上游新特性参考（远期，不影响当前稳定性）

- Bitwarden 2026.3.0：passkey 登录支持 related origins（trusted browsers）；会话 token 过期的账户保护。
- Bitwarden 2026.1.1：phishing blocker（premium 侧）；错误日志 PII 脱敏（bastion 日志脱敏已有，对齐其脱敏范围）。
- Keyguard v2.13.0：WebAuthn Level 3（Android）；PSL 异常规则处理（TLD 匹配）+ **Public Suffix List 定期更新**（bastion 域名匹配若内置 PSL 需建更新通道）。
- Keyguard 教训：autofill「origin 隔离」导致 Edge 不工作被回退——bastion 的 passkey origin 校验勿过度隔离。
- Monica：嵌套目录解析（KeePass 目录树）；密码卡片显示验证器（bastion 已有）。

## 四、建议执行顺序

1. （小）恒定时间比较审计 + 剪贴板默认值 → 一个提交 ✅（2026-09-05 已实施，含下述实测范围）
2. （中）TOTP 进度环改秒级+动画 → 装包回归滚动流畅度
3. （小）clearVault 调用链守卫测试
4. （中）附件地址过期重取 + OkHttp 泄漏审计
5. （大）passkey 备份完整性（需设计备份格式兼容）
