# 外部项目借鉴分析（2026-09）

## 1. 背景与目标

调研 Bitwarden、Keyguard、Monica 近期（2026-06 ~ 2026-09）改动，筛选可借鉴到 bastion
（安卓 Bitwarden 兼容密码管理器，Kotlin + Jetpack Compose）的修复与优化。
**原则：不盲目借鉴，基于 bastion 实际情况出发，找出最优解。**

## 4. 本次聚焦确认：用户选的两项 bastion 已具备

用户最初选择"同步单条隔离"与"加密存储失败分类恢复"，但读代码后确认 **bastion 已具备这两项**。

### 4.1 同步单条 cipher 解析失败隔离
- `BitwardenSyncService.processSyncResponse`（316-380）：`response.ciphers.forEach { cipherApi ->`
  整个处理（同步 + 附件 reconcile）包在 `try` 内，377-379 行 `catch (e: Exception)` 兜底。
- `cipherSyncProcessor.syncCipherFromServer(...)` 返回密封类 `CipherSyncResult`
  （`Added` / `Updated` / `Conflict` / `Skipped` / `Error`），单条失败转 `Error` 而非抛出（350 行仅 `Log.w`）。
- `CipherSyncProcessor.decryptString`（1601-1613）：`catch (e: Throwable)` 返回 `null`，
  单字段解密失败降级为 null，不中断整条 cipher。
- **结论：bastion 单条隔离已是"内层 sealed result + 外层 try-catch"双层保障，零漏抛。
  不存在"一条坏 cipher 拖垮全量同步"的问题。**

### 4.2 加密存储失败分类恢复
- `SecurityManager.persistKeystoreWrappedMdk`（1044-1059）：
  `KeyPermanentlyInvalidated` / `UnrecoverableKey` → 删 alias + 清 wrapper + 重建 compat wrapper；
  `UserNotAuthenticatedException` → 走 compat；通用 `Exception` → 失败。
- `SecurityManager.getMdkForCrypto`（1300-1343）：
  `KeyPermanentlyInvalidated` → `invalidateCachedSecureKey` + 抛出让用户重设；
  `UserNotAuthenticatedException` → cooldown + `return null`（降级）；
  其他 `Exception` → `clearKeystoreWrappedMdk` + `null`。
- `SecurityManager.encryptData`（1356-1382）：MDK 不可用降级到 compat 加密。
- **结论：bastion 已有"失败分类 → 协调恢复（降级 / 重建 / 清缓存）"闭环，
  与 Keyguard `SecureStorageCoordinator` 思路一致。**

## 5. 真实可落地的微小加固（若继续打磨已具备项）

- **同步**：`CipherSyncResult.Error` 当前仅 `Log.w`，未计入同步诊断统计
  （`SyncDiagnostics`）。可把单条失败数暴露到诊断，使"隔离生效但仍有坏数据"可见可量化。
- **加密恢复**：`getMdkForCrypto` 对 `BadPadding` / `IllegalBlockSize`（数据损坏）走通用分支清 wrapper——
  合理，但可加一条明确诊断标记"MDK 数据疑似损坏"，便于真机排查。

## 6. bastion 真正缺失的高价值项（供下一步）

- **Autofill 请求方签名校验**：bastion 用 `activityComponent.packageName`（系统填充、可信），
  无 SHA-256 签名校验。Android Autofill 中 packageName 由系统保证真实，但加签名校验可防缓存/离线匹配
  投毒，是密码管理器 Autofill 的标准加固。中等价值，真实缺失。
- **baseline profile 自动化基准**：bastion 有 `baseline-prof.txt` 但无 benchmark 模块，
  无法量化冷启动改进。中低价值。
- **同步边界收紧 / 新 cipher 格式对齐**：需先评估 bastion `BitwardenCrypto` 现状再定。中。

## 7. 结论

用户最初选的"同步单条隔离""加密存储失败分类恢复"两项 bastion **均已具备且扎实**。
本轮最大价值是**确认 bastion 护城河已覆盖这些点，避免重复劳动与引入回归风险**。
下一步应聚焦 bastion 真正薄弱项（Autofill 签名校验等，见 §6），而非重复已有能力。
