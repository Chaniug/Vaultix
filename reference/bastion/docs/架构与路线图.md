## 1. 多后端存储架构（Phase A 已完成）

- **决策**：移除自研 MDBX 引擎，**保留 KDBX + Bitwarden + BastionLocal 三后端**（`architecture-kdbx-bitwarden.md`，Phase A 已合 `69c9f8b5`）。
- KDBX：本地 KeePass 文件，支持 WebDAV 原子条件写入（If-Match）+ 密钥文件内部副本与指纹。
- Bitwarden：含官方/自建（Vaultwarden）同步，详见 `bitwarden同步与密码库生态.md`。
- BastionLocal：纯本地库，数据由 app 级 MDK（SecurityManager）加密，与 Bitwarden 锁正交。

## 9. 关键风险与注意

- **本地构建限制**：沙箱内 `dl.google.com` 被 DNS 劫持，AGP 需远程解析 `platforms;android-37.0`，本地直连无法编译；**本地验证依赖 GitHub Actions**（runner 网络正常）。镜像注入：`~/.gradle/init.gradle` 用 `gradle.beforeSettings` 注入腾讯 maven 镜像。
- **多模块一致性**：`Bastion/app`（Android）与 `desktop/shared` 为独立模块，部分优化（如 revision-date 预检）需两端分别镜像。
