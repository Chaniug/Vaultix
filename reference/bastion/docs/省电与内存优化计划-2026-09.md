### 2.2 `[anon]` 133 MB 的定性过程（**方法比结论重要**）

**第一步：增长曲线实验**（单点快照说明不了任何问题）

```bash
snap() { P=$(adb shell pidof com.bastion.app | tr -d '\r'); \
  adb shell run-as com.bastion.app showmap "$P" | \
  awk '$NF=="[anon]"{a+=$3} /scudo/{s+=$3} END{printf "anon=%dKB scudo=%dKB", a+0, s+0}'; }
```

| 时点 | anon | scudo |
|---|---|---|
| 冷启动后 8 秒（T0） | **135952 KB** | 22360 KB |
| 静置到 53 秒（T1） | **135952 KB** | 22360 KB |
| 运行 6 分钟后 | **135952 KB** | 68163 KB |

⇒ `[anon]` **一字不差**，启动时一次性预分配，**非增长性泄漏**。

**第二步：段结构**（区分"单个大块"与"碎片累积"）

`[anon]` **只有 1 段**：`virtual=2,574,496 KB（2.45 GB）/ PSS=135,952 KB`。
虚拟地址巨大、实际提交仅 133 MB ⇒ 典型的**堆地址空间预留 + 按需提交**。

**第三步：排除假设**

- ❌ **Argon2 / KDF**：查库确认 `local_keepass_databases` 与 `keepass_remote_sources` **均 0 行**，本机根本没在用 KDBX；`bitwarden_vaults` 用 PBKDF2 600k 迭代（非内存密集）。
- ❌ **LeakCanary 等调试库**：`app/build.gradle:325-329` 处于注释状态（2.14 不支持 API 37，无稳定版 3.0）。debug 仅 `minifyEnabled false` + `ui.tooling`。
- ❌ **多进程翻倍**：`ps -A` 确认只有 1 个 `com.bastion.app` 进程。

### 2.3 唯一待观察项：`scudo`（native malloc）

22 MB（T0）→ 68 MB（6 分钟）增长约 46 MB。可能是正常的图片/网络缓存，也可能是小泄漏。
**定性方法**：长时运行多点采样，看是否**收敛**（趋平）而非线性增长。

```bash
# 每 60 秒采一次，采 20 次（20 分钟）
for i in $(seq 1 20); do echo "t=${i}min $(snap)"; sleep 60; done
```

判据：**趋平 = 缓存，线性增长 = 泄漏**。

## 三、耗电：确定项（P0，建议优先修）

### 3.1 现象

15 秒采样内 `com.bastion.app` 发起 **1218 次** `hasEnrolledFingerprints` ≈ **81 次/秒**。
每次都是跨进程 Binder 调用 BiometricService，且**非操作时段也持续**。

> 注：不同时段测得的频率不同（早前测到 10 次/秒，本次 81 次/秒），
> 因频率取决于**重组频率**（滚动/动画/TOTP 倒计时越高越频繁），故取等级而非定值。

### 3.2 根因：两处 Composable 漏写 `remember`

```kotlin
// ui/password/PasswordListContent.kt:622   ← 每次重组都执行
val canUseBiometric = activity != null && appSettings.biometricEnabled
                      && biometricHelper.isBiometricAvailable()   // 跨进程 Binder

// ui/screens/NoteListScreen.kt:217   ← 同款写法
val canUseBiometric = activity != null && settings.biometricEnabled
                      && biometricHelper.isBiometricAvailable()
```

`biometricHelper` 本身用了 `remember { }`（621 / 216 行），但**查询结果没缓存** —— 每次重组都重新查。

**这不是设计选择，是漏写**，项目里同一判断已有三处写对：

| 位置 | 写法 |
|---|---|
| `MasterPasswordLockingSettingsScreen.kt:56` | `remember(biometricHelper) { ... }` ✅ |
| `PasskeyListScreen.kt:328` | `remember(appSettings.biometricEnabled) { ... }` ✅ |
| `AuthComponents.kt:61` | `remember { ... }` ✅ |

### 3.3 修法（✅ 已完成，`47dddc2`）

**实际改了 3 处**（比初判多一处）：

| 文件 | 原行 | 说明 |
|---|---|---|
| `PasswordListContent.kt` | 622 | 密码页，随滚动/动画重组 |
| `NoteListScreen.kt` | 217 | 笔记页（同结构，`settings.biometricEnabled`） |
| **`TotpListContent.kt`** | **412** | ⚠️ **初判时 `grep \| head -30` 被截断而漏掉**。该页 `sharedTickSeconds`（413 行 `produceState`）**每秒**刷新 ⇒ 每秒打一次指纹服务，比密码页更稳定持久 |

```kotlin
// 三处统一写法（NoteListScreen 用 settings.biometricEnabled）
val canUseBiometric = remember(activity, appSettings.biometricEnabled) {
    activity != null && appSettings.biometricEnabled && biometricHelper.isBiometricAvailable()

```

## 七、复用手法

- **判断泄漏靠曲线不靠快照**：`冷启动 T0 / 静置 T1 / 长跑后` 三点对比，单点数字毫无意义。
- **逐段映射**：`adb shell run-as <pkg> showmap <pid>`（需 run-as，debug 包可用），
  配合 `awk '$NF=="[anon]"'` 按类型聚合；`virtual ≫ PSS` 且单段 ⇒ 地址空间预留，非泄漏。
- **频率类问题先找调用点再看频率**：`grep` 找齐所有调用点，对比写法差异（有无 `remember`），
  比直接读频率数字更快定位。
